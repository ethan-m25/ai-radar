qm — 多人协作 agent 框架，HN 583 points，非开发者也能用

爪哩，今天 HN 上出现了一个叫 qm 的工具——它是一个多人协作的 agent 框架，让多个 AI agent 像团队一样协同工作。583 points，119 comments，上首页 17 小时了。最妙的是它不需要写代码就能配置使用，nginx-like configuration YAML，对非开发者非常友好。

📍 背景 · 目前市面上几乎所有 agent 框架（LangChain、CrewAI、AutoGen）都是面向开发者的——你要写 Python 代码、理解类之间的关系、会调试。qm 走的是一条相反的路：它用 YAML 描述工作流，多人同时在线协作，每个 agent 有自己的角色和工具。这和 "AI 团队" 的概念很像，但不需要你是程序员就能搭起来。GitHub 上 yc-software/qm，今天 HN 首页第 6 位，583 points。

为什么这事重要

  • 非开发者也能用 — 配置是 YAML + nginx-like config，不需要写代码。你写个 `roles:` 下面定义 "研究员" "写手" "审核员"，它就能跑。
  • 多人实时协作 — 不是单机 agent，是多个 agent 像 Slack 频道一样聊天式工作。你可以让一个 agent 读文件、另一个总结、第三个写报告。
  • HN 583 points / 17 小时 — 流量和讨论度极高，说明社区在追捧这个方向。
  • 对你的意义 — 如果你在用 ChatGPT 或者 Claude 做多步工作流（比如调研+写作+做 PPT），qm 可以帮你自动化这个流程，不需要写一行 Python。
🎯 今天就能做的事
  1. 打开 GitHub repo：github.com/yc-software/qm，看 README 示例。
  2. 看 HN 讨论：HN qm — 583 points，119 comments。
  3. 如果它提供 pip install 或 docker 镜像，直接跑一个 "记者调研 → 写稿 → 审核" 的 3-agent 工作流试试。
  4. 对比你现在的 ChatGPT/Claude 用法——qm 能替代哪些手动切换步骤？

Run Kimi K3 using 29 GB of RAM — 本地跑 2.8T 参数模型，HN 258 points

爪哩，昨天技术圈一个热点是把 Kimi K3——那个 2.8T 参数的怪物——压缩到 29GB 内存里跑，虽然速度只有 0.5 token/秒，但能在你的 MacBook 上跑了。HN 258 points，108 comments，说明本地推理圈非常兴奋。

📍 背景 · Kimi K3 是 Moonshot 发布的 2.8T 参数 MoE 模型（104B 活跃参数），正常部署需要至少 8 块 MI355X GPU（几十万人民币）。这次 sqliteai 团队用 GGUF 量化 + 优化的推理代码，把它压缩到 29GB 内存（约 1/4 的模型大小），让普通开发者的 MacBook 上也能跑——虽然每秒只能生成半个 token。这是本地推理的一次大胆尝试，但实用性有限。

为什么这事重要

  • 本地运行 2.8T 参数模型 — 以前这是不可能的事情。虽然 0.5 tok/s 很慢，但证明了 "模型可以在个人设备上跑" 这件事正在变成现实。
  • HN 258 points + 108 comments — 社区讨论很活跃，说明本地推理是热门话题。
  • 对你的意义 — 如果你在做 vibe coding 但网络不稳定或者想离线使用，这种本地部署方案未来可能成为你的备选。但目前 0.5 tok/s 还不实用。
  • 技术趋势 — 量化、剪枝、蒸馏等技术正在让大模型变小。这个方案虽然慢，但展示了方向。
🎯 今天就能做的事
  1. 看 GitHub 仓库：github.com/sqliteai/kimi-k3-29gb
  2. 看 HN 讨论：HN Kimi K3 29GB — 258 points。
  3. 如果你有 32GB+ 内存的 MacBook，可以试试自己跑——但是要有心理准备，0.5 tok/s 真的很慢。
  4. 关注 unsloth 的 Kimi K3 GGUF 版本（已发布 41.3k 下载），未来可能会有更快版本。

老实说：0.5 tok/s 意味着生成一个 1000 字的段落需要 40 分钟。目前纯粹是技术演示，不适合实际工作。但这个方向很重要——未来 1-2 年，我们可能会看到 10 tok/s 以上的本地版本。

🔭 关注点 · 关键 trigger event：如果 unsloth 或者 llama.cpp 发布优化的 Kimi K3 量化版本，速度提升到 5+ tok/s，那就真的实用化了。另外看是否有 Apple Silicon 优化版本（利用 NPU 加速）。
术语解码 · GGUF = 一种模型量化格式，由 llama.cpp 项目推广，可以在 CPU 上运行。量化 = 把模型参数从 16 位浮点数压缩到 4 位或更少，减少内存占用但牺牲一点精度。MoE = Mixture of Experts，混合专家模型——不是所有参数都参运算，只有少数 "专家" 被激活。
