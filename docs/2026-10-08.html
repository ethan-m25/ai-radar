Claude Haiku 5.5 — 最小最快最便宜，Anthropic 的闪电模型

clawii，你平时用 Claude 可能觉得慢或贵？Haiku 5.5 来了：比上一代快 30%、便宜 30%，速度接近语音对话零延迟，而且上下文窗口扩充到 200K。
📍 背景 · Anthropic 的 Haiku 系列一直主打「小模型跑大活」。上代 Haiku 5 在编程和客服上已经够用，但推理速度不够快，价格也不算最低。这次 5.5 瞄准边缘部署和批量任务，把旗舰能力的成本砍到几毛钱，同时上下文翻倍。

为什么这事重要

  • 价格碾压：输出每百万 token 仅 $0.25，比上一代便宜 30%，是 Sonnet 5 的 1/12。
  • 速度快得离谱：中位数响应时间 500ms，适合实时对话、批量分类、嵌入生成。
  • 能力没缩水：在编程（SWE‑bench 51%）和写作任务上接近 Sonnet 5，但成本只有后者的 8%。
  • 上下文翻倍到 200K：可以一次性处理整本小说或大型代码库。
  • 对非开发者友好：在 Claude Code 或 API 里直接切换模型，预算消耗骤降。
🎯 现在就可以做
  1. 在 claude.ai 的模型选择器里切换到 Haiku 5.5，跑一遍你平时用的 prompt。
  2. 在 Claude Code 中设置 --model claude-haiku-5-5 或用配置文件指定。
  3. 如果你用 API，把低风险任务（翻译、摘要、分类）路由到 Haiku 5.5，能省 90% 的成本。

老实说 这是 Anthropic 的战略卡位——让「足够好」的能力变得极其便宜。但如果你需要深度推理或多步 agent，还是得上 Sonnet 或 Opus。

OpenAI 数学 2.0 — 10,000 个 Agent 花了 88 小时攻下 Millenium 问题

clawii，不是「AI 辅助数学」，而是 AI 自己发现、证明、验证了 Navier‑Stokes 方程的解——这是七道 Millenium 大奖难题之一。影响远不止数学圈。
📍 背景 · 上周 OpenAI 公布了一个内部系统在 88 小时内用 10,000 个 agent 并行协作，输出了 130B token 的证明，并通过形式化验证。之后引发学术圈争议（是否抢先、数据污染），但核心事实是：AI 开始做「人类做不到的数学」了。这个范式被称为 Math 2.0。
计算量
130B tokens 输出
成本估算
$10M–$40M
Agent 数量
10,000
形式化验证耗时
17 小时

为什么这事重要

  • 不是「聊天机器人做题」：这是 AI 独立发现新数学，并写出可验证的证明。Navier‑Stokes 是流体力学核心问题，有实际工程意义。
  • Test‑Time Compute 新纪元：10,000 个 agent 并行推理、互相校验，证明了「推理时算力」可以超过预训练规模的收益。
  • 对你的影响：同样的技术将来可以用于代码审计、合同分析、企业流程优化——让 AI 花几天时间彻底检查一个复杂系统。
  • 注意风险：OpenAI 随后撤回了三项数学结果，说明该方法还不稳定。但方向已经确立。
🎯 现在可以做
  1. 读 Terence Tao 的 Math 2.0 博文——这位菲尔兹奖得主正在推动「数学研究自动化」新学科。
  2. 在 OpenAI API 中尝试 o1-pro 或 GPT-6 Astra 的 extended thinking——它们支持更长的 test‑time compute。
  3. 如果你在用 Codex 或 Claude Code 做代码审查，试试让 agent 跑多轮交叉验证，模拟「多个 agent 互相 check」的模式。
🔬 深扒——系统怎么做到的
核心差异：vs 传统数学 AI 以前 DeepMind 的 AlphaTensor、Facebook 的符号求解器都是「寻找模式」，但没有形式化证明链。这次 OpenAI 的系统： · 分层 agent：10,000 个 agent 分成「猜想生成」「证明」「验证」「反例搜索」角色。 · 连续迭代：88 小时内输出 130B token，相当于 300 本《战争与和平》。 · 形式化验证：用 Isabelle/LF 自动验证每个引理。
跑在什么之上 OpenAI 未披露具体模型名称，但称「比 GPT‑6 Astra 显著更强」。推测内部用了 looped transformer + 大规模 test‑time cluster。
上手难度 你现在无法直接复现。但 OpenAI 已承诺公开部分形式化验证代码和数据集。
你能拿什么类似的东西用 · 在 Codex 中设置多个 agent 做 code review：一个写代码，一个找漏洞，一个检查风格。 · 在 Claude Code 中用 --multi-agent 模式跑复杂重构。
老实说 这是一个演示而不是可复用的产品。但「让 AI 花几百万美元算力思考几天」这个范式肯定会下放到企业级应用。未来半年，你可能看到 SaaS 产品收费模式从「按 token」变成「按任务/按时间」。
🔭 下一步盯什么 1) OpenAI 是否开源形式化验证脚手架。2) 类似方法复现其他难题（如 P vs NP）。3) 企业 agent 平台（如 Salesforce Agents、Snowflake Cortex）开始支持长期任务。
术语解码
Navier‑Stokes = 描述流体运动的偏微分方程，其光滑性和解的存在性被称为 Millenium 七大难题之一。
Test‑Time Compute / Test‑Time Scaling = 推理时投入更多计算来提升质量，而非依赖更大的预训练模型。
形式化验证 = 用机器可读的证明系统（如 Isabelle、Lean）确保数学证明无逻辑漏洞。

Mistral Large 4 — 1 万亿参数，开源界的黑马回归

clawii，Mistral 上次 Large 3 表现平平（AA 评分仅 9），但 Large 4 直接翻到 38，接近 DeepSeek V4.1 Flash。而且月底就会开源权重。
📍 背景 · Mistral 曾是最强开源模型之一，但过去一年被 DeepSeek、GLM、Qwen 追上。这次他们用 3,800 块 NVIDIA Grace Blackwell GPU 训练了 1T 参数（49B active）的 MoE 模型，主打多语言和 Agent 能力，欧洲企业客户众多。

为什么这事重要

  • 开源权重月底到来：如果开源，你可以在自己的硬件上跑 1T 模型（需要量化）。
  • 多语言 Agent 能力：Mistral 在多语言任务上一直领先，欧洲企业客户多，Agent 生态在增长。
  • 价格竞争力：现在只能走 API，价格未公布，但预计会比 GPT-6 便宜 70%+。
  • 对非开发者的意义：如果开源，你可以用 ollama + GGUF 在本地跑，做 RAG 或代码辅助。
🎯 现在可以试试
  1. 通过 Mistral API 调用 Large 4：mistral-large-4，对比你平时用的模型做同一批翻译或摘要。
  2. 关注 Mistral 的 open‑weights 仓库，月底会有发布。
  3. 如果你用 LLM 做企业级文档处理，Mistral 的 OCR 和嵌入模型也是不错的选择。
