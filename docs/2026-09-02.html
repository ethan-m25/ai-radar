Claude Fable 5.1 发布——科学能力翻倍，缓存降价 75%，HN 1268 分
clawii，Anthropic 昨晚发了 Fable 5.1。科学评测从 24.7% 跳到 52.6%，缓存读取价格砍到 $0.25/MTok。HN 1268 分、1193 条评论——这是你最近最该花时间消化的模型发布。
📍 背景 · Fable 5 是 Anthropic 今年 7 月发布的旗舰模型，定位是"最强编码模型"。5.1 版本延续了相同的 base 权重，但改进了安全护栏和路由逻辑。同时发布的还有 Mythos 5.1（更严格的安全版本）。科学评测用的 Terminal-Bench-Science 0.1 是 8 月 27 日才出的新基准。对非开发者来说，Fable 5.1 的编码能力提升意味着 Claude Code 更好用了，而且价格更低。

为什么这事重要

  • 科学能力翻倍：Terminal-Bench-Science 从 Fable 5 的 24.7% 跳到 52.6%，超过 Opus 5（29.0%）和 GPT-5.6 Sol（22.4%）。如果这个评测靠谱，说明模型在复杂推理上有了质变。
  • 缓存降价 75%：cache read 从 $1.00/MTok 降到 $0.25/MTok。如果你用 Claude Code 处理长任务，成本直接砍到 1/4。
  • Simon Willison 已经测了：他用 Fable 5.1 生成了一只骑自行车的鹈鹕动画，还分析了推理过程的文本特点——说明模型在创意任务上也能打。
  • HN 1268 分：这是近几个月 HN 上最高的 AI 模型帖子之一。社区在认真讨论，不是纯 hype。

OpenAI 预览 Astra——第一个达到 Critical 网络安全级别的 AI 模型
clawii，OpenAI 昨天发了 Astra 的预览文章，这是他们第一个达到 Critical 网络安全准备级别的模型。HN 161 分、75 条评论。虽然你大概率用不上，但这事的意义在于：AI 的能力天花板又往上推了一层。
📍 背景 · OpenAI 的"网络安全准备度"框架把模型分为几个等级，Critical 是最高级。Astra 是第一个达到这个级别的模型。它采用了 recurrent depth / looped transformer 架构，这种架构在推理深度上比传统 transformer 更高效。Sam Altman 说安全审查拖慢了 Astra 的部署——意思是能力已经很强，但安全把关需要时间。

为什么这事重要

  • AI 安全不是一个理论问题：当模型达到 Critical 级别，它理论上能自主发现和利用 0-day 漏洞。这对网络安全行业是大事。
  • recurrent depth 架构可能改变游戏规则：如果 looped transformer 能大幅提升推理深度，那它可能影响下一代模型架构。
  • Sam Altman 说"安全拖慢了部署"：这句话的潜台词是——模型能力已经远超当前安全审查流程的承受范围。
  • 对你来说：Astra 的能力可能最终会进入 ChatGPT 或 Codex，让你也能用上更强的推理能力。

🎯 今天就能做的事

  1. 读 OpenAI 的官方博文：Path to Astra（9月1日发布）
  2. 关注 HN 讨论：#20（161 points, 75 comments）——社区在讨论 recurrent depth 架构的影响
  3. 如果你做网络安全相关工作，这个模型可能直接影响你的工具链

OpenAI 发布 AI-Native Company Workflows——企业 AI 工作流官宣
clawii，OpenAI 昨天发了一篇新文章，讲的是企业如何用 AI 重构工作流。对非开发者来说，这可能是理解"AI 怎么改变日常工作"的最直接官方文档。
📍 背景 · OpenAI 从 7 月开始一直在推 ChatGPT Work 和 Codex 的企业应用。这篇文章是第一次系统性地讲"AI-native 工作流"应该怎么设计。它不只是一个产品更新，更是一个思维框架——教你如何从"用 AI 辅助做事"变成"用 AI 重新设计做事的方式"。

为什么这事重要

  • 企业 AI 正在从"试点"走向"重构"：这篇文章不是讲某个工具，而是讲工作流本身——从文档处理、审批流程、客户服务到项目管理，AI 怎么嵌入进去。
  • 对非开发者尤其有价值：你不需要写代码就能理解里面的框架。它讲的是"流程"而不是"技术"。
  • 和 Simon Willison 的 ChatGPT Work 文章互为补充：Simon 讲的是"怎么用"，OpenAI 讲的是"为什么这么设计"。
  • 企业级采纳信号：OpenAI 专门写这个，说明他们看到了企业客户的需求，也说明企业 AI 市场正在成型。

🎯 今天就能做的事

  1. 读 OpenAI 的原文：AI-Native Company Workflows（2026-09-01）
  2. 结合 Simon Willison 的 ChatGPT Work 文章一起读——先理解"为什么"，再看"怎么用"
  3. 想一想你自己的工作中有哪些流程可以"AI-native"化——比如报销审批、周报生成、数据分析
🔬 深扒——AI-Native 工作流和传统自动化有什么不同
对比项AI-Native 工作流传统自动化（RPA / 低代码）
核心逻辑AI 做决策 + 执行规则驱动 + 执行
灵活性高（AI 能处理异常）低（规则外的异常需人工）
部署难度低（GPT 界面即可）中高（需要搭平台）
适合的场景非结构化流程（文档、邮件、审批）结构化流程（数据录入、报表）
学习门槛低（自然语言）中（需要懂规则引擎）

vs 传统自动化：传统自动化（RPA / 低代码）需要你先把规则写清楚，AI 才能执行。AI-native 工作流是反过来——AI 自己理解上下文，自己决定怎么做。这对非开发者来说是巨大的解放。

跑在什么之上：ChatGPT Work + Codex + Skills + Files API。全部在 OpenAI 平台上。

上手难度：读文章就能理解框架。实操需要 ChatGPT 付费账号。

诚实警告：这篇文章是理念框架，不是操作手册。具体实施还是要依赖 ChatGPT Work 的产品能力。但理解这个框架，能帮你判断哪些工作流值得 AI 化。
