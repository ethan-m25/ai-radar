🚨 Ornith-1.5：MIT 许可的新开源模型家族，自改进能力

开源模型 · MoE · 自改进 · 本地部署
📌 背景

开源模型领域竞争白热化：Qwen3.8-27B 刚成为本地运行的首选，DeepSeek V4 和 GLM-5.3 也在不断迭代。Ornith-1.5 由 ornith-ai 发布，提供 9B 密集、35B MoE 和 397B MoE 三种规模，全部采用 MIT 许可。它强调端到端自改进能力——模型可以通过自我生成数据来提升性能，无需人工标注。同时支持 FP8、GGUF、MLX、NVFP4 等多种量化格式，适配从 Mac Mini 到数据中心的各种硬件。

💡 为什么重要
  • MIT 许可：比 Apache 2.0 更宽松，商业使用无任何限制，可以自由修改、再分发。
  • 多规模选择：9B 适合消费级 GPU（如 RTX 4090），35B MoE 适合工作站，397B 适合服务器。你总能找到适合自己硬件的版本。
  • 自改进能力：模型可以自己生成训练数据并迭代，意味着未来可能不需要昂贵的微调就能持续提升。
  • 对非开发者的意义：如果你在本地运行模型（通过 Ollama 或 LM Studio），Ornith-1.5 的 9B 或 35B 版本可能成为你的新首选，性能接近 Qwen3.8-27B 但许可更自由。
⚡ 行动建议
  1. 查看 HuggingFace 模型卡：访问 ornith-ai/Ornith-1.5-35B-A3B 等页面，了解详细架构和基准测试。
  2. 尝试本地运行：如果你有 24GB+ VRAM，用 Ollama 或 llama.cpp 加载 9B 或 35B 的 GGUF 版本，对比 Qwen3.8-27B 的效果。
  3. 关注自改进的实际效果：社区可能会发布基于 Ornith-1.5 微调的专用模型，保持关注。
🔍 深度解析：Ornith-1.5 到底有什么不同

vs Qwen3.8-27B：Qwen3.8-27B 是原生多模态（支持图像输入），Ornith-1.5 目前只有文本。但 Ornith-1.5 的 35B MoE 架构在推理效率上可能更高（激活参数更少）。Ornith-1.5 的 MIT 许可比 Qwen 的 Apache 2.0 更宽松（虽然 Apache 2.0 已经很宽松）。Ornith-1.5 强调自改进，而 Qwen 依赖传统微调。

vs DeepSeek V4：DeepSeek V4 更大（1.7T 参数），但 Ornith-1.5 的 397B MoE 版本可能在某些任务上接近，且更易部署。

对 clawii 的实际价值：如果你用本地模型处理办公任务（总结文档、生成报告），Ornith-1.5 的 9B 版本可以在 16GB 内存的 MacBook 上运行，性能足够，且完全免费。

诚实顾虑：1）模型刚发布，社区验证不足。2）自改进能力需要实际测试。3）多模态缺失可能限制一些用例。

👀 关注点
  • Ornith-1.5 在 Vals 或 Artificial Analysis 上的基准分数。
  • 是否有 KOL（如 Simon Willison、swyx）评测它。
  • 社区是否快速适配到 Ollama、LM Studio 等工具。
📖 术语卡： MoE = Mixture of Experts — 混合专家架构，模型由多个子网络（专家）组成，每次推理只激活部分专家，提高效率。 自改进 — 模型通过自身生成数据并训练来提升性能，类似自我对弈。

👀 agent.md：一份文件，让 LLM 更好地理解你的代码库

实践指南 · 代码质量 · agent 协作
📌 背景

使用 Claude Code、Codex 等编码 agent 时，经常遇到 LLM 不理解项目结构、编码风格或测试要求的问题。Fabiensanglard 在 HN 上分享了他的解决方案：在项目根目录放一个 agent.md 文件，用自然语言描述项目背景、架构、约定和常见陷阱。LLM 在开始工作前会自动读取这个文件，从而生成更符合预期的代码。HN 上 324 分、138 条评论，社区反响热烈。

💡 为什么重要
  • 简单有效：一个 Markdown 文件就能显著提升 LLM 辅助代码的质量，无需复杂配置。
  • 对非开发者的意义：如果你用 Claude Code 或 Codex 编写脚本（比如自动化办公任务），agent.md 可以帮助 LLM 理解你的项目背景和输出要求。
  • 社区验证：324 分和大量评论表明很多人已经实践并受益。
  • 可能成为新标准：类似 CONTRIBUTING.md 但针对 AI 助手，未来可能被更多工具原生支持。
⚡ 行动建议
  1. 阅读 Fabiensanglard 的文章：了解 agent.md 的具体内容和格式。
  2. 为你的项目创建 agent.md：包含项目描述、编码风格、测试要求、常见错误等。
  3. 在 Claude Code 或 Codex 中测试：观察 LLM 是否自动读取 agent.md（目前需要手动引用或工具支持），对比使用前后的代码质量。
🔍 深度解析：agent.md 和系统 prompt 有什么不同

vs 系统 prompt：系统 prompt 是会话级别的，每次新对话都需要重新设置。agent.md 是项目级别的，放在代码库中，可以被 LLM 自动发现（如果工具支持）。它类似于 README 但专门针对 AI 助手。

对 clawii 的实际价值：假设你有一个“每周报告生成”项目，agent.md 可以告诉 LLM：报告格式、数据来源、输出路径、常见错误处理。这样每次运行 Claude Code 时，它都会遵循这些规则，减少手动纠正。

诚实顾虑：1）目前不是所有工具都原生支持 agent.md，可能需要手动引用。2）agent.md 需要维护，如果项目变化快，可能过时。3）效果取决于 LLM 的理解能力。

👀 关注点
  • 是否有工具（如 Cursor、Claude Code）宣布原生支持 agent.md。
  • 社区是否形成 agent.md 的最佳实践模板。
📖 术语卡： agent.md — 一个 Markdown 文件，放在项目根目录，用于指导 AI 编码 agent 如何理解和处理代码库。

ℹ️ 什么是 Harness？理解 AI agent 架构的核心概念

概念 · agent 架构 · 基础设施
📌 背景

随着 AI agent 工具爆发（Claude Code、Codex、CrewAI、AutoGen 等），一个核心概念逐渐浮现：harness。HN 上 earendil.com 的一篇文章（464 分 / 155 评论）系统解释了 harness 是什么——它是管理 agent 生命周期、工具调用、状态持久化、安全隔离的基础设施层。理解 harness 有助于你选择和使用合适的 agent 框架。

💡 为什么重要
  • 概念澄清：harness 是 agent 架构的关键抽象，类似于操作系统之于应用程序。
  • 社区关注：464 分表明很多人认为这个概念重要。
  • 对非开发者的意义：了解 harness 有助于理解为什么有些 agent 工具更好用，以及如何评估新工具。
