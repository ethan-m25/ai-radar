Anthropic Claude Opus 5.5 — 性能持平 Fable 5.1，价格降 40%

hey clawii — Anthropic 昨天突然放出 Opus 5.5，它跟最贵模型 Fable 5.1 性能差不多，但价格砍了 40%。这不是技术跃迁，是定价信号——大模型价格战正式开打。

📍 背景：Anthropic 目前有三条产品线：Mythos（最便宜）、Fable（最强，适合 coding 和科学）、Opus（次强，平衡性能与价格）。Opus 5 发布后，Fable 5.1 在 9/1 发布，现在 Opus 5.5 直接吃掉 Fable 的大部分能力。这是 Anthropic 主动降价抢占企业的策略：与其让你用 OpenAI 的便宜模型，不如我自己降价。

为什么这事重要

  • 性能等效于旗舰：Opus 5.5 在大多数任务上达到 Fable 5.1 的水平，尤其是代码、推理、写作。这意味着你不需要花 Fable 的钱就能得到差不多的能力。
  • 价格直降 40%：输入 $15/百万 token，输出 $60/百万 token（相对于 Fable 的 $25/$100）。这对企业用户是实打实的成本节省。
  • 对 vibe coding 用户：如果你自己调 API 做自动化，直接切到 Opus 5.5，成本省一半，体验不减。
  • 信号：Anthropic 主动降价，说明竞争白热化。下一个可能是 OpenAI 跟牌。

🎯 你现在就能做

  1. 如果你在用 Claude Code 或 API，把 model 从 claude-fable-5-1 改成 claude-opus-5-5。在 Claude Code 里：运行 /model 并选择 Opus 5.5。
  2. 对比测试：同一任务分别跑两个模型，看性能差异是否可接受。
  3. 如果跑 OpenAI 的 GPT-6 Sol/Luna，也可以考虑切回 Opus 5.5 做备份。

OpenAI GPT-6 Sol 和 Luna — 旗舰分化为「高智商」和「高情商」两条线

你看这个 — OpenAI 同一天发布 GPT-6 Sol（高智商/STEM）和 GPT-6 Luna（创意/对话/安全性更高）。这不是新模型发布，是产品策略分岔：以后你想写代码用 Sol，想写邮件用 Luna。

📍 背景：GPT-6 Astra 是 9 月发布的通用旗舰，首次达到「临界安全」级别。现在 Sol 和 Luna 是 Astra 的分化版本：Sol 针对 STEM/代码/数学，极强但安全护栏较松；Luna 针对创意/对话/安全，更温和。OpenAI 同时还优化了 prompt caching，让重复 prompt 成本更低。
中文

为什么这事重要

  • 产品分化信号：不再是「一个模型干所有事」。Sol 专注理科，Luna 专注文科。你可以根据任务选模型，而不是一个模型适配所有场景。
  • Sol 突破 Enigma 密码：OpenAI 展示 GPT-6 Astra 破解了自 2005 年悬而未决的 Enigma 消息（670 分 HN）。这证明 Sol/Astra 在密码学和推理上确实有实质进步。
  • 对 vibe coding 用户：如果你主要写代码，用 Sol；如果你要用 AI 写报告/邮件/创意内容，用 Luna。
  • 更好的 prompt caching：OpenAI 宣布改进的 prompt caching，重复前缀更快更便宜。如果你用固定系统提示词，成本能再降 30-50%。

🎯 你现在就能做

  1. 在 API 中指定模型：coding 任务用 gpt-6-sol，写作/对话用 gpt-6-luna。
  2. 利用新的 prompt caching：如果你的系统提示词很长且有重复前缀，启用 caching 可大幅降低成本。
  3. 对比测试 Sol vs Opus 5.5，看哪个在代码生成上更适合你。

Jev 正式确立「决策模型」品类 — Simon Willison 深度评测引爆社区

hey clawii — Jev 这个「系统一模型」昨天被 Simon Willison 写了 983 字深度评测，社区开始认真讨论。这不是另一个聊天机器人，而是一种专门做判断/分类/评分的模型——输出浮点数而非文字。

📍 背景：Jev 由 TypeSafe AI 于上周发布，是一种新品类——System One 模型（又称决策模型）。它不是生成文本，而是输入文本后直接输出评分/分类/置信度。昨天 Simon Willison 发布了详细评测（983 字），HN 上 Jev 相关讨论有 #1（204 分）、#26（296 分讨论 OpenAI 跟进）、#27（JevBench 基准测试）。信号从「弱」升级为「值得看」。
中文

为什么这事重要

  • 新品类正式确立：Simon Willison 的评测等于业界认可。Jev 不是传统 LLM，而是一种「决策引擎」——输入自然语言，输出结构化数值。
  • OpenAI 被指可能跟进：HN 上有一篇讨论「OpenAI is well positioned to fast-follow Jev」（296 分），说明大厂已经盯上这个方向。
  • JevBench 发布：社区已经创建了 JevBench，一个可复现的决策模型基准测试。说明生态开始形成。
  • 对你意味着：未来可能有专门的「判断模型」来处理审核、分类、评分，比通用 LLM 更便宜、更可靠。

🎯 你现在就能做

  1. 读 Simon Willison 的评测：Jev introduces a new shape of LLM
  2. 去 TypeSafe AI 官网看 Jev API 文档。
  3. 想一下你工作中是否有「是/否」或「评分」类任务（比如简历评分、邮件分类），可以尝试用 Jev 替代传统 LLM。

⚠️ 注意：不是开源模型，只能通过 API 使用。定价未公开。社区已创建 JevBench 用于可复现比较。
