Claude 发现新型酶系统 + 模型价格战（Opus 5.5 / GPT-6 Sol & Luna / MiMo v2.6）

clawii，模型价格战正式开打。Anthropic 和 OpenAI 昨天几乎同时发了新模型，而且都在降价。同时 Claude 还搞了个科学大新闻——自己发现了一个全新的酶系统。这三件事放一起，意味着你接下来两周能用到更便宜、更强的模型。

📍 背景 · 上周（9/22）Anthropic 发布了 Claude Opus 5.5，OpenAI 紧接着发了 GPT-6 Sol 和 GPT-6 Luna。昨天（9/23）Anthropic 又放出一个重磅科学发现：Claude 在分析宏基因组数据时，发现了一个具有 CRISPR 样重复序列的新型酶系统。与此同时，MiMo v2.6 Flash/Pro 也在同一周发布。模型发布密度极高，且全部伴随降价。
为什么这事重要
  • Opus 5.5 性能 ≈ Fable 5.1，价格低 40% — 如果你在用 Claude，这是目前性价比最高的模型。Simon Willison 实测说 "Opus 5.5 在大多数工作上和 Fable 5.1 差不多，但便宜一大截"。
  • GPT-6 Sol 和 Luna 是 Astra 的变体 — Sol 侧重推理/科学，Luna 侧重速度/成本。OpenAI 在打双模型策略，类似 Google 的 Gemini Pro vs Flash。
  • Claude 发现新酶系统 — 这不是 benchmark 刷分，是 AI 在真实科学发现上的突破。Claude 分析了大量宏基因组数据，找到了一个之前没人注意到的酶家族。这对 AI 在生物/医药领域的应用是里程碑信号。
  • 价格战意味着你的 API 账单会降 — 三个厂商（Anthropic / OpenAI / 小米 MiMo）都在降价，接下来两周你会看到更多降价公告。
🎯 今天就能做的事
  1. 打开 Claude，试试 Opus 5.5（如果你有 API 权限，价格比 Fable 5.1 低 40%，性能几乎一样）。
  2. 如果你是 vibe coding 用户，在 Codex 或 Claude Code 里切到 GPT-6 Sol（推理更强）或 Luna（更快更便宜），看哪个更适合你的工作流。
  3. 关注 Anthropic 的 Claude 科学发现页面——如果这个酶系统能落地，未来几个月会有更多 AI + 生物学的工具出现。

Claude 发现酶系统怎么工作的？ Claude 被用来分析大量宏基因组测序数据（来自环境样本的 DNA）。它在数据中识别出了一个之前未被描述的基因簇，这个基因簇编码的蛋白质具有类似 CRISPR 的重复序列结构。实验室验证后确认这是一个新型酶系统。这不是 Claude 自己"想"出来的，而是它在海量数据中找到了人类没注意到的模式。

老实说：对非科学家来说，这个发现本身不会直接影响你的日常工作。但它是一个强烈的信号——AI 正在从"聊天工具"变成"科学发现工具"。如果你在医药/生物相关行业，这周就应该开始研究怎么用 AI 分析你的数据。

🔭 盯什么 · 接下来 1-2 周，关注 Anthropic 是否会把这个酶系统做成可用的 API 或工具。如果 Anthropic 推出"科学发现即服务"，那才是真正的产品化信号。
术语解码 · 宏基因组 = 直接从环境样本（土壤、海水、人体肠道）中提取所有微生物的 DNA 进行测序，而不是单独培养某种细菌。 · CRISPR = 一种细菌的免疫系统，科学家用它来做基因编辑。Claude 发现的酶系统有类似的结构。

Mercury 2.5 LLM — 推理速度 770 tokens/秒

clawii，有个叫 Mercury 2.5 的模型跑到了 770 tokens/秒——比 GPT-4 快 10 倍以上。虽然它是个小模型（不是全能型），但在特定任务上这个速度意味着"实时"不再是口号。

📍 背景 · Mercury 2.5 由 Artificial Analysis 在 9/24 的 HN 上曝光。它达到了 770 tokens/秒的推理速度，是目前公开可测模型中最快的之一。这个速度主要得益于极致的模型量化和推理优化，而不是模型本身有多大。
为什么这事重要
  • 770 tokens/秒意味着什么？ 你打一个字的时间（约 200ms），这个模型能生成 150 个 token。对于实时翻译、语音助手、代码补全这类场景，延迟几乎不可感知。
  • 不是全能模型 — Mercury 2.5 在推理/知识类任务上不如 GPT-6 或 Claude Opus。它的优势在速度，不是智商。
  • 对 vibe coding 的影响 — 如果你用 AI 做代码补全（Codex / Cursor / Copilot），速度是关键。Mercury 2.5 这类模型可能成为代码补全场景的"专用引擎"。
🎯 今天就能做的事
  1. 去 Artificial Analysis 看看 Mercury 2.5 的 benchmark 详情，了解它在哪些任务上快、哪些任务上弱。
  2. 如果你在用 Cursor 或 Codex，关注它们是否会集成 Mercury 2.5 作为速度选项。
  3. 思考你的工作流中哪些环节对"速度"敏感（实时翻译、语音转文字、代码补全），这些场景可能很快会有专用模型。

怎么做到的？ Mercury 2.5 使用了极致的模型量化（可能是 2-bit 或 3-bit）和专门的推理内核优化。它不是一个"大模型"，而是一个为速度优化的专用模型。类似 Apple 的 On-Device 模型策略——小、快、够用。

老实说：770 tokens/秒很惊艳，但你要知道这是"生成速度"，不是"思考速度"。在复杂推理任务上，它可能不如一个慢 10 倍但更聪明的模型。这不是 GPT-6 的替代品，而是补充。

🔭 盯什么 · Mercury 2.5 是否会开放 API 或开源。如果它变成可用的服务，实时语音翻译和代码补全会是第一波受益场景。

Gemini 3.8 文本转语音 — 质量飞跃

clawii，Google 的 Gemini 3.8 TTS 在 HN 上拿了 309 分。如果你做任何需要语音输出的东西（播客、语音助手、有声书），这个值得周末试一下。

📍 背景 · Google 在 9/24 发布了 Gemini 3.8 的文本转语音功能。HN 上 309 points 说明社区反响强烈。这不是一个"新模型"，而是 Gemini 3.8 多模态能力的一部分——它现在可以生成极其自然的语音。
为什么这事重要
  • 语音质量接近人类 — 早期评测说 Gemini 3.8 TTS 在自然度上超过了 ElevenLabs 和 OpenAI 的 TTS。特别是情感表达和语调变化。
  • 对非开发者的意义 — 如果你在做视频配音、播客、或者任何需要语音的内容，这个工具可以省掉你找配音演员的成本。
  • 多语言支持 — Gemini 3.8 原生支持多语言，TTS 质量在中文上也可能不错（待实测）。
🎯 今天就能做的事
  1. 去 Google AI Studio 试试 Gemini 3.8 的 TTS 功能，输入一段中文文本听听效果。
  2. 如果你在用 ElevenLabs 或 OpenAI TTS，对比一下质量和价格。
  3. 考虑在你的工作流中加入语音输出——比如让 AI 读邮件、读文档摘要。
