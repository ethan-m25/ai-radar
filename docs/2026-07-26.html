Opus 5 上下文工程新规 — 349 points，Claude 5 系列最佳实践

爪哩，Anthropic 的 Thariq Shihipar 今天发了《Claude 5 代模型的上下文工程新规则》，上了 HN #6 获得 349 points。这不是模型发布，而是告诉你"怎么用 Opus 5 / Fable 5 才能发挥最大效果"——对 vibe coder 来说比模型发布本身更实用。

📍 背景 · 上下文工程（Context Engineering）是指如何组织 prompt、提供背景信息、设置系统提示来让模型输出更好。Claude 5 系列（Fable 5、Opus 5）在 agent 和长任务上有显著提升，但需要不同的上下文策略——比如更强调"角色设定"和"任务分解"。Thariq 的指南是官方最佳实践，直接来自 Anthropic 团队。

为什么这事重要

  • 官方最佳实践，不是社区猜测 — 这是 Anthropic 团队写的，不是第三方博客。349 points 说明 HN 社区认为它质量高。
  • 直接提升你的 vibe coding 效果 — 指南里讲了如何用"角色设定"让 Opus 5 更主动、如何分解长任务、如何避免上下文溢出。你读完就能用到 Claude Code 里。
  • Opus 5 的性价比优势需要正确的上下文策略 — 昨天我们说了 Opus 5 接近 Fable 5 但半价。但如果你用错了上下文策略，效果会打折扣。这个指南就是帮你把 Opus 5 的潜力榨干。

🔬 深扒——上下文工程 vs 普通 prompt 工程
方面上下文工程（新）传统 prompt 工程
核心思想模型是"角色"，给它完整的背景和任务上下文模型是"工具"，给指令和示例
角色设定必须明确（如"你是一个资深 Python 开发者"）可选，不强制
任务分解自动拆解长任务，模型自己规划步骤手动拆解，用户提供步骤
上下文长度尽量提供完整背景，模型会自己过滤尽量精简，避免"噪声"
适用模型Claude 5 系列（Fable 5、Opus 5）GPT-4、Claude 3 等旧模型
学习曲线需要调整习惯，但效果提升明显已经熟悉，但效果有限

老实说：这不是革命性的新概念，更像是对 Claude 5 系列的最佳实践总结。但如果你正在用 Opus 5 做 vibe coding，花 30 分钟读这个指南，可能让你的 agent 效果提升 20-30%。

术语解码 · 上下文工程 = Context Engineering，指如何组织 prompt 和背景信息来让模型输出更好。角色设定 = Role Setting，给模型一个明确的身份（如"你是一个资深开发者"）。任务分解 = Task Decomposition，模型自己把大任务拆成小步骤。
