GPT-6 Astra 第二日跟踪——OpenRouter 已上线、Simon 发布深度评测、社区发现 ARC 99.9% 的隐藏条件更严重了
clawii，昨天 GPT-6 Astra 发布后今天又出现重磅新信息：OpenRouter 已经上架了 Astra 模型（236 个 HN points），Simon Willison 发布了他第一篇深度评测博客，用 pelican SVGs 展示了从 low 到 max reasoning 的差异。更关键的是 HN 暴论区发现 ARC-AGI 3 那个 99.9% 的 Provider Adapter harness 问题比第一天报道的严重——评测论文直接承认"这个 99.9% 不能和其他模型直接比较"。
📍 背景 · GPT-6 Astra 是 OpenAI 昨天发布的旗舰模型，定价与 Claude Fable 5.1 一致（$10/$50）。昨天我们的主条目聚焦在安全能力碾压和 ARC 隐藏条件上。今天出现了三个新 signal：OpenRouter 直接上架、Simon 的 pelican 评测（从 low 到 max reasoning 对比）、以及社区强烈质疑 ARC-AGI 3 评测的公平性。Simon 的评测已提到"发现昨天我没有报导的内容——包括更详细的性能变化"。

为什么这事值得再跟进

  • OpenRouter 已上线 Astra：这意味着你可以立即通过 API 调用 Astra，不需要等 ChatGPT 推送。236 个 HN points 说明开发者已经在实际测试了。
  • Simon Willison 发布了完整评测：他用 pelican SVGs 在 low/medium/high/xhigh/max 五个 reasoning 级别上做了对比，发现"从 low 到 high 的质量提升非常明显，但 max 模式用了超多 token"——这对你决定用哪种 reasoning 级别很有参考价值。
  • 社区发现 ARC-AGI 3 评测的猫腻比想象中严重：HN 上有人分析了 OpenAI 的技术报告，发现 99.9% 是在"一个定制化的 Provider Adapter 评测框架"下拿到的，标准 ARC-AGI 3 harness 只有 62.7%。更关键的是，这个 62.7% 本身也低于 GPT-5.6 Sol 发布时候的分数——也就是说 Astra 的"新能力"可能被高估了。
  • OpenAI 博客服务器 500 错误仍未修复：官方公告只能通过镜像访问。这在发布第二日仍未修复，说明可能出现了严重的部署问题。社区已经开始猜测这是"发布节奏失误"。

  4. 关注 HN 上关于 ARC-AGI 3 猫腻的讨论：HN 讨论帖（已经 2004+ 条评论）

Simon 评测的核心发现：他让 Astra 在 low/medium/high/xhigh/max 五个级别各生成一副"骑自行车的 pelican" SVG。区别明显——high 以上的 pelican 姿态更自然、细节更丰富但 token 消耗飙升。他说："max 模式下的 pelican 几乎可以作为画廊作品……但用了 8x 多 token。"

ARC-AGI 3 猫腻再放大：HN 上有人指出，Provider Adapter harness 让 Astra 可以在多个请求之间保持推理状态和压缩信息——这本质上是一个"多次尝试 + 内部协同"的评测，而不是单次推理能力。标准 harness 下的 62.7% 低于 Sol 的历史值（约 65%），说明 Astra 的通用推理能力可能没有比 Sol 强，只是安全能力和长上下文更强。

OpenRouter 实测：网友报告 Astra 在 OpenRouter 上延迟约为 5-8 秒预填充 + 30 tokens/s 流式输出——类似 Fable 5.1 的性能水平。

诚实警告：今天的信息量是"负面大于正面"——ARC 猫腻扩大、博客故障持续、token 消耗巨大。如果你对安全领域不感兴趣，Astra 可能不值得立即切换。

🔭 盯紧什么 · 看 OpenAI 是否会在未来几天发布博客修复和 ARC 澄清。如果 62.7% 的标准 harness 分数被确认且没有额外解释，Astra 的声誉会受影响。另外，关注 Anthropic 是否跟进发布 Fable 5.1 在 ARC-AGI 3 上的分数——如果 Fable 更高，竞争会更激烈。同时，关注是否有独立安全评测机构验证 Astra 的 ExploitBench 100% 得分。

Anthropic 将费马大定理形式化证明在 Lean 4 上开源——科学能力展示，但对 vibe coding 无直接影响
clawii，Anthropic 今天开源了一个仓库：在 Lean 4 中形式化证明费马大定理的程序——625 HN points，390 条评论。这是 Fable 5.1 能力的展示：一个 AI 能够通过 Lean 4 定理证明器验证一个 300 年未解的数学问题。但对你日常工作影响有限。
📍 背景 · 费马大定理是 1637 年提出的数学猜想，1994 年才由 Andrew Wiles 证明。Anthropic 让 Fable 5.1 用 Lean 4 定理证明器（一个形式化数学证明系统）完整生成并验证了证明过程。这对数学界和形式验证领域有重要意义——证明可以自动检查是否无漏洞。

为什么这事重要（但不用立即行动）

  • 形式化数学证明的里程碑：这不是 Codex/Claude Code 能做的事——它需要理解复杂的数学推理并且写出可在 Lean 4 中验证的代码。这对 AI 的抽象推理能力是重大验证。
  • 对开发者生态的长期影响：如果 AI 能形式化验证数学证明，那它也可能会验证软件安全属性（比如无越界内存访问、无死锁）。这是 Fable 5.1 安全能力的一个方面。
  • 对你来说暂时无需行动：Lean 4 不是 vibe coding 工具，这也不是一个可用的 API 或端到端工具。属于 "知道了就行" 层级。除非你正在做安全关键的系统验证，否则你不需要立即尝试。
术语解码 · Lean 4 = 一个交互式定理证明器，用函数式语言写的形式化数学证明系统 · 形式化证明 = 用数学逻辑的语言写出的、可以被计算机自动验证的证明步骤。
