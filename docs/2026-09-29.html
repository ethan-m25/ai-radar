Anthropic 发布 Claude Sonnet 5.5——免费层现在就能用

clawii，你的日常 Claude Claude 代码助手免费版升级了。今天 Anthropic 把 Sonnet 5.5 放进了免费层，跑得快了 30%，价格没涨。要不要先试试看？

📍 背景：Sonnet 是 Claude 的"性价比旗舰"系列。两天前（9/28）Anthropic 发布 Sonnet 5.5，官方说是"比 Sonnet 5 快 30%+、成本低 30%"，但当时没说免费层。今天（9/29）免费层正式切换到 Sonnet 5.5。Simon Willison 第一时间试了：用免费版直接做出 3D 鹈鹕骑自行车——比 Luna 5.6 强。现在 Claude 免费版能力首次明显优于 ChatGPT 免费版。MIT license + 1M context 的 DeepSeek V4.1-Flash 上周刚抢走生态热度，Sonnet 5.5 这一下等于把性价比牌打了回来。

为什么这事重要

  • 免费层直接升杯：claude.ai 免费版现在跑的是 Sonnet 5.5；ChatGPT 免费版还是 Luna 5.6。你用 Claude Code 的话，等于每天白送更多 compute。
  • 与 Opus 5.5 的不同：Opus 5.5 = 降价 40% 的旗舰；Sonnet 5.5 = 降本增效的中流砥柱。Opus 适合复杂推理，Sonnet 适合日常 coding，现在两个都升级了。
  • 社区检测结果有趣：Sonnet 5.5 强度和 Opus 5.5 相近（Simon 说"某些任务几乎一样"），但 Sonnet 输出格式控制略差——你的 CLAUDE.md 可能需要微调。
  • 价格不变：API 价格 $3/MTok input + $15/MTok output，比 Fable 5.1 便宜得多。

🎯 你现在可以做的事

  1. 打开 claude.ai，确认免费模型显示 Sonnet 5.5——然后跑一个你平时在 Claude Code 做的任务，感受速度差异。
  2. 更新 CLAUDE.md：Sonnet 5.5 对输出格式控制敏感度下降，你需要更明确的格式描述（JSON / 表格等）。
  3. 对比 Opus 5.5 vs Sonnet 5.5 在三个日常任务上的输出质量——决定哪个当默认模型。
  4. 注意：Sonnet 5.5 的"高度思考"（max thinking effort）选项在需要时仍然收费——免费层默认关。

Jeff 决策模型火到 HN 头条：506 分，192 条评论，本地 30 毫秒推理

clawii，Jev 生态的"本地决策模型"今天冲上了 HN 前三。这次不是 API 调用——是你在笔记本上就能跑的 0.8B 小模型，推理只要 30 毫秒。本周 HF 博客上了 6+ 篇 Jev 教程，这个赛道开始卷落地了。

📍 背景：Jev 是今年新兴的"决策模型"品类——不是常规 LLM（会聊天、会生成），而是接受结构化输入、输出确定性决策结果的小模型。通常与 RAG 或 agent 流程配合，代替动辄几千次 API 调用的 LLM 决策。上周（9/24）我们提过 Jev 生态开始热起来。今天 HN 出现了一个叫 Jeff 的 0.8B 模型（firelex/jeff），开源、可本地运行，推理延迟约 30ms。同时 autotrust/JEV-27B（带完整推理的 27B 决策模型）也在 HF 上出现。这个品类从"知性概念"变成了"能跑生产"。

为什么这事重要

  • 0.8B 参数，30ms 推理：这意味着一台普通的 MacBook 或 Windows 笔记本就能跑决策模型，不需要任何 GPU——适合作为 agent 流程中的"快速判断"前哨。
  • 开源且与 Jev 兼容：Jeff 使用 Jev 的决策协议。如果你已经在用 Jev 做 agent 决策，可以无缝替换或降级到 Jeff 做简单判断。
  • HF 博客一周内 6+ 篇 Jev 教程 + 对比文章：社区已经在认真教你怎么用、怎么选。这通常是技术开始从早期玩家向主流用户扩散的标志。
  • 107k stars 等级的 "Jeff" 没用多平台，纯靠 HN 社区冲到首页：说明是真的差评少、硬核用户认可。

🎯 你现在可以做的事

  1. 克隆 Jeff 仓库并用 Ollama 跑一次基准测试（如果你有 Ollama）：ollama pull firelex/jeff:0.8b
  2. 想一个你正在写 agent 流程中的"快速判断"步骤（比如：这个邮件需要人工回复吗？），试试用 Jeff 替换原本的 LLM 调用。
  3. 花 15 分钟读一篇 HF 上的 Jev 教程——推荐"Jev vs LLMs: When Should You Use a Decision Model"那篇（sora-2，8 days ago）。
  4. 记住：Jeff 是 0.8B，autotrust/JEV-27B 是 27B——它们解决不同质量需求的场景。

跑在什么之上：Jeff 基于一个小型 encoder-only 架构，不需要 transformer decoder。Ollama / llama.cpp 都可以跑。

上手难度：如果用过 Ollama，下载加运行不超过 5 分钟。如果是第一次接触决策模型，需要理解它的输入格式（结构化 string / JSON）——教程读 15 分钟就够。

诚实说：决策模型的核心价值是"减少你自己写条件判断代码"，但对 vibe coder 来说，不一定比直接写 if-else 快。适合的场景是"我有一堆非结构化的输入，需要一个灵活的分类/评分引擎"。

🔭 盯什么：Jeff 能不能在 1-2 周内被主流 agent 框架（n8n / Dify / LangChain）直接集成成插件；有没有 KOL 正面推荐。如果有，说明决策模型进入了"拿来就能用"阶段。
术语解码：
Jev = 一个开放标准的"决策模型"品类。和 LLM 不同，它不生成文字回复，而是接受输入、输出结构化的决策（评分、类别、路由目标）。
0.8B = 8 亿参数：很小，可以在 CPU 上实时跑。对比：GPT-5.6 是万亿级参数。
推理延迟 = 模型从接收到输出结果的时间。30ms 约等于人眼一眨眼的时间里跑了 3 次决策。

AI 公司向广告商泄露数据——不是 bug，是设计

clawii，一篇研究论文显示用户与 AI chatbot 的聊天内容可能被泄露给广告商。这不是孤例，是新的商业模式。知道你不需要立刻割舍 AI——但知道这件事本身很重要。

为什么这事值得知道

  • 不是偶发，是类商业模式：研究发现多家 AI 服务（包括一些知名平台）在聊天 API 中嵌入了广告追踪代码，将用户意图、聊天主题等信号传给广告网络。
  • 对 vibe coder 的意义：如果你在用免费 AI 工具做商业项目的原型，输入的材料可能被用于广告定向——隐私敏感场景（HR / 薪资 / 法律）最好只走付费 API 或本地模型。
  • 后续走向：这篇文章 2 小时前发到 HN，86 分，评论区已经开始讨论"这是否构成 GDPR 违规"，值得后续跟踪。
