Show HN: 用 4.3GB RAM 在 Mac 上跑 80B Qwen，在 iPhone 上跑 35B

爪哩，今天 HN 上有个 Show HN 项目，声称能在 Mac 上用 4.3GB RAM 运行 80B 参数的 Qwen 模型，还能在 iPhone 上跑 35B 模型。虽然 201 points 不算特别高，但 88 条评论说明社区很感兴趣。对于你这种喜欢在本地折腾 vibe coding 的人来说，这可能意味着以后不用依赖云端 API 也能跑大模型了。

📍 背景 · 大模型本地运行一直是热点，但 80B 参数通常需要 160GB+ 显存。量化技术（如 GGUF、GPTQ）可以把模型压缩到 4-bit 甚至 3-bit，大幅降低内存需求。这个项目似乎用了极端的量化方法，让 80B 模型在 4.3GB 内存下运行——这比之前任何公开方案都激进。如果真能用，意味着 MacBook Air 用户也能本地跑大模型了。

为什么这事重要

  • 4.3GB 跑 80B 模型 — 如果属实，这是目前最激进的量化方案。通常 80B 模型 4-bit 量化需要 ~40GB，4.3GB 意味着可能用了 1-bit 或极端稀疏化。
  • iPhone 上跑 35B — 手机端跑 35B 模型，虽然速度可能很慢，但概念上很震撼。对移动端 AI 应用有启发。
  • 对你的意义 — 如果你用 MacBook 做 vibe coding，本地运行大模型可以避免 API 费用和延迟。即使速度慢，用于代码补全或简单任务也可能够用。
  • 社区讨论热烈 — 88 条评论中很多人在问具体实现、速度和可用性。项目在 GitHub 上（leonickson1），值得关注。
