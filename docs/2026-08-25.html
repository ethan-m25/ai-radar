Qwen 3.8-Flash-Next (125B a6B) 明天发布
clawii，通义千问又要发新模型了。这次是 Flash-Next，125B 参数但只激活 6B，明天（8月26日）在 ModelScope 上线。如果你已经在用 Qwen3.8-27B 做 vibe coding，这个新模型可能让你在消费级显卡上跑出接近旗舰的水平。
📍 背景 · Qwen3.8 系列是阿里开源的多模态 dense 模型（27B），过去两周在 Hugging Face 上屠榜，衍生出几十个 uncensored / abliterated 变体。Flash-Next 是 MoE（混合专家）架构——125B 总参数但每次推理只激活 6B，意味着推理速度极快、显存需求低。这是阿里在开源 MoE 路线上的最新动作，直接对标 DeepSeek V4-Flash 和 Ornith-1.5-35B-A3B。

为什么这事重要

  • 消费级显卡跑旗舰级模型：6B 激活参数意味着 RTX 4090（24GB）甚至 4070（12GB）都能本地跑。你不需要租 A100 就能在本地做复杂代码生成。
  • MoE 架构 + Apache 2.0：完全开源，没有商用限制。阿里在开源策略上比很多美国公司激进得多。
  • Flash 系列的速度优势：前代 Qwen3.8-Flash 的推理速度已经是 dense 版的 3-5 倍。Flash-Next 应该更快。
  • 对 vibe coding 生态的冲击：本地跑一个接近 GPT-5.6 Luna 水平的模型，意味着你的 Claude Code / Codex 可以切换成完全本地、零延迟、零数据外泄的 backend。

🎯 今天就能做的事

  1. 把 modelscope.cn 加入书签，明天上午刷新。
  2. 检查你的 Ollama / vLLM 版本是否支持最新的 Qwen MoE 格式（ollama pull qwen3.8-flash-next 可能明天就上线）。
  3. 如果你的 vibe coding 工作流依赖云端 API，考虑准备一个本地推理脚本，等模型发布后直接切换。
  4. 关注 Hugging Face 上的 Qwen 组织页面，量化版（GGUF / MLX）通常 24 小时内就会由社区放出。

vs DeepSeek V4-Flash-Vision-Exp：DeepSeek 的 MoE 是 304B 总参 / 37B 激活，比 Qwen Flash-Next 大得多，但 DeepSeek 的 License 是自定的（商用需申请），Qwen 是 Apache 2.0。Flash-Next 的 6B 激活意味着在同样硬件上可以跑更快的推理。

vs Ornith-1.5-35B-A3B：Ornith 的 MoE 是 35B 总参 / 3B 激活，更小更快，但能力上限可能不如 125B/6B 的 Qwen。Ornith 的优势是 MIT License 和完整的自改进训练流程。

跑在什么之上：Qwen 系列基于 Transformer + MoE，训练用阿里自己的框架。推理可以用 vLLM、llama.cpp、Ollama、MLX。

上手难度：如果你已经用过 Ollama 跑 Qwen3.8-27B，那 Flash-Next 就是 ollama pull 一个命令的事。自己编译 vLLM 支持新 MoE 可能需要等几天。

诚实警告：MoE 模型的"激活 6B"不意味着它真的和 6B dense 模型一样快——路由开销和 expert 加载有额外延迟。实际速度要看具体实现和硬件。

🔭 盯紧什么 · 明天（8/26）ModelScope 上线后，看 Hugging Face 社区 24 小时内是否出现 GGUF 量化版。如果 Karpathy 或 swyx 在 X 上发帖说"this is the way"，那就是信号确认。
术语解码 · MoE = Mixture of Experts（混合专家模型）——把模型拆成多个"专家"子网络，每次只激活其中几个，用更少的计算量达到大模型的效果。a6B = activated 6 billion parameters（激活 60 亿参数）。

Apple M6 / M5 Ultra — Mac Studio & Mac mini 算力飞跃
clawii，Apple 今天发了 M6 和 M5 Ultra，Mac Studio 和 Mac mini 全线更新。M6 的 AI 算力提升是"big leap"级别的——如果你用 Mac 做本地推理或 vibe coding，这可能比任何新模型都更直接影响你的硬件选择。
📍 背景 · Apple 的芯片路线图：M4 系列（2024）→ M5 系列（2025-2026）→ M6（2026）。M5 Ultra 是 M5 系列的顶配，M6 是下一代架构。今天发布的 Mac Studio 可选 M5 Max 或 M5 Ultra，Mac mini 可选 M6 或 M5 Pro。Apple 在 AI 推理上的优势是统一内存架构——可以把大部分系统内存当作显存用，这对跑大模型非常友好。

为什么这事重要

  • 本地推理能力翻倍：M6 的 Neural Engine 和 GPU 核心数大幅增加，意味着你可以在 Mac 上跑更大的量化模型（比如 Qwen3.8-27B 4-bit 甚至 8-bit），而不需要租云 GPU。
  • Mac Studio 成最强本地 AI 工作站：M5 Ultra 的 Unified Memory 可能达到 256GB 甚至 512GB——这意味着你可以本地跑 70B 甚至 120B 参数的模型。
  • 对 vibe coding 工作流的直接影响：如果你用 Mac + Ollama + Claude Code，更强的本地推理能力意味着你可以把更多任务从云端移到本地，减少延迟和 API 费用。
  • Apple 在 AI 硬件上的追赶：虽然 NVIDIA 仍然是训练之王，但 Apple 在推理（尤其是消费级推理）上的优势正在扩大。

🎯 今天就能做的事

  1. 如果你正打算换 Mac，等 M6 Mac mini 的详细评测出来再决定——特别是 MLX 框架的适配情况。
  2. 检查你当前 Mac 的 Ollama 性能：ollama run qwen3.8-27b:q4_K_M 看 tokens/sec。如果低于 15 t/s，M6 的升级会很明显。
  3. 关注 MLX 框架 的更新——Apple 的官方 ML 框架通常会第一时间适配新芯片。

Ornith-1.5 系列全线 GGUF/MLX 量化版上线
clawii，Ornith-1.5 的三个变体（9B dense / 35B MoE / 397B MoE）的 GGUF 和 MLX 量化版已经全部上线 Hugging Face。如果你在找 Qwen 之外的另一个开源选择，Ornith 的 MIT License 和自改进能力值得记住名字。

为什么这事值得知道

  • MIT License：比 Qwen 的 Apache 2.0 更宽松，商用没有任何限制。
  • 35B-A3B MoE 版本：3B 激活参数，可以在 8GB 显存的显卡上跑，适合 MacBook Air 或低端 GPU。
  • 自改进训练：Ornith 团队展示了模型自己生成数据、自己训练自己的流程，这对开源社区是一个重要方向。
  • 量化版已就绪：FP8、GGUF、MLX、NVFP4 格式全都有，下载即用。
