Automated Security Attacks: Vulnerabilities Exploited Within Minutes of Disclosure
Hey clawii — Cambridge professor Anil Madhavapeddy is reporting a scary new trend: security vulnerabilities are being automatically exploited by AI agents within minutes of being discussed publicly. The rclone maintainer confirms 40+ security disclosures in the past month (vs ~20 in the prior decade). Not a product launch, but it directly affects how you should protect your own code.
📍 Context · As coding agents like Claude Code and Codex go mainstream, security researchers are finding that AI agents can automatically scan public patch discussions, understand the vulnerability, and generate exploit code. Anil Madhavapeddy observed probe traffic within 10 minutes of patch discussions in the OCaml compiler community. The rclone project confirmed the same phenomenon. Simon Willison and the HN community are both on this.

Why this matters

  • Direct threat to your code's security: If you discuss a security fix in a public repo, attackers may exploit it within hours.
  • Traditional security processes are breaking: Existing vulnerability disclosure and patch-release workflows can't keep up with AI-speed attacks.
  • Impact on vibe coding: If you use AI agents to manage code, you need stricter security practices.
  • Simon Willison has covered it: This isn't a fringe phenomenon — it's a reality the mainstream security community is facing.

🎯 Action you can take today

  1. Read Anil's original report: recoil.org ("Just the rumour of a bug is enough")
  2. Audit your public repos: are there unfixed security issues being discussed openly? Consider a private disclosure process.
  3. If you run AI agents on your code, make sure they run in a sandbox with restricted network egress.
  4. Follow Simon Willison's ongoing analysis: simonwillison.net
🔬 Deep dive — how automated attacks work

The attack flow:

  1. A developer discusses a security patch on a public mailing list or GitHub issue.
  2. AI agents (e.g., automation built on Claude Fable or DeepSeek V4 Pro) monitor these discussions.
  3. The agent understands the vulnerability, auto-generates exploit code, and scans target systems within minutes.
  4. Anil successfully reproduced this attack using DeepSeek V4 Pro (when Claude Fable refused the task).

The rclone data: 40+ security disclosures in the past month vs ~20 in the prior decade. 75% of disclosures had real substance. GitHub's CVE assignment time went from 2-3 days to 3-4 weeks.

What this means for you:

  • Don't discuss unfixed security issues in public channels.
  • Use private vulnerability disclosure processes (like GitHub's security advisory feature).
  • If you use AI agents on your code, ensure they don't auto-apply patches from untrusted sources.

Honest caveat: This isn't a problem you can "solve" — it's a new reality to adapt to. The security community is actively discussing new embargo processes.

🔭 Watch for · Whether GitHub introduces new security disclosure workflows; whether mainstream coding agents (Claude Code, Codex) add security guardrails; whether new "AI security audit" tools emerge.
