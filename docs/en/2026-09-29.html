Claude Sonnet 5.5: free tier gets a huge upgrade, faster and cheaper for everyone

Hey clawii — if you were on the fence about which Claude model to use, Anthropic just made the decision easy. Sonnet 5.5 is out, the free tier on claude.ai now runs it, and it's 30% faster and up to 30% cheaper than Sonnet 5 at the same price.

📍 Context: Anthropic released their flagship Fable 5.1 and Mythos 5.1 on Sep 1, then Opus 5.5 (value flagship) on Sep 22. Today (Sep 28) Sonnet 5.5 drops. The Sonnet line has always been the "sweet spot" — stronger than Haiku, cheaper than Opus. This upgrade replaces Sonnet 5 at the same price with better performance, and the free tier on claude.ai now runs it directly. Simon Willison tested it immediately and found it "almost as good as Opus 5.5 on some coding tasks."

Why this matters

  • Free tier gets a real upgrade today: If you use claude.ai for free, you're now running a model that Simon describes as nearly Opus-level for many tasks. Try generating a 3D HTML page — it works.
  • For Claude Code users: Faster iterations, lower cost per run. If Claude Code switches its default to Sonnet 5.5 (likely), your vibe coding sessions become noticeably snappier.
  • Pricing signal: Same price as Sonnet 5, better performance. Anthropic is compressing costs while raising capability — good news for API users.
  • Positioning vs Opus 5.5: For most coding tasks Sonnet 5.5 is nearly as good. Unless you're doing the hardest reasoning tasks, it's probably your new default.

🎯 What you can do today

  1. Open claude.ai (free tier) and test its new capabilities — ask it to generate a 3D animated HTML page or a complex SVG.
  2. If you use Claude Code, check what model it's defaulting to. If it's still on Sonnet 5, switch to Sonnet 5.5 and compare speed on a few of your routine tasks.
  3. If you use the API, benchmark Sonnet 5.5 vs Opus 5.5 on your typical workload. Sonnet 5.5 might be the better default.
  4. Watch for Haiku 5.5 — Anthropic says "in the coming weeks." That could be the cheapest option yet.

👀 Worth a look

Jeff: A 0.8B Jev-compatible decision model you can train at home — 30ms inference

Hey clawii — the Jev decision model ecosystem just got a lot more accessible. Jeff is a tiny 0.8B parameter model compatible with the Jev format, trainable on your own GPU (yes, even an RTX 3090), and runs inference in about 30 milliseconds. HN gave it 506 points — the community is genuinely excited.

📍 Context: Jev is a new class of "decision model" — not a chat model, but a specialized model for classification, scoring, routing, and other deterministic tasks. They're typically small (0.5B–8B), fast, and designed to be embedded in agent workflows as "System 1" judgment calls. Over the last week we've tracked the Jev ecosystem growing rapidly (HF blog tutorials, openjev updates, GLiNER2.5-Decide joining the category). Now Jeff takes it further: 0.8B parameters, trainable on consumer GPUs, inference at 30ms. You can train your own decision model at home.

Why this matters

  • Decision models go mainstream: Earlier Jev models were 7B+ and required decent compute. Jeff's 0.8B means any developer with a GPU can train and deploy one.
  • 30ms inference — real-time agent decisions: You can embed Jeff in an agent workflow for intent classification, content filtering, or tool routing without adding meaningful latency to the main flow.
  • Jev-compatible: Drop-in replacement for other Jev models. Works with the openjev toolchain and others. No lock-in.
  • For vibe coders: If you write agents in Claude Code or Codex, you can use Jeff for fast, cheap decisions (e.g., "is this user asking for help or reporting a bug?") instead of calling a large model every time.

🎯 What you can do today

  1. Check out Jeff's GitHub README — understand the training method and Jev-compatible format.
  2. If you have a GPU (RTX 3090 or better), try fine-tuning a decision model on your own data using the provided training script.
  3. In your agent workflow, consider replacing some LLM calls with Jeff — for simple classification/routing tasks, it saves tokens and latency.

What it runs on: Based on Jev architecture, compatible with Jev inference format. Training uses PyTorch; inference via ONNX or direct PyTorch.

How hard to use: Moderate. If you're comfortable with PyTorch and model training, follow the README. For inference-only, use the pretrained weights — a few lines of code to load.

Honest caveat: A 0.8B model's capability ceiling is lower than a 7B model. For simple binary or 3-class tasks it's likely sufficient, but you need to test on your own data to be sure.

🔭 Watch for: Whether Jeff becomes the "entry-level standard" for the Jev ecosystem; community fine-tuning tutorials and pretrained weights; whether Jeff's low barrier leads to a wave of decision model applications.
Jargon decoder:
Jev = A class of small models specialized for decision-making (classification, scoring, routing). Not a chat model. Named after "Jevons."
Decision model = Unlike an LLM, it outputs a classification label or score instead of generating text. Fast, cheap, predictable.
0.8B = 800 million parameters — very small, runs on consumer GPUs.
