🚨 Ornith-1.5: MIT-licensed open model family with self-improvement

open model · MoE · self-improvement · local deployment
📍 Context

The open-model race is white-hot: Qwen3.8-27B just became the go-to local model, and DeepSeek V4 and GLM-5.3 keep iterating. Ornith-1.5, released by ornith-ai, comes in three sizes — 9B dense, 35B MoE, and 397B MoE — all under MIT license. Its headline feature is end-to-end self-improvement: the model can generate its own training data and iterate without human annotation. It also ships with multiple quantization formats (FP8, GGUF, MLX, NVFP4), covering everything from a Mac Mini to a data center.

WHY THIS MATTERS
  • MIT license: More permissive than Apache 2.0 — no restrictions on commercial use, modification, or redistribution.
  • Multi-scale choice: 9B fits consumer GPUs (RTX 4090), 35B MoE works on workstations, 397B targets servers. There's a version for whatever hardware you have.
  • Self-improvement capability: The model can generate its own training data and iterate, meaning future improvements may not require expensive fine-tuning.
  • What it means for someone like clawii: If you run local models (via Ollama or LM Studio), the 9B or 35B version could become your new default — performance close to Qwen3.8-27B but with a freer license.
🎯 ACTION
  1. Check the HuggingFace model cards: Visit ornith-ai/Ornith-1.5-35B-A3B and related pages to see architecture details and benchmarks.
  2. Try running it locally: If you have 24GB+ VRAM, load the 9B or 35B GGUF version via Ollama or llama.cpp and compare against Qwen3.8-27B.
  3. Watch for community fine-tunes: The self-improvement claim means specialized variants may emerge quickly.
🔬 DEEP DIVE: how Ornith-1.5 is actually different

vs Qwen3.8-27B: Qwen3.8-27B is natively multimodal (accepts images); Ornith-1.5 is text-only for now. But Ornith-1.5's 35B MoE architecture may be more efficient at inference (fewer active parameters). The MIT license is slightly more permissive than Qwen's Apache 2.0. Ornith-1.5 emphasizes self-improvement; Qwen relies on traditional fine-tuning.

vs DeepSeek V4: DeepSeek V4 is much larger (1.7T params), but Ornith-1.5's 397B MoE variant may rival it on some tasks while being easier to deploy.

What you can actually do with it: If you use local models for office work — summarizing documents, drafting reports, answering questions about your data — the 9B version can run on a 16GB MacBook with decent performance, completely free.

Honest caveat: 1) The model just launched — community validation is thin. 2) Self-improvement needs real-world testing. 3) No multimodal support limits some use cases.

👀 WATCH FOR
  • Benchmark scores on Vals or Artificial Analysis.
  • KOL reviews (Simon Willison, swyx, etc.).
  • How fast the community ports it to Ollama, LM Studio, etc.
📖 Jargon decoder: MoE = Mixture of Experts — the model has many sub-networks ("experts") and only activates a subset per inference, improving efficiency. Self-improvement — the model generates its own training data and retrains, like self-play in games.

👀 agent.md: one file that helps LLMs understand your codebase

practice guide · code quality · agent collaboration
📍 Context

When using Claude Code, Codex, or similar coding agents, you've probably experienced the LLM misunderstanding your project structure, coding style, or testing requirements. Fabiensanglard shared a dead-simple solution on HN: drop an agent.md file in your project root that describes the project background, architecture, conventions, and common pitfalls. The LLM reads it before starting work, producing much more predictable code. HN 324 points, 138 comments — the community is all over it.

WHY THIS MATTERS
  • Simple and effective: One Markdown file can dramatically improve LLM-assisted code quality with zero complex setup.
  • What it means for someone like clawii: If you use Claude Code or Codex to write scripts (automation, data processing), agent.md helps the LLM understand your project context and output expectations.
  • Community validated: 324 points and heavy discussion means many people have tried it and it works.
  • Could become a new standard: Like CONTRIBUTING.md but for AI assistants — future tools may support it natively.
🎯 ACTION
  1. Read Fabiensanglard's article: Get the exact format and content recommendations.
  2. Create an agent.md for your project: Include project description, coding style, test requirements, common mistakes.
  3. Test it in Claude Code or Codex: See if the LLM picks it up automatically (some tools need manual reference) and compare output quality before and after.
🔬 DEEP DIVE: how agent.md is different from a system prompt

vs system prompt: A system prompt is session-level — you have to re-set it every new conversation. agent.md is project-level — it lives in your repo and can be auto-discovered by the tool (if supported). It's like a README but specifically for AI assistants.

What you can actually do with it: Say you have a "weekly report generator" project. Your agent.md can tell the LLM: report format, data sources, output path, common error handling. Every time you run Claude Code on that project, it follows those rules. No more manual corrections.

Honest caveat: 1) Not all tools natively support agent.md yet — you may need to reference it manually. 2) The file needs maintenance; if your project changes fast, it can become stale. 3) Effectiveness depends on the LLM's ability to follow instructions.

👀 WATCH FOR
  • Do tools like Cursor or Claude Code announce native agent.md support?
  • Does the community converge on a best-practice template?
📖 Jargon decoder: agent.md — a Markdown file placed in the project root that instructs AI coding agents on how to understand and work with the codebase.

ℹ️ What Is a Harness? — understanding the core concept of AI agent architecture

concept · agent architecture · infrastructure
📍 Context

With the explosion of AI agent tools (Claude Code, Codex, CrewAI, AutoGen), a core concept keeps bubbling up: the harness. An article on earendil.com (HN 464 pts / 155 comments) systematically explains what a harness is — it's the infrastructure layer that manages agent lifecycle, tool calling, state persistence, and security isolation. Understanding "harness" helps you pick and evaluate agent frameworks.

WHY THIS MATTERS
  • Conceptual clarity: The harness is the key abstraction in agent architecture, like an operating system for applications.
  • Community attention: 464 points signals many people think this concept matters.
  • What it means for non-developers: Understanding harnesses helps you see why some agent tools work better than others, and how to evaluate new ones.
