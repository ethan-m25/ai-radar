Meta returns to open frontier: Muse Glimmer 30B local agent model

Apache 2.0 license, 30B parameters, multimodal, 128K context, ~18GB quantized — Muse Glimmer is one of the best local agent models yet. HN 1122 points, Simon Willison already hands-on.

🚨 Must see

Muse Glimmer: Meta open-sources 30B local agent model under Apache 2.0

clawii — Meta just dropped Muse Glimmer, a 30B multimodal model built for always-on local agents. Apache 2.0 license, runs on a single consumer GPU, and Simon Willison already has it working in his coding agent stack. This is the first truly open local agent model from a major lab in months.

Context. Meta's last open-weight release was the Llama 3 series, which had a custom commercial license that scared off some enterprises. Muse Glimmer is Apache 2.0 — no restrictions. It's a 30B dense model (not MoE), optimized for local deployment with 128K context, multimodal (vision), and a lightweight DFlash speculative decoder for faster generation. Released August 10, 2026.

Why this matters

  • Apache 2.0 license — no commercial restrictions, unlike Llama's custom license. Enterprises can use it in products without legal review.
  • Runs locally on consumer hardware — quantized to ~18GB (4-bit), fits on a 24GB GPU or 32GB Mac. No API costs, no data leaving your machine.
  • Strong agent benchmarks — top scores on DeepSearch QA, MCP-Atlas, τ-Bench, SWE-Bench. Can do multi-step reasoning and tool calling.
  • Immediate ecosystem support — vLLM, llama.cpp, Ollama, Together AI, Hugging Face Transformers all compatible day one.
🎯 What you can do today
  1. Download the GGUF quantized version (~18GB) and run it locally via ollama pull meta/muse-glimmer or LM Studio
  2. Try Simon Willison's llm-coding-agent plugin — he's already confirmed it works with Muse Glimmer
  3. Evaluate it as a drop-in replacement for GPT-5.6 Luna for daily coding assistance — zero cost, full privacy
  4. Watch for community 4-bit quantization benchmarks — may run on 16GB GPUs

vs Muse Spark 1.2: Spark is a 127B MoE model optimized for cloud inference (top 5 on Vals Index at $0.69/test). Glimmer is a 30B dense model for local deployment. They're complementary — Spark for high-throughput cloud, Glimmer for privacy-sensitive or offline use.

vs Claude Code / Codex: Both are closed-source agent services with API costs and data privacy concerns. Glimmer runs entirely locally — no API fees, no data leaving your machine. On complex coding tasks, Opus 5 or Sol may still be stronger, but Glimmer handles daily coding assistance, code review, and simple refactoring well.

Technical details: Gemma 4-style hybrid attention (local + global), scale-free QK norm for training stability. DFlash is a small transformer that generates tokens 3-5x faster, verified by the main model. 128K context handles medium-sized codebases.

How hard to use: 5 minutes. Download LM Studio, search "Muse Glimmer", load the model, and chat. For coding agent workflows, configure llm-coding-agent or write a simple script.

👀 Watch for: community fine-tunes for specific domains (Chinese, legal, finance). Enterprise adoption under Apache 2.0. Possible smaller (7B) or larger (70B) variants from Meta. Also watch whether this cannibalizes demand for cloud coding agents.
📖 Jargon watch:
Apache 2.0 — a permissive open-source license that allows commercial use, modification, and redistribution with only a copyright notice. More business-friendly than Llama's custom license.
Quantization — compressing model parameters from high precision (e.g., 16-bit float) to lower precision (e.g., 4-bit integer) to reduce size and speed up inference, usually with minimal accuracy loss.
DFlash (speculative decoding) — a lightweight "draft" model that generates tokens 3-5x faster; the main model then verifies them. This speeds up generation without quality loss.
