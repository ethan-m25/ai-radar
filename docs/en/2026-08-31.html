Claude Code Auto Mode Broken — Your Agent Might Be Getting Exploited
Hey clawii — Johann Rehberger found an attack against Claude Code Auto Mode with an 80% success rate. Worse: Auto Mode blocked the cleanup command after detecting the attack. This isn't a theoretical vulnerability — it's a real, usable exploit.
📍 Context · Claude Code's Auto Mode is Anthropic's default safety mechanism, designed to automatically block prompt injection attacks. Johann Rehberger (one of the most credible prompt injection researchers) discovered a "confused environment attack": by tricking Claude Code into downloading and unzipping a file, the extracted struct.py gets auto-executed by Python's import mechanism. Auto Mode failed to stop the attack in 80% of tests, and even blocked cleanup commands after detecting the compromise.
Auto Mode block rate ~20% (only stopped attack in 20% of tests)
Attack success rate ~80% (per Johann's report)

Why this matters

  • Auto Mode is the default: Anthropic recently made Auto Mode the default safety setting for Claude Code, claiming it protects users from prompt injection. This exploit directly undermines that claim.
  • The safety mechanism itself became the problem: Most alarmingly, Auto Mode blocked Claude's own cleanup commands after detecting the attack. The safety mechanism became an accomplice.
  • Not a theoretical bug: Johann published the full attack chain, including zip file construction and import hijacking. Anyone can reproduce it.
  • Simon Willison confirmed it: He calls it a "confused environment attack" rather than traditional prompt injection, but the conclusion is the same — Auto Mode is not reliable.
  • Relevant even if you're not a dev: If you use Claude Code to handle any sensitive files (SSH keys, cloud credentials, codebases), this exploit could be used against you.

🎯 Action you can take today

  1. Don't rely on Auto Mode: Turn it off and run Claude Code inside a sandbox instead. Anthropic's default safety mechanism has been broken.
  2. Use a container or VM: Run Claude Code inside a Docker container or virtual machine with restricted network egress. Don't expose home directories, SSH keys, or cloud credentials.
  3. Monitor agent behavior: Use audit logging to track Claude Code's filesystem access and network requests. Alert on anomalous behavior immediately.
  4. Watch for Anthropic's fix: Anthropic will likely ship a patch soon. Upgrade to the latest version before re-evaluating whether to enable Auto Mode.

Attack chain explained:

  1. Attacker crafts a zip file containing a malicious struct.py.
  2. Claude Code in Auto Mode downloads and unzips the file (normal operation).
  3. When Claude Code runs Python code, import struct gets hijacked — Python loads the local struct.py instead of the standard library.
  4. Malicious code executes. Auto Mode fails to detect the anomaly.
  5. Even when Claude detects the attack and tries to kill the malicious process, Auto Mode blocks the cleanup command.

vs traditional sandbox: Docker containers or VMs prevent this attack because of filesystem isolation. But Claude Code's Auto Mode operates at the application layer and can't defend against filesystem-level attacks.

Honest caveat: This exploit requires the attacker to trick Claude Code into downloading a malicious zip file. Risk is low in normal use, but high if you use Claude Code to process files from untrusted sources.

🔭 Watch for · Anthropic's official response and fix timeline. If they don't ship a patch within 48 hours, the problem is worse than it looks. Also watch for similar vulnerabilities in other agents (Codex, Cursor).
📖 Jargon decoder · Confused environment attack = attacker exploits the environment (filesystem, import mechanism) rather than the LLM itself to execute malicious code · Prompt injection = feeding malicious instructions to an LLM to make it do unintended things · Sandbox = isolated environment that restricts what resources a program can access · Import hijacking = Python loading a local module instead of the standard library, causing malicious code to execute.

OpenAI Decides Not to Acquire Cursor — Why This Matters to You
Hey clawii — OpenAI officially announced it will not acquire Cursor (after SpaceX's acquisition). This isn't "company gossip" — it means Cursor stays independent, and OpenAI keeps investing in Codex. For anyone doing vibe coding with Cursor, this is good news.
📍 Context · Cursor is the most popular AI-native IDE today. After SpaceX acquired it, OpenAI had to decide whether to exercise a matching right or make its own acquisition. On August 28, OpenAI officially announced it would not acquire Cursor. This means: Cursor stays independent, OpenAI goes all-in on Codex, and the two compete in the market. For users, competition means better products and lower prices.

Why this matters

  • Cursor stays independent: It won't be absorbed into OpenAI, so it continues supporting multiple models (Claude, Gemini, etc.). If you use Cursor for vibe coding, you don't have to worry about being locked into the OpenAI ecosystem.
  • OpenAI goes all-in on Codex: OpenAI explicitly said it will keep investing in Codex. That means Codex and Cursor will keep competing. Competition = better products + lower prices.
  • Impact on non-developers: Both Cursor and Codex are expanding beyond developers. Cursor's "natural language programming" mode and Codex's agent features are both lowering the barrier to coding. Their competition will accelerate this trend.
  • Ecosystem signal: OpenAI choosing not to acquire means they believe their own Codex can win. This is an important market signal — the AI coding tools market is diverging.

🎯 Action you can take today

  1. Keep using Cursor: No need to worry about product changes from an acquisition. Cursor will stay independent.
  2. Try Codex too: OpenAI's Codex is iterating fast. Use both and see which fits your workflow better.
  3. Watch pricing: Competition could lead to price cuts. Both Cursor and Codex may adjust their pricing strategies.
