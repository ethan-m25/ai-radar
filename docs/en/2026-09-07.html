Engrim — A Universal, Local-First SQLite Memory Engine Built for AI CLIs (Show HN 42 Points)
Hey clawii, there's a Show HN project on HN today called Engrim — 42 points, 10 comments. It's a "universal, local-first SQLite memory engine" built specifically for AI CLI tools. In plain words: it gives your AI agent persistent, locally-stored memory — no cloud service, no complex config, just a SQLite database + a simple API. For vibe coding, this could be a genuinely useful tool.
📍 Context · AI CLI tools (Claude Code, Codex, Vibe, etc.) currently have a problem: every conversation is independent, no long-term memory. Engrim tries to solve this — it provides a local SQLite database where AI agents can read/write "memories" (key-value pairs + vector embeddings), all stored locally. The project is on GitHub, written in Go, with a REST API and CLI interface.

Why this is worth a look

  • Solves a real pain point: Every time you start a new task in Claude Code or Codex, it doesn't remember what it did before. Engrim provides a simple memory layer — you can have the agent store key info and read it back on the next launch.
  • Local-first, SQLite-based: No cloud service, no API key, data entirely on your own machine. SQLite means you can view and edit memories with any SQLite browser.
  • Practical value for vibe coding: You can have Claude Code store project context, decision records, and common commands in Engrim, then auto-load them on the next launch. That's far more reliable than manually writing a system prompt every time.
  • 42 points isn't high, but the project's thinking is clear: Show HN 42 points is a medium signal, but the problem is well-defined and the implementation is simple — worth a try.

🎯 What you can do today

  1. Check the GitHub project: github.com/timgordontg/engrim
  2. Install (Go environment): go install github.com/timgordontg/engrim@latest
  3. Start the service: engrim serve (default port 8080)
  4. Configure MCP or API calls in Claude Code or Codex so the agent can read/write memory.

How Engrim works: Run engrim serve and it starts a local HTTP service. AI agents can store and retrieve memories via REST API. Supports: key-value storage, vector embedding search (based on SQLite FTS5), tag classification. All data is stored in a SQLite file under ~/.engrim/.

vs existing options: Mem0 and MemGPT are more powerful but need Docker or cloud services. Engrim's advantage is minimalism — one binary + SQLite, running in 5 minutes. Downside: limited features (no auto-summarization, no memory priority management).

How hard to get started: With a Go environment, 5 minutes. Without Go, grab a binary from GitHub Releases. Configuring Claude Code or Codex to use it requires a bit of MCP config knowledge, but the README has examples.

Honest caveat: The project is very new (Show HN today), may have rough edges. 42 points isn't high, suggesting limited community interest. But the thinking is clear and the implementation is simple — worth a try.

🔭 Watch for · Whether the project gains more stars over the next week (currently 42 points; if it hits 200+, the community is endorsing it). Watch for Claude Code / Codex MCP integration tutorials. If Engrim gets integrated into mainstream agent frameworks, it becomes an important infrastructure piece.
📖 Jargon decoder · FTS5 = Full-Text Search 5 — SQLite's built-in full-text search engine, supports simple vector search · MCP = Model Context Protocol — the standard protocol for AI agents to talk to external tools · Key-value pair = the simplest data storage model, one key maps to one value.
