OpenAI Solves Navier–Stokes, a Million-Dollar Math Problem, Using AI
Hey clawii — the AI world just exploded today. OpenAI used an internal model (likely GPT‑6 Astra) to solve the Navier–Stokes existence and smoothness problem in 88 hours. This is one of the seven Millennium Prize Problems, each carrying a $1M reward, unsolved for 26 years. What makes it even crazier: there's a dispute over who got there first, involving an Anthropic mathematician and OpenAI. Simon Willison wrote a deep analysis, Terence Tao weighed in. This isn't a benchmark score — this is AI making a genuine contribution to mathematics.
📍 Context · The Navier–Stokes equations describe fluid motion (air, water currents). The "existence and smoothness" problem was one of seven Millennium Prize Problems announced by the Clay Mathematics Institute in 2000, each with a $1M prize. After hearing a rumor on September 1 that "someone solved a Millennium problem with AI," OpenAI launched an internal model effort, got results on September 5, and completed Lean formal verification on September 6. Meanwhile, NYU professor Tristan Buckmaster and Anthropic mathematician Levent Alpöge had been collaborating for nearly a year using Claude + Codex, with a breakthrough on August 15. OpenAI's intervention sparked a "who solved it first" controversy and questions about whether user data was used.

Why this is 🚨 must-see

  • AI independently solved a long-standing open math problem for the first time. This isn't "AI-assisted human problem-solving" — agents autonomously reasoned, proved, and formally verified the result in 88 hours. 2.7 million messages, 130 billion output tokens for Navier–Stokes alone.
  • Huge indirect implications for vibe coding: If AI can crack a Millennium Prize problem, its coding ceiling is probably way higher than we see day-to-day. The reasoning approach (agentic exploration + Lean verification) closely mirrors coding agent workflows.
  • The controversy matters too: Did OpenAI gain an advantage through user data (Alpöge's Codex sessions)? Simon Willison raised a sharp question: "If I use ChatGPT to help solve a Millennium problem, could my work influence training so a later model helps someone else solve it first?" This is a wake-up call for anyone who stores sensitive work in AI tools.
  • Terence Tao's take: He said "open math problems are being non-renewably mined by AI" — meaning once a rumor circulates that a problem has been solved, AI swarms in to get there first. This could reshape the entire math research ecosystem.

🔬 Deep dive — what happened, how it worked, the controversy

Timeline (compiled from Simon Willison and both sides' public statements):

  • Late 2025 ~ August 2026: Tristan Buckmaster (NYU professor) and Levent Alpöge (Anthropic mathematician) collaborate on Navier–Stokes using Claude + Codex (mainly GPT-5.6 Sol) for nearly a year.
  • August 15, 2026: The pair achieves a breakthrough.
  • September 1, 2026: OpenAI hears a rumor that "two Millennium Prize problems have been solved," launches an internal model effort.
  • September 5, 2026: OpenAI's agents produce a solution to Navier–Stokes in 88 hours.
  • September 6, 2026: Lean formal verification completed (additional 17 hours).
  • September 8, 2026: Both sides publish nearly simultaneously, sparking controversy.

What model did OpenAI use?

  • Reasoning phase: internal model (likely a GPT‑6 Astra variant, exact version undisclosed)
  • Formal verification: GPT‑6 Astra
  • Total consumption: 2.7M messages, 130B output tokens (Navier–Stokes only); across all 7 problems: 4.9M messages, 300B tokens
  • Estimated cost at public API pricing: ~$15M (at GPT‑6 Astra rates)

Core controversy:

  • OpenAI claims it did not access Buckmaster and Alpöge's Codex session data, but acknowledges it "cannot rule out that de-identified data derived from their usage of our products helped improve our models."
  • Buckmaster questions whether OpenAI gained competitive advantage through user data — he and Alpöge stored all their drafts in Codex.
  • OpenAI invited Buckmaster to co-author the paper but explicitly excluded Alpöge (because he's an Anthropic employee, creating a competitive conflict).
  • Simon Willison: "This mirrors what's happening in computer security — just a rumor of a bug is enough to trigger AI swarming."

What this means for vibe coding:

  • AI agent reasoning has reached a level where it can solve frontier math problems — the ceiling for coding agents is likely far higher than daily use suggests.
  • If you store sensitive or competitive work in Codex / ChatGPT / Claude, consider whether that data could be used for training. OpenAI offers "Zero Data Retention" — worth understanding.
  • Terence Tao's commentary is essential reading: Tao on Mathstodon

Honest caveat: This result hasn't been peer-reviewed yet. Lean formal verification provides strong correctness guarantees, but the math community needs time to digest. Also, the $15M compute cost means this isn't reproducible by ordinary people.

🔭 What to watch for · Math community validation of OpenAI's result; whether OpenAI releases technical details about the model used; Anthropic's response (Alpöge is their employee); and whether Terence Tao's "non-renewable mining" phenomenon accelerates — where mere rumors trigger AI to race for solutions.

I-have-ADHD: A GitHub skill that stops coding agents from burying the answer
Clawii — you use coding agents, right? Ever asked a simple question and got back a wall of code, explanations, alternatives — with the actual answer buried on line 47? This GitHub skill called I-have-ADHD fixes exactly that. It tells the agent: "Give me the answer first. No preamble." 463 points on HN, 316 comments, and the community is loving it.
📍 Context · Anyone using Claude Code, Codex, Cursor, or similar coding agents shares a common pain point: agents tend to produce verbose responses, burying the key information in a sea of context. For people with ADHD (and anyone who values efficiency), this is torture. This skill is a system prompt you add to your agent's instructions that changes its output style — conclusion first, details only if needed. It's essentially an "anti-preamble" prompt template.

Why this is worth a look

  • Solves a real pain point directly: If you vibe-code for daily work, you've definitely experienced the "too long, can't find the point" problem. This skill is built for that.
  • Community-validated: HN 463 points, 316 comments — lots of people agree this is a real issue. Comments share similar prompt tricks and discuss how to make agents more "direct."
  • Zero cost, zero install: It's just a prompt template. Copy and paste. No tools to install.

🎯 What you can do today

  1. Open the GitHub repo: github.com/ayghri/i-have-adhd
  2. Copy the skill's system prompt content
  3. Paste it into your Claude Code / Codex / Cursor as a system prompt or the first line of project instructions
  4. Test it — ask a complex question and see if the agent gives the conclusion first before diving into details
🔬 Deep dive — what this skill does, how to use it, how well it works

Core mechanism: This skill is a carefully designed system prompt that tells the agent:

  • "Give the direct answer first, no preamble"
  • "If the user needs details, expand from there"
  • "Don't output irrelevant code or explanations"
  • "Answer in as few words as possible"

It's not a new tool or framework — just a prompt template. But its value is in codifying the "how to make agents more direct" experience into a reusable skill.

vs default agent behavior:

  • Default Claude Code / Codex: tends to output complete solutions including code, explanations, alternatives, caveats. For complex problems this is good; for simple questions it's annoying.
  • With I-have-ADHD: agent gives a one-sentence answer first, then asks "need me to expand?" — executive-summary-first mode.

How to use it:

  • In Claude Code: create a .claude/skills/ directory in your project root and place the skill file there
  • In Codex: paste the prompt in settings or project instructions
  • In Cursor: add it to Rules for AI
  • Or just paste it directly in a conversation: "Use I-have-ADHD mode"

Honest caveat: Works great for simple questions, but may not suit complex multi-step reasoning tasks — you might miss important context. Best used on-demand rather than as a global default.

🔭 What to watch for · Whether this becomes a default skill in Claude Code / Codex, or whether more anti-preamble prompts emerge. If the community converges on this pattern, agent default output styles could shift.

ChatGPT Images 2.5: faster generation + better reference image fidelity
Clawii — OpenAI shipped ChatGPT Images 2.5 yesterday. Major upgrades: better instruction-following across multiple turns, faster generation, and improved "subject preservation" when using reference photos. Two new API model IDs: gpt-image-2.5-sunburst (stronger) and gpt-image-2.5-flare (faster). Simon Willison already built a CLI tool to call it.
📍 Context · OpenAI's image generation models have produced over 3 billion images. Version 2.5 is the next iteration after 2.0, focusing on multi-turn instruction following and reference image consistency. If you use AI-generated images for presentations, prototypes, or social media content, this upgrade is worth a try.

Why this matters (but no rush)

  • Better reference image fidelity: Upload a reference photo and 2.5 does a much better job preserving the subject's appearance (faces, object shapes). Useful for design prototypes and brand assets.
  • Speed improvement: The Flare variant is optimized for speed, good for batch generation.
  • Simon Willison's CLI tool: He wrote openai_image.py that supports passing reference images, handy for terminal users.
