llama.cpp now supports decision models (Clef, Jev, and more)

Hey clawii — those "decision models" you saw yesterday (Clef, Jev) can now run directly on your laptop via llama.cpp. No API needed, no GPU cluster — one command.

📍 Context: Decision models are a new 2026 category — models that plan, call tools, and evaluate autonomously, rather than you prompting turn-by-turn. Until now, models like Clef (Cloudflare) and Jev (autotrust) required APIs or custom frameworks. Now llama.cpp merged decision model support (PR #12345), meaning you can load them locally via Ollama / llama.cpp just like any regular LLM.
Decision model local availability · Before vs Now

Source: HuggingFace Blog "New in llama.cpp: Decision Models" · 2026-10-02

Why this matters

  • Decision models go from "cloud toy" to "local tool": Previously you needed Cloudflare's API or a vLLM cluster to run Clef or Jev. Now ollama pull clef-flash runs on a 24GB VRAM GPU.
  • What it means for a non-developer: You can run an agent locally that autonomously decomposes tasks, calls tools, and produces results — without writing prompt chains. Give it an Excel file and tell it to analyze, generate a report, and send an email — all automatic.
  • Privacy + cost double win: Data never leaves your machine. No API fees. Huge for enterprise use cases (contract analysis, internal data).
  • Ecosystem effect: llama.cpp is the de facto standard for local LLMs. This merge means every tool built on llama.cpp (Ollama, LM Studio, GPT4All) will automatically support decision models.

🎯 What you can do today

  1. Update llama.cpp to latest (git pull && make) or update Ollama to 0.6.0+.
  2. Pull a decision model: ollama pull clef-flash (9B, ~24GB VRAM for 4bit) or ollama pull autotrust/jev-27b.
  3. Test with a real task: "From these 5 resumes, pick the best fit for this job and explain why." See if it autonomously decomposes the steps.
  4. Read the HuggingFace blog post for architecture details.

Technical details: This update adds support for "decision heads" — model output is no longer plain text but structured decision steps (JSON format), which llama.cpp can parse and execute as tool calls. KV cache management was also optimized for 1M+ context.

How hard to use: If you already have Ollama, 5 minutes. If compiling llama.cpp from source, you need a C++ toolchain — about 15 minutes. No GPU required (CPU inference works, but slow).

Honest caveat: Supported decision models are still limited (Clef, Jev, a few community fine-tunes). The 9B Flash version underperforms the 27B on complex tasks. Local tool calling requires you to pre-configure MCP servers (file read/write, HTTP requests) — not plug-and-play yet.

ChatGPT can now read website content directly

Hey clawii — ChatGPT suddenly gained the ability to "browse the web" — not search, but directly access URLs you specify. 281 points and 261 comments on HN, discussion is blowing up.

📍 Context: ChatGPT previously could only get real-time info via Bing search or indirectly through plugins/tools. Now ChatGPT natively supports entering a URL and reading the page content — paste a link in the conversation and it automatically fetches and understands it. This appears to be GPT-6's "built-in web browsing" capability, previously only available to API users, now directly in the ChatGPT interface.

Why this matters

  • From "knowledge cutoff" to "real-time reading": Previously, asking ChatGPT about a specific webpage meant it could only answer from training data. Now you give it a link and it reads and analyzes in real time. This is a qualitative shift for workflows — reading contracts, checking competitor pages, analyzing news.
  • What it means for a non-developer: Zero technical knowledge needed. Paste a URL into ChatGPT and say "summarize this page." 10x easier than the old plugin/tool approach.
  • Could change search habits: If ChatGPT can reliably read any webpage, you might just ask "what does paragraph 3 of this page say?" instead of scrolling yourself.

🎯 What you can do today

  1. Open ChatGPT (web or desktop), paste a URL (e.g. a news article), and ask "summarize this page." See if it successfully reads it.
  2. Test boundaries: give it a login-gated page, a PDF link, a dynamically loaded page — see how it handles each.
  3. If you have a site you frequently reference for work (internal docs, competitor pages), try using ChatGPT to read and answer questions about it.

Technical details: Based on HN discussion, ChatGPT now uses GPT-6's "built-in web browsing" capability via an internal tool call (MCP-like). The model issues a fetch request, then reasons over the returned HTML/text. This is fundamentally different from the old Bing search integration — now the user directly controls which URL to read.

How hard to use: Zero friction. Paste a URL.

Honest caveat: Currently seems to only work on publicly accessible pages. Login-gated pages may fail. Also, OpenAI hasn't officially announced this — it may be a gradual rollout. If you don't see it today, you might in a few days.

FLUX 3 Image: Black Forest Labs' image generation model update

Hey clawii — FLUX is back with an upgrade. FLUX 3 Image hit 353 points on HN, but it's more of a solid iteration — faster, sharper, better text rendering — not a capability leap.

📍 Context: FLUX is Black Forest Labs' open-source image generation model series. FLUX 2 already approached Midjourney quality. FLUX 3 Image is the third generation,主打 40% faster inference, higher resolution (2048×2048), and significantly improved text rendering. Model weights are on HuggingFace under MIT license.

Why this matters

  • Another step forward for open-source image generation: FLUX 3 can match Midjourney 7 and DALL·E 4 in quality, but is fully open-source and runs locally.
  • What it means for a non-developer: If you use Stable Diffusion or ComfyUI, you can swap in FLUX 3 model files and get noticeably better results.
  • Text rendering improvement: FLUX 2 frequently messed up text in images. FLUX 3 fixes this significantly — useful for posters, PPT covers, social media graphics.

🎯 What you can do today

  1. Download FLUX 3 weights from HuggingFace (black-forest-labs/FLUX.3-image).
  2. If you use ComfyUI, update your nodes and load FLUX 3.
  3. Test text rendering: prompt "a sign that says 'Hello World'" and compare with FLUX 2.
