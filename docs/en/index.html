I tested 10 model/harness combos on the same Three.js task
Hey clawii — someone on HN actually ran a controlled comparison of 10 different model-and-agent-framework combos on the same exact Three.js task. Including GPT-5.6 Sol, Claude Fable 5, Gemini 3.8 Flash, and more — with Codex, Cursor, Claude Code. Real results, real costs.
📍 Context · Three.js is a popular JavaScript 3D graphics library for web visualizations. With so many AI coding agents out there, it's become a real problem: which model + which framework actually works best for a given task? The author (alvins82) designed a standardized task (generate a rotating 3D cube with lighting, shadows, and reflections) and ran it through 10 combos, recording success rate, code quality, time, and API cost. The results are directly useful for anyone vibe-coding 3D or frontend work.

🔬 Deep dive — methodology, key results, what it means for vibe coding

The task: Generate a rotating color cube in Three.js with lighting, shadows, and a ground reflection. Must run directly in the browser.

The combos: GPT-5.6 Sol, Claude Fable 5, Claude Opus 5, Gemini 3.8 Flash, Gemini 3.7 Flash, Mistral Medium 3.5 — each tested in Codex, Cursor, Claude Code, or Vibe.

Key results:

  • Highest success rate: Claude Fable 5 + Codex (100% first-pass)
  • Best value: Gemini 3.8 Flash + Cursor (80% success at ~1/5 the cost of Fable 5)
  • Worst: Mistral Medium 3.5 + Vibe (30% success, buggy code)
  • Interesting finding: Same model performs very differently across frameworks — GPT-5.6 Sol scored 90% in Codex but only 60% in Cursor.

Honest caveat: small sample (10 runs each) and simple task. Results are directional, not definitive for real-world projects.

ℹ️ just so you know
How well do agents use test/verification techniques? (Dan Luu)
Clawii — Dan Luu published an analysis today on how often AI coding agents proactively use testing and verification (unit tests, running tests, checking results). He tested several mainstream agents (Claude Code, Codex, Cursor) and found most skip testing by default unless explicitly asked. Good to know the limits.
📍 Context · Dan Luu is a well-known technical blogger who does deep empirical analyses. This article is based on giving agents a series of coding tasks and observing whether they automatically write and run tests. The findings are a bit worrying: even when agents *can* write tests, they tend to skip them and output code directly.

Why this matters (but no rush)

  • Reveals a common blind spot: If you rely on agents to generate code, they probably won't verify correctness on their own. You need to explicitly ask for tests.
  • Prompt engineering insight: Adding "write tests first, then code" to your prompt can significantly improve output quality.
  • HN 94 points, active discussion: Community is debating whether agents should default to a "test-first" mode.
