GLM-5.3 Full Weights Released (HN 708 pts)
Hey clawii — Z.ai just open-sourced the full GLM-5.3 (753B) and Flash (321B) weights. HN hit 708 points with 235 comments. The full model is too big to run locally, but the API is cheap, it's MIT licensed, and you can do whatever you want with it.
📍 Context · The GLM family is Z.ai (Zhipu)'s flagship model line. GLM-5.2 and GLM-5.3-Flash were released earlier, but GLM-5.3 full weights just landed on HuggingFace today under the MIT license. Specs: 753B total / 40B active parameters, 1M context window, multimodal. The Flash variant (321B / 18B active) is also available. This is another heavyweight entry from the Chinese open-model camp.
GLM-5.3 753B total / 40B active
GLM-5.3-Flash 321B total / 18B active
DeepSeek V4-Flash 304B total / 37B active
Qwen3.8-Flash-Next 125B total / 6B active

Why this matters

  • MIT license + full weights: You can freely download, fine-tune, and use commercially. No API lock-in.
  • Performance claims near Claude Opus 4.8: On coding benchmarks it claims parity, and the Artificial Analysis Intelligence Index scores it at 57 (Opus 4.8 is 59).
  • 1M context window: Whole books, entire codebases — no problem. Great for agents and long-document analysis.
  • HN 708 points is not noise: The community is voting with upvotes. This is a milestone.

🎯 Action you can take today

  1. Check the weights on HuggingFace: zai-org/GLM-5.3 and GLM-5.3-Flash.
  2. If you can't run 753B locally, start with the Flash variant (18B active — runs in 4-bit on 24GB VRAM).
  3. If you prefer API, check Z.ai's pricing — rumored to be excellent value.

Qwen3.8-Flash-Next: Qwen4 Architecture Preview Model Drops
Hey clawii — Alibaba just released Qwen3.8-Flash-Next, an architecture preview of Qwen4. 125B total / 6B active parameters. Simon Willison already tested it and says "worth paying attention to." HF trending #2.
📍 Context · The Qwen family is Alibaba's open-source model line. Qwen3.8-Flash-Next is a new member of the Qwen3.8 series built around low active parameters + high performance. 6B active means it runs on consumer GPUs (RTX 3090 handles 4-bit quantization easily), while performance approaches DeepSeek V4-Pro. It's a "teaser" for the Qwen4 architecture — multimodal MoE with architectural improvements.

Why this matters

  • 6B active = runs locally: This is a model you can actually run on your own machine. No cloud required.
  • Architecture preview: Qwen4's new MoE and attention optimizations may set the standard for the next generation of open models.
  • Simon Willison tested it personally: He ran quantized versions on a DGX Spark and generated images (pelicans riding bicycles). Positive experience.
  • Apache 2.0 license: Commercial-friendly, just as permissive as MIT.

🎯 Action you can take today

  1. Download the Unsloth quantized version: unsloth/Qwen3.8-Flash-Next-GGUF
  2. Run it locally with llama.cpp (or Ollama if already supported): llama-cli -m qwen3.8-flash-next-Q4_K_M.gguf -p "Hello"
  3. Read Simon Willison's review: simonwillison.net

vs Qwen3.8-27B: Flash-Next uses MoE to squeeze active params down to 6B, theoretically 4-5× faster while retaining similar quality. The trade-off: MoE is less batch-size-friendly, so single-request latency may be slightly higher.

How hard to use: 5 minutes. Download the GGUF, run with Ollama or llama.cpp. If you have 8GB+ VRAM, 4-bit quantization is more than enough.

Honest caveat: Simon said he's "still exploring" — the model may have rough edges. Early users reported KV cache BF16 issues (already fixed). And 6B active params won't match 40B-active GLM-5.3 on complex reasoning. But for daily coding and Q&A, it's more than enough.
