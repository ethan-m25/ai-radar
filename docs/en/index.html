Claude Opus 5.5 and GPT-6 Sol/Luna Launch — AI Price War Is Official

Anthropic and OpenAI dropped new models almost simultaneously, with performance near flagship level but prices significantly lower. Your vibe coding costs could literally be cut in half.

📍 Context · Over the past three weeks, Anthropic released Fable 5.1 (Sep 1) and Mythos 5.1, while OpenAI launched GPT-6 Astra (Sep 3). Now both strike again: Anthropic released Opus 5.5, performing near Fable 5.1 level but 40% cheaper; OpenAI released GPT-6 Sol (speed-optimized) and GPT-6 Luna (cost-optimized). Simon Willison calls it a "price war" — a major win for developers.

Why This Matters

  • Direct savings: Opus 5.5 is 40% cheaper than Opus 5 with nearly identical performance. If you're on Opus 5, you can switch seamlessly.
  • More choices: GPT-6 Sol works best for low-latency scenarios (real-time chat), Luna for batch tasks. You can pick the right model per use case instead of being locked into a single pricing tier.
  • For your vibe coding: When using Claude Code or Codex, try switching to these new models — lower cost, faster speed, more enjoyable iteration.
🎯 What You Can Do Today
  1. In Claude Code, set model: claude-opus-5.5 and run your usual workflow to feel the performance and cost difference.
  2. In the OpenAI API, test gpt-6-sol and gpt-6-luna against Astra on latency and price.
  3. Subscribe to Simon Willison's blog — he's doing detailed benchmarks with real numbers.

This time Claude didn't just answer questions — it actively analyzed massive genomic datasets, identified an enzyme system never recorded before, and it contains CRISPR-like repeats — potentially opening the door to new gene-editing tools.

Why This Matters

  • What it means for you: When you use Claude Code for complex tasks, the underlying model may be more reliable and deeper than you realize.

👀 Worth A Look

Jev — System One / Decision Models: A New Model Category Is Born

TypeSafe AI released Jev, a model that doesn't output text — it outputs floating-point numbers. Simon Willison calls it a "decision model," and it may change how we use AI for classification, routing, and scoring tasks.

📍 Context · Traditional LLMs output natural language that you then need to parse. Jev outputs numbers directly (classifications, ratings, confidence scores) — like putting a dashboard on AI. It draws from Daniel Kahneman's "System One / System Two" theory: Jev is the fast, intuitive decision system, suited for classification, routing, moderation, and scoring.

Why This Matters

  • New paradigm: No more prompt engineering to make LLMs output JSON. Jev natively outputs structured numbers — more reliable, more efficient.
  • Potential use for you: Automatically classify resumes (match or not), score email priority, rate documents. No complex prompts needed.
  • Could replace some LLM calls: For tasks that only need a "yes/no" or "1-5 score," Jev is cheaper and more deterministic than an LLM.
🎯 What You Can Do Today
  1. Read Simon Willison's blog and Jev's official docs to understand the API design.
  2. If the API is available, try Jev on a simple classification task (e.g., "is this text work-related?").
  3. Watch for open-source implementations or alternatives in the coming weeks.

Honest caveat: Only one company is doing this so far; the ecosystem hasn't been built. If TypeSafe AI gets acquired or shuts down, your integration breaks. Wait 1-2 weeks to see if open-source alternatives emerge.
