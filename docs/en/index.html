qm – Multiplayer agent harness for work — HN 583 points, YAML-based, non-devs welcome

Hey clawii — a project called qm hit HN today with 583 points and 119 comments, ranking #6 for 17 hours. It's a multiplayer agent harness — a framework for multiple AI agents to collaborate like a team. The killer feature: it uses YAML config (nginx-like), not Python code. If you use ChatGPT or Claude for multi-step workflows (research → write → review), qm might let you automate that without writing a single line of code.

📍 Context · Most agent frameworks (LangChain, CrewAI, AutoGen) are built for developers — you write Python classes, understand OOP, and debug stack traces. qm goes the opposite direction: YAML-based workflow descriptions, real-time multiplayer agent collaboration, each agent has a role and tools. It's like "AI team" but you don't need to be a programmer to set it up. GitHub yc-software/qm, HN front page #6, 583 points.

Why this matters

  • Non-developers can use it — configuration is YAML + nginx-like syntax, no code required. You write `roles:` with "researcher" "writer" "reviewer" and it runs.
  • Real-time multiplayer — not a single-process agent, multiple agents chat like a Slack channel. One agent reads files, another summarizes, a third writes the report.
  • HN 583 points / 17 hours — massive community heat, not a small side project.
  • Impact on your workflow — if you use ChatGPT or Claude for multi-step tasks (research + writing + PPT), qm can automate the pipeline without you writing Python.
🎯 What you can do today
  1. Open the GitHub repo: github.com/yc-software/qm — read the README examples.
  2. Read the HN discussion: HN qm — 583 points, 119 comments.
  3. If it offers pip install or a Docker image, try running a 3-agent workflow (researcher → writer → reviewer).
  4. Compare with your current ChatGPT/Claude usage — which manual switching steps could qm replace?

Run Kimi K3 using 29 GB of RAM — local 2.8T model, HN 258 points

Hey clawii — a hot topic yesterday: squeezing Kimi K3 — that 2.8T parameter monster — into 29GB of RAM. Speed is only 0.5 tokens/second, but it runs on your MacBook. HN 258 points, 108 comments. The local inference community is excited.

📍 Context · Kimi K3 is Moonshot's 2.8T parameter MoE model (104B active parameters). Normal deployment needs at least 8× MI355X GPUs (hundreds of thousands of RMB). The sqliteai team used GGUF quantization + optimized inference code to squeeze it into 29GB RAM (~1/4 the model size), letting ordinary developers run it on a MacBook — though at 0.5 tokens/second. It's a bold local inference experiment, but practical utility is limited.

Why this matters

  • Running a 2.8T parameter model locally — previously impossible. 0.5 tok/s is slow, but proves "models can run on personal devices" is becoming real.
  • HN 258 points + 108 comments — active community discussion, local inference is a hot topic.
  • Relevance for you — if you vibe-code with unstable internet or want offline capability, this kind of local deployment could become a backup option. But 0.5 tok/s isn't practical yet.
  • Tech trend — quantization, pruning, distillation are making big models smaller. This demo shows the direction.
🎯 What you can do today
  1. Check the GitHub repo: github.com/sqliteai/kimi-k3-29gb
  2. Read the HN discussion: HN Kimi K3 29GB — 258 points.
  3. If you have a 32GB+ MacBook, try running it yourself — but be prepared: 0.5 tok/s is really slow.
  4. Watch unsloth's Kimi K3 GGUF version (already 41.3k downloads) — a faster version may come.

🔭 What to watch for · Trigger event: if unsloth or llama.cpp releases an optimized Kimi K3 quantized version with speed >5 tok/s, that becomes practical. Also watch for Apple Silicon optimized versions (using NPU acceleration).
Jargon decoder · GGUF = a model quantization format popularized by llama.cpp, runs on CPU. Quantization = compressing model parameters from 16-bit floats to 4-bit or less, reducing memory usage at the cost of some precision. MoE = Mixture of Experts — not all parameters are active at once, only a few "experts" are triggered.
