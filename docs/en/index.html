Anthropic Claude Opus 5.5 — Matches Fable 5.1 Performance, 40% Cheaper

Hey clawii — Anthropic dropped Opus 5.5 yesterday and it performs about as well as their most expensive model Fable 5.1, but costs 40% less. This isn't a technical leap — it's a pricing signal. The LLM price war has officially begun.

📍 Context: Anthropic currently runs three product lines: Mythos (cheapest), Fable (strongest, optimized for coding and science), and Opus (balanced). Fable 5.1 launched September 1. Now Opus 5.5 absorbs most of Fable's capability at a much lower price. This is Anthropic's aggressive move to compete on price — rather than letting you switch to cheaper OpenAI models, they're cutting their own prices.

Why This Matters

  • Performance matches the flagship: Opus 5.5 hits Fable 5.1 levels on most tasks — especially coding, reasoning, and writing. You don't need to pay Fable prices to get near-Fable capability.
  • 40% price cut: $15/MTok input, $60/MTok output vs Fable's $25/$100. Real savings for enterprise users and vibe coders alike.
  • Cache pricing also slashed: $3.75/MTok cached read vs Fable's $6.25. If your prompts have long repeated prefixes, effective cost drops even more.
  • The signal: Anthropic is proactively cutting prices. Competition is white-hot. OpenAI likely counters next.

🎯 What You Can Do Today

  1. If you use Claude Code or the API, change your model from claude-fable-5-1 to claude-opus-5-5. In Claude Code: run /model and select Opus 5.5.
  2. Run a side-by-side test: same task on both models, see if the quality difference is acceptable for your use case.
  3. If you're running OpenAI's GPT-6 Sol/Luna, consider Opus 5.5 as a backup for cost-critical automations.

OpenAI GPT-6 Sol and Luna — Flagship Splits Into "High IQ" and "High EQ" Lines

Check this out — OpenAI released GPT-6 Sol (high-IQ / STEM) and GPT-6 Luna (creative / dialogue / higher safety) on the same day as Anthropic's Opus 5.5. This isn't just a model launch — it's a product strategy fork. From now on, you use Sol for coding and Luna for emails.

📍 Context: GPT-6 Astra was the general-purpose flagship released in September, the first model to reach "Critical" cybersecurity preparedness level. Now Sol and Luna are differentiated offshoots of Astra: Sol targets STEM/code/math with aggressive capability but looser guardrails; Luna targets creative writing/dialogue/safety with a softer touch. OpenAI also shipped improved prompt caching alongside, making repeated prompt prefixes faster and cheaper.

Why This Matters

  • Product differentiation signal: No longer "one model does everything." Sol for STEM, Luna for humanities. Pick the model based on your task.
  • Sol breaks Enigma cipher: OpenAI demonstrated GPT-6 Astra cracking a 2005 Enigma message that had resisted solution for 21 years (670 HN points). This proves Sol/Astra has real cryptographic and reasoning advances.
  • For vibe coding users: Use Sol for code, Luna for writing reports/emails/creative content. The distinction is actually useful in practice.
  • Better prompt caching: OpenAI announced improved caching for repeated prompt prefixes. If you use fixed system prompts, you can save 30-50% on costs.

🎯 What You Can Do Today

  1. Specify the model in your API calls: use gpt-6-sol for coding tasks, gpt-6-luna for writing/dialogue.
  2. Take advantage of the new prompt caching — if your system prompt is long with repeated prefixes, enable caching to dramatically reduce costs.
  3. Run a head-to-head test: Sol vs Opus 5.5 and see which one codes better for your workflow. The price war means you have leverage.

Honest caveat: The performance gap between Sol and Luna isn't huge yet. The differentiation is more about product positioning than technical breakthrough. But the trend is clear: models will keep fragmenting into specialized variants.

Jev Establishes "Decision Model" Category — Simon Willison Deep Dive Ignites Community

Hey clawii — Jev, the "System One model," got a 983-word deep-dive from Simon Willison yesterday, and the community is starting to take it seriously. This isn't another chatbot — it's a model purpose-built for judgment, classification, and scoring. It outputs floating-point numbers instead of text.

📍 Context: Jev was unveiled by TypeSafe AI last week as a new category — System One models (aka decision models). Instead of generating text, it takes text input and outputs scores, classifications, and confidence values directly. Yesterday Simon Willison published a detailed review (983 words), and HN has three concurrent discussions: #1 "Jev in 25 Lines of Python" (204 pts), #26 "OpenAI is well positioned to fast-follow Jev" (296 pts), and #27 "JevBench" (111 pts). Signal has escalated from "weak" to "worth watching."

Why This Matters

  • New category gets legitimized: Simon Willison's review is effectively industry recognition. Jev is not a traditional LLM — it's a "decision engine" that takes natural language and outputs structured numbers instead of text.
  • OpenAI potentially following: HN discussion "OpenAI is well positioned to fast-follow Jev" (296 points) suggests the big players are watching this space. If OpenAI ships a similar product, the category is confirmed.
  • JevBench launches: The community has already created JevBench, a reproducible benchmark for decision models. An ecosystem is forming around a 2-week-old product.
  • What this means for you: Future "judgment models" could handle moderation, classification, and scoring tasks more cheaply and reliably than general-purpose LLMs — directly useful for HR tasks like resume screening or survey analysis.

🎯 What You Can Do Today

  1. Read Simon Willison's review: simonwillison.net/2026/Sep/21/jev/
  2. Visit TypeSafe AI's website to read the Jev API docs and understand the pricing.
  3. Think about whether you have any "yes/no" or "rating" tasks at work (resume scoring, email classification, sentiment analysis) where Jev could replace a general-purpose LLM call — cheaper and faster.

What it runs on: Based on Transformer architecture but with a regression output head instead of a classification head. Currently API-only, no open-source weights available.

How hard to set up: Just call the API, but you need to understand Jev's structured output format. Documentation is still early — expect some trial and error.

Honest caveat: This is a very early proof of concept. Only one model (Jev) exists, the ecosystem is essentially zero, and pricing isn't fully public yet. Could be a flash in the pan, but the signal is now worth monitoring. The Simon Willison endorsement is the strongest validation so far.

⚠️ Note: Not open-source — API-only. Pricing not yet public. Community has created JevBench for reproducible comparisons. Watch for fast-follow from OpenAI.
🔭 Next thing to watch: If more KOLs review it in the coming week, or if OpenAI/Google ships a similar decision-model product, this direction is confirmed and the category becomes real. Also watch for Jev pricing to go public.
Jargon decoder:
System One = Borrowed from Kahneman's "System 1" thinking (fast, intuitive, automatic) — here it refers to a fast decision model that outputs judgments rather than generating text.
Regression head = The model's output layer is modified to predict continuous values (like a score from 0 to 1) instead of classification probabilities.
JevBench = Community-created benchmark for evaluating decision models on classification and scoring tasks.
