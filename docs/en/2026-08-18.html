🚨 Qwen3.8-27B: Simon Willison publishes deep review — model scores 52, tying GPT-5.6 Luna

Model · Open-source · Deep-dive
📍 Context

Qwen3.8-27B hit #1 on HN on Aug 14 (1216 points), climbed to 1387 on Aug 16. Today (Aug 18) Simon Willison published a 2,543-word deep review calling the model "truly astonishing." He ran it on an M5 MacBook Pro and an NVIDIA DGX Spark using his own Tool CORS Chat utility. The model scores 52 on the Artificial Analysis Intelligence Index — identical to GPT-5.6 Luna (max), and just one point behind GLM-5.2 (max) and DeepSeek V4 Pro 0813 (max). Those models are 753B and 1.7T parameters respectively. This is a 27B model.

Why this matters
  • Simon Willison's authoritative review: He built CORS Chat to test Qwen3.8-27B in LM Studio on both an M5 MacBook Pro and an NVIDIA DGX Spark. SVG image generation quality far exceeded expectations, with progressive rendering (draws as tokens stream). This is the first time he's seen "almost as good as GPT-5.6 Luna" multimodal output from a local model.
  • Performance-to-parameter ratio is insane: A 27B model on a consumer GPU hits 80-85% of frontier models on Chinese code generation, math reasoning, and document understanding. The community is shifting from "wow, Alibaba open-sourced something good" to "how is this even possible?"
  • Ecosystem is all in: Hugging Face model card: 666k downloads, 10.9k stars. unsloth GGUF version: 3.56M downloads, 1.73k stars. LM Studio, Ollama, vLLM, llama.cpp all support it natively. 5 minutes to first chat.
  • Apache 2.0 license: Commercially safe for now, but the community still worries about Alibaba's history of "open-source bait-and-switch" — changing license terms after market adoption.
🎯 Action
  1. Download it now: Get unsloth's GGUF version (~16GB 4-bit quantized), load it in LM Studio. If you're still using Qwen3.8-Max (2.4T params), switch to 27B — it runs locally and performs close.
  2. Test Chinese multimodal: Feed it screenshots, PDFs, charts. For Chinese users, this is the best local multimodal model available right now.
  3. Watch the license: Qwen uses Apache 2.0 this time, which is safer for commercial use. But keep test results documented in case you need to migrate later.
  4. Try Simon's CORS Chat: If you're running models in LM Studio, try his tool — it provides an OpenAI-Responses-compatible web UI with progressive SVG rendering.
🔬 Deep dive

vs Qwen3.8-Max (2.4T params): In Simon's review, the 27B version hits 80-85% of Max on Chinese doc summarization, code review, and image description. Max needs 8×MI355X GPUs (six-figure USD). 27B needs a single RTX 4090 (under $2,000). For individuals, 27B is the obvious choice.

Tech details: 28B params, Image-Text-to-Text architecture, 128K context. 4-bit quantized ~16GB, fits in 24GB VRAM consumer GPUs. FP8 version ~28GB, needs 32GB VRAM. GGUF supports CPU+GPU hybrid inference — M5 MacBook Pro works.

Setup effort: 5 minutes. Download LM Studio, search "Qwen3.8-27B", load unsloth's GGUF version, start chatting. Agent scenarios need Ollama + plugins (~1-2 hours).

Simon's CORS Chat tool: A simple web UI compatible with OpenAI Responses endpoints. Runs directly on LM Studio or connects to OpenRouter. Supports progressive SVG rendering — draws as tokens stream.

Honest caveat: Apache 2.0 license this time is good, but Alibaba has a history of changing license terms mid-stream (early Qwen versions). The community panic isn't entirely unfounded.

👀 Watch for
  • Will Alibaba release smaller variants (7B, 14B) to cover more devices?
  • Will the community produce fine-tuned versions (Chinese legal, finance, medical)?
  • License question — if Alibaba changes terms, can the community quickly switch to alternatives?
📖 Jargon decoder: GGUF — model file format designed for llama.cpp, supports quantization, de facto standard for local deployment.
Quantization — compressing model parameters from high precision (e.g. 16-bit float) to lower precision (e.g. 4-bit integer) to reduce size and speed up inference, usually with minimal accuracy loss.
Artificial Analysis Intelligence Index — a composite model performance scoring system aggregating multiple benchmarks; higher scores indicate stronger capability.

👀 GPT-5.6 Sol price cut 50%: OpenRouter announces, HN 471 points, 293 comments

Pricing · API · Cost optimization
📍 Context

OpenRouter announced a 50% price cut for GPT-5.6 Sol today, hitting HN with 471 points and 293 comments. Sol is OpenAI's latest fast-inference tier, offering 2.5× lower latency than standard Sol at double the price. This is the first major price reduction for Sol since its launch. The move follows OpenAI's broader pricing strategy — Luna was cut 80% and Terra 20% on July 30. API pricing wars are intensifying across the industry.

Why this matters
  • First major Sol price drop: GPT-5.6 Sol is OpenAI's fast-inference tier. A 50% cut brings its cost close to standard Sol, but with significantly lower latency. For developers using the OpenAI API, this is a clear cost win.
  • HN community is paying attention: 471 points, 293 comments. Discussion centers on "does this mean demand is weak," "is OpenAI in a price war," and "Sol vs Luna value comparison."
  • Impact on clawii: If you use GPT-5.6 Sol via OpenRouter or the OpenAI API, your costs just halved. If you use Claude Code or codex, you're not directly affected, but the price war may push other vendors to follow.
  • Price war continues: OpenAI cut Luna 80% and Terra 20% on July 30. Now Sol. DeepSeek, Google, and others are also cutting prices. API costs are dropping fast — good news for all AI users.
🎯 Action
  1. Check your API usage: If you use GPT-5.6 Sol via OpenRouter, confirm the price cut has taken effect. If using the OpenAI API directly, check for new pricing tiers.
  2. Consider migrating to Sol: If you avoided Sol due to cost, re-evaluate now. Sol offers 2.5× lower latency than standard models — great for real-time applications.
  3. Watch for competitors following suit: DeepSeek, Google, and others may match the cut. Stay alert and pick the best value model.
  4. Test Sol quality post-cut: Run your actual workloads through Sol to verify output quality hasn't changed with the price reduction.
🔬 Deep dive

vs standard GPT-5.6 Sol: Standard Sol pricing was $X/1M tokens; after 50% cut it's $X/2M tokens. The Sol Fast tier (even faster) costs 2× standard Sol but delivers 2.5× lower latency. This cut brings Sol pricing close to Luna, but with better speed.

OpenRouter vs OpenAI official: OpenRouter is a third-party API aggregator. The cut could be OpenRouter's own promotion or a pass-through of an official OpenAI price reduction. Check whether OpenAI has officially announced matching cuts.

Real impact: For developers using the OpenAI API, costs are halved. For OpenRouter users, same benefit. If you use Claude or other models, no direct impact — but the price war may eventually benefit everyone.

Honest caveat: Price cuts may signal weaker demand or competitive pressure. Long-term, lower prices are good. But watch for OpenAI balancing this by restricting free tiers or raising prices on other models.

👀 DeepSeek V4 Pro 0813 weights released: 1.7T params, Simon Willison finds dramatic image differences across reasoning effort levels

Model · Open-source · Weights release
📍 Context

DeepSeek V4 Pro 0813 is DeepSeek's latest Pro model — 1.7T parameters (893 GB). It went live via API on Aug 12, and today (Aug 18) the weights were officially released on Hugging Face. Simon Willison first reviewed it on Aug 12 and updated today with the weights release. He tested image generation at different reasoning effort levels (low, medium, high) and found dramatically different outputs — the first time he's seen such variation within a single model. It scores 53 on the Artificial Analysis Intelligence Index, one point above Qwen3.8-27B's 52.

Why this matters
  • Weights officially released: DeepSeek V4 Pro 0813 weights are now on Hugging Face (1.7T params, 893 GB), following DeepSeek-V4-Flash as another major open-source release from DeepSeek.
  • Simon Willison's discovery: Different reasoning effort levels produce dramatically different image outputs. Low effort generates a simple pelican, medium adds background detail, high produces a very complex composition. This suggests deep reasoning chain tuning in the model.
  • Frontier-competitive performance: Score of 53 ties GLM-5.2 (max) and DeepSeek V4 Pro 0813 (max), but at enormous parameter count. For enterprises with GPU clusters, this is a competitive option.
  • Open ecosystem: Weights are released, so the community can fine-tune and deploy. But 1.7T params requires serious hardware — not for individual users.
🎯 Action
  1. Understand the model's capabilities: If you have enterprise GPU resources, download the weights for testing. Note: requires 893 GB storage and at least 8×A100 or equivalent GPUs.
  2. Try via API: If you don't want to self-host, use OpenRouter or DeepSeek's official API. Pricing is relatively cheap ($0.435/M input tokens).
  3. Watch reasoning effort differences: If you use DeepSeek V4 Pro, tune the reasoning effort parameter for best results. Simon's tests show high effort produces more complex outputs but at higher cost.
  4. Compare with Qwen3.8-27B: For individuals, Qwen3.8-27B is far more practical (27B vs 1.7T). But if you need maximum performance, DeepSeek V4 Pro 0813 is worth evaluating.
🔬 Deep dive

vs DeepSeek-V4-Flash (284B total / 13B active): V4 Pro 0813 is the larger sibling (1.7T total params), stronger but far more resource-hungry. Flash is better for individuals; Pro is for enterprises.

Tech details: 1.7T params, 893 GB weight files. MoE architecture (active parameter count unknown). Supports 128K context. Requires serious GPU clusters to run.

Setup difficulty: High. Nearly impossible for individuals to self-host. Use the API instead.

Simon's test: He used OpenRouter to test image generation at different reasoning effort levels. Low effort → simple pelican. Medium → pelican with background. High → very detailed composition. First time he's seen such dramatic variation within one model.

Honest caveat: 1.7T params is impractical for individuals. DeepSeek's API is cheap but may not match OpenAI or Anthropic on reliability and consistency.

👀 Watch for
  • Will the community release quantized versions (e.g. 4-bit) to lower the deployment barrier?
  • Will DeepSeek release smaller variants (e.g. 70B)?
  • Does the reasoning effort variation indicate unique reasoning chain architecture?
📖 Jargon decoder: MoE — Mixture of Experts, model architecture that activates only a subset of parameters per token to balance performance and efficiency.
Reasoning Effort — a parameter controlling how many reasoning steps the model performs before generating output. Higher effort typically produces more detailed but slower results.
