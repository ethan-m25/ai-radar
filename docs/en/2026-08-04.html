Show HN: Run an 80B Qwen in 4.3 GB of RAM on a Mac, and a 35B on an iPhone

Hey clawii — there's a Show HN on the front page today claiming you can run an 80B-parameter Qwen model on a Mac using just 4.3 GB of RAM, and even a 35B model on an iPhone. 201 points and 88 comments means the community is paying attention. For someone who likes to run models locally for vibe coding, this could mean big models without the cloud API bill — if it's real.

📍 Context · Running large models locally has always been a holy grail, but 80B parameters typically needs 160 GB+ of VRAM. Quantization (GGUF, GPTQ, etc.) can compress models to 4-bit or even 3-bit, cutting memory drastically. This project claims to push quantization to an extreme — 80B in 4.3 GB is a compression ratio of ~18x, far beyond anything publicly demonstrated before. If it works, it means a MacBook Air could run frontier-class models locally.

Why this matters

  • 4.3 GB for an 80B model — If real, this is the most aggressive quantization scheme I've seen. A normal 4-bit 80B model needs ~40 GB. 4.3 GB implies 1-bit or extreme sparsity.
  • 35B on an iPhone — Running a 35B model on a phone, even slowly, is conceptually huge for on-device AI.
  • What it means for you — If you use a MacBook for vibe coding, running a big model locally means zero API costs and zero latency for simple tasks. Even if it's slow, it could handle code completion or light reasoning.
  • Community is digging in — 88 comments asking about implementation details, speed, and usability. The GitHub repo (leonickson1) is the place to watch.
