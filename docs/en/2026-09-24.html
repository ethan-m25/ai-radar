  • Claude discovered a new enzyme system — This isn't a benchmark score. It's a real scientific breakthrough. Claude analyzed massive metagenomic datasets and found an enzyme family nobody had noticed before. For AI in biology/medicine, this is a milestone signal.

Mercury 2.5 LLM — 770 Tokens Per Second Inference

Check this out — a model called Mercury 2.5 just hit 770 tokens per second, more than 10x faster than GPT-4. It's a small model, not a general-purpose giant, but for latency-sensitive tasks this speed means "real-time" is no longer a marketing claim.

📍 Context: Mercury 2.5 was posted to HN today (Sep 24) via Artificial Analysis. It achieves 770 tok/s inference, making it one of the fastest publicly measurable models available. The speed comes from aggressive model quantization and inference kernel optimization, not from model size.

Why This Matters

  • 770 tok/s in practice: In the time it takes you to type one character (~200ms), this model generates 150 tokens. For real-time translation, voice assistants, and code completion, latency becomes practically imperceptible.
  • Not a general-purpose model — Mercury 2.5 loses to GPT-6 and Claude Opus on reasoning/knowledge. Its advantage is speed, not intelligence.
  • Implications for vibe coding: If you use AI for code completion (Codex, Cursor, Copilot), speed is everything. Models like Mercury 2.5 could become the "dedicated engine" for code completion scenarios.

🎯 What You Can Do Today

  1. Visit Artificial Analysis to see Mercury 2.5's full benchmark breakdown — understand which tasks it's fast on and where it falls short.
  2. If you use Cursor or Codex, watch for them to integrate Mercury 2.5 as a speed option.
  3. Think about which parts of your workflow are latency-sensitive (real-time translation, speech-to-text, code completion) — those scenarios will get dedicated models soon.

How it works: Mercury 2.5 uses extreme model quantization (possibly 2-bit or 3-bit) and specialized inference kernels. It's not a "big model" — it's a speed-optimized specialist. Similar to Apple's on-device strategy: small, fast, good enough.

Honest caveat: 770 tok/s is impressive, but that's generation speed, not thinking speed. On complex reasoning tasks, a model 10x slower but smarter will outperform it. This isn't a GPT-6 replacement — it's a complement.
