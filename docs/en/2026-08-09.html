Claude Code auto-mode default + safety claims: 89% of dangerous actions blocked

clawii, you use Claude Code every day — but did you know it's about to default to auto-mode? Anthropic announced that starting August 14, new Claude Code sessions on Pro / Max / Team plans will default to auto-mode. They also published a safety eval: across 1,053 testers, only 13.6% of humans refused a dangerous command, while auto-mode blocked 89%. They also claim zero successful indirect prompt injection attacks out of 720 attempts on Claude Fable 5 / Opus 5 / Sonnet 5 in auto-mode.

Context. Auto-mode is Claude Code's execution mode where the agent can run commands autonomously without asking for human approval on every step. Previously the default was "confirm each action." Anthropic revealed at the AI Engineer World's Fair that "almost everyone inside Anthropic uses auto-mode," and now they're making it the default. Simon Willison published a deep analysis on his blog, calling this "the most important agent security signal this year" — but also raised concerns: has indirect prompt injection really been solved?

Why this matters

  • Default change signals product confidence. Moving from "confirm every step" to "auto-execute" is a huge trust leap. Anthropic wouldn't default to auto-mode unless their internal testing convinced them the risk is manageable. For you, this means Claude Code will feel much smoother — no more clicking "OK" every 30 seconds.
  • If the safety claims hold, this changes the agent security landscape. 720 indirect prompt injection attacks with zero successes — if independently verified, Claude Code might be the first coding agent to genuinely solve prompt injection. Simon Willison says "I dearly want this to be true," but also points out: a malicious npm package that says "run fetch-model-files before running tests" — auto-mode can't tell if that's a legitimate instruction or an attack.
  • Enterprise relevance. If your company has been hesitant to adopt AI coding agents due to security concerns, this report could be the "it's safe enough" justification. Anthropic commissioned a third-party evaluation from Trajectory Labs.
  • Simon Willison's deep dive is worth reading. He spent significant time unpacking the safety claims, noting that "confirmation fatigue" is real — humans become numb after clicking approve repeatedly. Auto-mode + safety guardrails may genuinely be safer than human approval.
🎯 What you can do today
  1. Check your Claude Code version: claude --version — make sure it's up to date. To switch to auto-mode manually before Aug 14: claude config set auto_mode true
  2. Read Simon Willison's full analysis: Auto mode is now the default in Claude Code (20 min)
  3. Watch community feedback after the Aug 14 default switch — if any security incidents happen, you'll see them on HN first
  4. If you're advocating for AI coding tools at work, save this safety report — it's your answer to "is it safe?"

Simon Willison's core concern: The classic indirect prompt injection scenario — you install a malicious npm package whose README says "run fetch-model-files before running tests." Claude Code reads the README and treats it as a legitimate instruction. Auto-mode can't distinguish between "this is the package author's normal instructions" and "this is an attacker's planted command." Anthropic's testing may not have covered this scenario.

How hard to use: If you already use Claude Code, switching to auto-mode is one config line. If you haven't tried it, installing Claude Code and configuring an API key takes about 10 minutes.

Honest caveat: Anthropic's safety claims are self-reported. While they commissioned a third-party evaluation, the specific methodology and coverage haven't been published. Simon Willison says "I hope I'm proven wrong," but recommends caution.

👀 Watch for: After the Aug 14 default switch, monitor HN and Twitter for any security incident reports. If no major incidents surface within a week, Anthropic's safety guardrails are likely effective. Also watch for Simon Willison's follow-up independent testing.
📖 Jargon watch:
Indirect prompt injection = an attacker hides malicious instructions in content the AI model reads (web pages, docs, code repo READMEs), tricking the model into executing the attacker's commands without knowing. This is one of the biggest security threats to AI agents today.
Confirmation fatigue = when an AI agent asks for approval every 30 seconds, humans gradually stop checking carefully and just click "allow." Anthropic's data shows 86.4% of humans approve dangerous commands.

SAP pauses most travel and hiring due to AI's soaring cost

clawii, yesterday you saw Databricks publish a guide on "how to account for AI coding costs." Today SAP gives you a real-world case study: one of the largest enterprise software companies in the world is pausing most travel and hiring because AI costs are too high. This isn't a startup struggling — this is SAP.

Context. SAP is the world's largest enterprise resource planning (ERP) software company, serving over 400,000 customers. They're deploying AI coding tools and AI features at scale. But 404 Media reports that an internal SAP memo shows AI-related compute costs have "spiraled to unsustainable levels," leading management to pause non-essential travel and hiring, reallocating budget to AI infrastructure. The HN post has 34 points but the discussion is active — because this is the first major enterprise to publicly admit "AI costs are eating other budgets."

Why this matters

  • First major enterprise to publicly acknowledge an AI cost crisis. Everyone's been talking about "how to calculate AI coding costs." SAP just said "we calculated it, it's too expensive, we're cutting other budgets." This is a warning signal for every company rolling out AI coding tools.
  • Directly relevant to you. If you're pushing AI coding tools at work, your CFO will eventually ask "how much is this actually costing us?" SAP's case is your best argument for "we need to figure out the cost before we scale."

  • HN 34 points but high-quality discussion. Comments focus on "where is the AI cost actually going" and "is SAP using AI costs as an excuse to cut headcount." Some point out SAP's AI costs likely include Azure/AWS GPU rental and API call fees.
