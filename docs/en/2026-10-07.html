Mistral Large 4 — trillion-parameter preview, open weights by end of month

Hey clawii — Mistral is back. After being quiet since last December, they dropped a 1 trillion parameter model (49B active) that scores 38 on Artificial Analysis — close to DeepSeek V4.1 Flash. And they promise open weights this month. This is a real return to the frontier conversation.

📍 Context: Mistral had fallen behind the open-source frontier since Mistral Large 3 (AA score 9). Chinese labs like DeepSeek and Zhipu surged ahead. Now Mistral Large 4 scores 38, trained on their own cluster of 3,800 NVIDIA Grace Blackwell GPUs. The preview is live via their API; open weights are promised by end of October. Simon Willison called it "Le chonk" and confirmed the model is genuinely competitive again.

Why this matters

  • Mistral is competitive again: AA score 38 puts it just behind DeepSeek V4.1 Flash (40). That's a huge leap from Large 3's 9. They're back in the conversation.
  • Open weights by end of month: You'll be able to run this trillion-parameter model yourself or use any inference provider. No lock-in to Mistral's API.
  • European AI ecosystem matters: Mistral is the leading European lab. A strong open-weight model from them means more geographic diversity in the frontier — important for enterprise compliance and sovereignty.

🎯 What you can do today

  1. Try the preview via Mistral API at register.mistral.ai — it's live now.
  2. Read Simon Willison's "Le chonk" blog for benchmark comparisons and pelican drawings.
  3. Watch for the open-weight release at end of month — that's when you can run it locally (with enough hardware) or via a third-party provider.

How hard to use: Preview is just an API key — minutes to try. Open-source version will need at least 80GB VRAM (4-bit quantized) to run locally. Not a MacBook model.

Honest caveat: It's not Fable or Opus 5.5 level (AA 38 vs 57+). But it's competitive in its size class. The open-weight promise is the real story — if they deliver, it's a major addition to the open ecosystem.

🔭 Watch for: The open-weight release at end of month is the real trigger. If it ships under a permissive license (MIT or Apache 2.0), expect community quantized versions and Ollama support within days. That's when you should actually try it.

OpenAI Decisions API public beta — your agent can finally make structured decisions

Hey clawii — OpenAI just launched a Decisions API in public beta. Instead of generating free text and hoping you can parse it, the model returns structured JSON: approve/reject, confidence score, reasoning. This is a native decision-making primitive for agents.

📍 Context: Until now, AI agents could only generate text. If you wanted a yes/no decision, you had to write a prompt, get text back, and parse it with regex or keywords. The Decisions API changes that — the model outputs a structured decision directly: { "decision": "approve", "confidence": 0.92, "reasoning": "..." }. Built on GPT-6 with a specialized decision head. This is a new primitive for agent workflows.

Why this matters

  • Native structured decisions: No more parsing text. The API returns a clean JSON object with decision, confidence, and reasoning.
  • Agent workflow friendly: Perfect for email classification, expense approval, routing, content moderation — any binary or multi-choice decision.
  • Lower engineering overhead: One API call replaces a complex prompt chain with parsing logic. Much simpler to integrate.

🎯 What you can do today

  1. Visit https://developers.openai.com and request access to the Decisions API beta.
  2. Read the docs to understand how to define your decision schema (string enum or boolean).
  3. Build a test agent in Claude Code or Codex that uses the Decisions API as a tool call — e.g., classify an email as "urgent / normal / spam".

How it works: The model uses a specialized "decision head" — an additional output layer trained specifically to produce structured decisions rather than free text. You define the schema (e.g., ["approve", "reject", "more_info"]) and the API guarantees the output conforms.

What it runs on: GPT-6 series models with additional instruction fine-tuning. API-only, no open-source plan.

How hard to use: Very easy. Define your decision schema, call the API. Much simpler than writing a prompt chain with parsing.

Honest caveat: Beta — stability may vary. Only supports simple decision scenarios (binary or few-choice). Complex risk decisions still need human review. Pricing not yet announced.

🔭 Watch for: Pricing at GA — if each decision costs under $0.01, this could replace traditional rule engines at scale. Also watch for open-source alternatives (e.g., Clef's decision capabilities) that might offer similar functionality locally.

Who's talking about it

  • Hacker News: 312 points, 155 comments — strong developer enthusiasm.
  • Simon Willison: hasn't commented yet, but likely to write about it soon.
Jargon decoder: Decision head = a specialized output layer added to a language model that forces it to produce structured decisions instead of free text. Trained separately from the base model. Schema = the definition of what outputs are allowed — e.g., a list of possible decisions, or a boolean true/false.

EmbeddingGemma 2 — Google open-sources a lightweight multimodal embedding model

Hey clawii — Google just released EmbeddingGemma 2, a 700M-parameter multimodal embedding model under Apache 2.0. Simon Willison made the case for why embedding models must be open-weight — and this one is.

Why this matters

  • Open weights = long-term availability: Simon Willison's key point — if you build up millions of embedding vectors using a proprietary model, you're stuck when that model gets deprecated. With open weights, you can run it yourself or switch providers.
  • Lightweight + multimodal: 700M parameters, supports both text and image input. Small enough for modest hardware, capable enough for RAG and retrieval.
  • First Apache 2.0 multimodal embedding model: Other models are either closed-source or have restrictive licenses. This sets a new standard.

Who's talking about it

  • Simon Willison: detailed commentary on why open-weight embedding models matter — blog
  • Hacker News: 340 points, 35 comments
  • Google DeepMind blog: official announcement
Jargon decoder: Embedding model = a model that converts text (or images) into a vector of numbers. These vectors are used for search, clustering, and similarity comparison. Once you embed millions of documents, you can't easily switch models without re-embedding everything.
