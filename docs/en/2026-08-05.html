Stateless MCP: Simon Willison rekindles interest

Hey clawii — Simon Willison posted today that Stateless MCP has recaptured his interest in the protocol. 245 points and 125 comments on HN. MCP is the Model Context Protocol you might already know, but the stateless version removes state management to make integration simpler. If you use MCP servers or want to build your own, this direction is worth watching.

📍 Context · MCP (Model Context Protocol) is an open protocol from Anthropic that lets AI apps connect to external tools and data sources safely. Traditional MCP requires maintaining state — sessions, connection pools, resource state — which adds complexity. Stateless MCP removes all that: each request is independent, like a REST API. Simon Willison is one of MCP's earliest advocates; when his attitude shifts, it usually means the technical direction is changing.

Why this matters

  • Lowers the barrier to using MCP — Stateless means you don't need to manage connection state. You can write a simple HTTP handler and call it an MCP server. For vibe coding users, this makes it easier to build your own tools.
  • Simon Willison endorsement — He's a core figure in the MCP ecosystem. "Recaptured my interest" usually means a substantive improvement is coming. He may release related tools or tutorials.
  • HN community buzz — 245 points + 125 comments means developers are seriously discussing this. Could become the next mainstream MCP pattern.
  • What it means for you — If you use Claude Code or Codex to connect external tools (databases, APIs), Stateless MCP could make configuration simpler and reduce errors.
🎯 What you can do today
  1. Read Simon Willison's post: Stateless MCP has recaptured my interest
  2. Check the HN discussion: Stateless MCP (245 points)
  3. Think about your current MCP usage: could you simplify any of your MCP servers by making them stateless?

LLM 0.32 release: Reasoning traces + OpenAI Responses API

Hey clawii — Simon Willison also shipped LLM 0.32 today, the biggest update to his command-line AI tool since launch. New features include visible reasoning traces (the model's thinking process), native support for OpenAI's new Responses API, and server-side tool support. If you use LLM to manage multiple models from the terminal, this release is worth upgrading for.

📍 Context · LLM is Simon Willison's open-source CLI tool that lets you call various LLMs (OpenAI, Anthropic, local models) from the terminal. It supports a plugin system for extensibility. Many developers use it for quick model testing, scripting, and automation. Version 0.32 is the most significant release since the project started.

Why this matters

  • Reasoning traces support — You can now see the model's "thinking" process. Great for debugging prompts and understanding model behavior. Claude Code and Codex have similar features, but LLM brings it to the terminal.
  • OpenAI Responses API — OpenAI's new unified API for chat, tool calling, and file processing. LLM 0.32 has native support, letting you test the latest API with a single command.
  • Server-side tools — MCP tools can now run on the server instead of the client. Useful for remote deployment and team collaboration.
  • Better logging — Redesigned SQLite logs with content-addressable storage for easy auditing and debugging.
🎯 What you can do today
  1. Upgrade LLM: pip install -U llm
  2. Try reasoning traces: llm -m gpt-5.6-sol "explain quantum entanglement" --reasoning (if the model supports it)
  3. Try the Responses API: llm -m gpt-5.6-sol "write a poem" --response-api
  4. Read Simon's release blog: New release of LLM adds support for reasoning traces, OpenAI Responses, server-side tools, and smarter logging

The reasoning traces feature is especially useful since other tools don't always expose them directly.
