OpenAI 用 AI 解决 Navier–Stokes 百万美元数学难题
clawii，今天 AI 圈炸了——OpenAI 用内部模型（可能是 GPT‑6 Astra）在 88 小时内解决了 Navier–Stokes 存在性与光滑性问题，这是千禧年大奖难题之一，悬赏 100 万美元、挂了 26 年没人解出来。更劲爆的是，这事牵扯到 Anthropic 一位数学家和 OpenAI 之间的"谁先解出来"争议。Simon Willison 写了超详细的分析，Terence Tao 也发帖评论。这不是 benchmark 刷分，这是 AI 真正在数学前沿做出贡献了。
📍 背景 · Navier–Stokes 方程描述流体运动（比如气流、水流），它的"存在性与光滑性"问题是克雷数学研究所 2000 年公布的七个千禧年大奖难题之一，每个悬赏 100 万美元。26 年来无人能解。OpenAI 在 9 月 1 日听到"有人用 AI 解出了千禧年难题"的传闻后，启动内部模型攻关，9 月 5 日得到结果，9 月 6 日用 Lean 完成形式化验证。与此同时，NYU 教授 Tristan Buckmaster 和 Anthropic 的数学家 Levent Alpöge 已经用 Claude + Codex 合作了近一年，在 8 月 15 日取得突破。OpenAI 的介入引发了"谁先解出来"和"是否使用了对方数据"的争议。

为什么这事是 🚨 必看

  • AI 第一次独立解决了一个长期悬而未决的数学难题。这不是"AI 辅助人类解题"，而是 agent 在 88 小时内自主完成推理、证明和形式化验证。用了 2.7 百万条消息、1300 亿个输出 token。
  • 对 vibe coding 的间接影响巨大：如果 AI 能解千禧年难题，那它写代码的能力上限可能比我们想象的更高。这次用的推理方法（agent 自主探索 + Lean 验证）和 coding agent 的工作流非常相似。
  • 争议本身也值得关注：OpenAI 是否通过用户数据（Alpöge 在 Codex 中的工作）获得了竞争优势？Simon Willison 提出了一个尖锐问题："如果我用自己的数据训练模型，会不会让竞争对手受益？"这对所有重度使用 AI 工具的人都是一个警示。
  • Terence Tao 的评论：他说"开放数学问题正在被 AI 非可再生地开采"，意思是——一旦有人传出某个问题有解，AI 就会蜂拥而上抢在原始研究者之前解出来。这会改变整个数学研究的生态。

时间线（根据 Simon Willison 和双方公开声明整理）：

  • 2025 年底 ~ 2026 年 8 月：Tristan Buckmaster（NYU 教授）和 Levent Alpöge（Anthropic 数学家）用 Claude + Codex（主要是 GPT-5.6 Sol）合作研究 Navier–Stokes 问题近一年。
  • 2026 年 8 月 15 日：两人取得突破性进展。
  • 2026 年 9 月 1 日：OpenAI 听到"两个千禧年难题被解出"的传闻，启动内部模型攻关。
  • 2026 年 9 月 5 日：OpenAI 的 agent 在 88 小时内得出 Navier–Stokes 的解法。
  • 2026 年 9 月 6 日：用 Lean 完成形式化验证（额外 17 小时）。
  • 2026 年 9 月 8 日：双方几乎同时发布结果，引发争议。

OpenAI 用了什么模型？

  • 推理阶段：内部模型（可能是 GPT‑6 Astra 的变体，未公开具体版本）
  • 形式化验证：GPT‑6 Astra
  • 总消耗：2.7 百万条消息、1300 亿输出 token（Navier–Stokes 部分）；全部 7 个问题共 4.9 百万条消息、3000 亿 token
  • 按公开 API 价格估算：约 1500 万美元（如果按 GPT‑6 Astra 定价）

争议核心：

  • OpenAI 声称没有访问 Buckmaster 和 Alpöge 的 Codex 会话数据，但承认"不能排除去标识化数据被用于改进模型的可能性"。
  • Buckmaster 质疑 OpenAI 是否通过用户数据获得了竞争优势——他和 Alpöge 把全部草稿都放在 Codex 中。
  • OpenAI 邀请 Buckmaster 合著论文，但明确表示不会邀请 Alpöge（因为他是 Anthropic 员工，存在竞争关系）。
  • Simon Willison 评论："这面镜子映照出计算机安全领域正在发生的事情——仅仅一个漏洞的传闻就足以触发 AI 蜂拥而上。"

对 vibe coding 的启示：

  • AI agent 的推理能力已经达到可以解决数学难题的水平——这意味着 coding agent 的能力上限可能远超我们日常使用所见。
  • 如果你在 Codex / ChatGPT / Claude 中存放了敏感或竞争性工作数据，需要考虑数据是否可能被用于训练。OpenAI 已提供"零数据保留"选项（Zero Data Retention），值得了解。
  • Terence Tao 的评论值得一读：Tao 在 Mathstodon 上的帖子

诚实警告：这次结果尚未经过同行评审。虽然 Lean 形式化验证提供了很强的正确性保证，但数学界需要时间消化这个结果。另外，1500 万美元的计算成本意味着这不是普通人能复现的。

I-have-ADHD：一个让 coding agent 不再把答案藏在长篇输出里的 GitHub skill
clawii，你用过 coding agent 吧？有没有遇到过这种情况——你问了一个简单问题，agent 给你输出了一大堆代码、解释、备选方案，而真正的答案藏在第 47 行？这个叫 I-have-ADHD 的 GitHub skill 就是解决这个问题的。它告诉 agent："直接给答案，别铺垫。" HN 上 463 分、316 条评论，社区反应很热烈。
📍 背景 · 用 Claude Code、Codex、Cursor 等 coding agent 的人都有一个共同痛点：agent 倾向于输出冗长的回复，把关键信息埋在大量上下文里。对于 ADHD 患者（以及任何追求效率的人）来说，这很折磨。这个 skill 是一个系统提示（system prompt），你把它加到 agent 的指令中，它就会改变 agent 的输出风格——先给结论，再给细节（如果需要的话）。本质上是一个"反铺垫"的 prompt 模板。

为什么这事值得看

  • 直接解决一个真实痛点：如果你用 vibe coding 做日常工作，你一定遇到过 agent 输出太长、找不到重点的问题。这个 skill 就是针对这个的。
  • 社区验证：HN 463 分、316 条评论，说明很多人认同这个问题。评论中有人分享了类似的 prompt 技巧，也有人讨论了如何让 agent 更"直接"。
  • 零成本、零安装：就是一个 prompt 模板，复制粘贴就能用。不需要装任何东西。

🎯 今天就能做的事

  1. 打开 GitHub 仓库：github.com/ayghri/i-have-adhd
  2. 复制 skill 的 system prompt 内容
  3. 在你的 Claude Code / Codex / Cursor 中粘贴这个 prompt（作为 system prompt 或项目说明的第一行）
  4. 试试效果——比如问一个复杂问题，看看 agent 是否先给结论再给细节
🔬 深扒——这个 skill 到底做了什么、怎么用、效果如何

核心机制：这个 skill 本质上是一个精心设计的 system prompt，它告诉 agent：

  • "先给出直接答案，不要铺垫"
  • "如果用户需要细节，再展开"
  • "不要输出无关的代码或解释"
  • "用最少的字数回答"

它不是一个新的工具或框架，就是一个 prompt 模板。但它的价值在于：它把"如何让 agent 更直接"这个经验总结成了一个可复用的 skill。

vs 默认的 agent 行为：

  • 默认 Claude Code / Codex：倾向于输出完整的解决方案，包括代码、解释、备选方案、注意事项。对于复杂问题，这可能是好事；但对于简单问题，这很烦人。
  • 用了 I-have-ADHD：agent 先给一句话答案，然后问"需要我展开吗？"——类似于"executive summary first"模式。

怎么用：

  • 在 Claude Code 中：在项目根目录创建 .claude/skills/ 目录，把 skill 文件放进去
  • 在 Codex 中：在 settings 或 project instructions 中粘贴 prompt
  • 在 Cursor 中：在 Rules for AI 中添加
  • 或者直接在对话中粘贴："请使用 I-have-ADHD 模式回答"

诚实警告：这个 skill 对简单问题效果很好，但对复杂问题（比如需要多步骤推理的）可能不太合适——你可能会错过重要的上下文。建议按需启用，不要全局默认开启。

🔭 盯紧什么 · 看这个 skill 是否会成为 Claude Code / Codex 的默认 skill 之一，或者是否会有更多类似的反铺垫 prompt 出现。如果社区形成共识，agent 的默认输出风格可能会改变。

ChatGPT Images 2.5 发布：更快的图像生成 + 参考图保持能力提升
clawii，OpenAI 昨天发布了 ChatGPT Images 2.5，说是图像生成模型的重大升级。主要改进：指令跟随更好、生成速度更快、对参考照片的"主体保持"能力更强。API 有两个新模型 ID：gpt-image-2.5-sunburst（更强）和 gpt-image-2.5-flare（更快）。Simon Willison 已经写了一个 CLI 工具来调用它。
📍 背景 · OpenAI 的图像生成模型已经生成了超过 30 亿张图片。2.5 版本是继 2.0 之后的又一次迭代，重点改进了多轮对话中的指令跟随能力和参考图的一致性。如果你用 AI 生成图片做演示、原型或社交媒体内容，这个升级值得一试。

为什么这事重要（但不用立即行动）

  • 参考图保持能力提升：如果你上传一张参考照片，2.5 版本能更好地保持主体的外观特征（比如人脸、物体形状）。这对设计原型和品牌素材有用。
  • 速度提升：Flare 版本针对速度优化，适合批量生成。
  • Simon Willison 的工具：他写了一个 CLI 工具 openai_image.py，支持传入参考图片，方便在终端中使用。
