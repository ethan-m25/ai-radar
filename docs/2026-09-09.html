OpenAI 用 AI 解决 Navier–Stokes 千禧年难题 + 数学界争议
clawii，今天整个 HN 和数学圈都在炸——OpenAI 宣布他们用内部模型（可能是 GPT‑6 Astra）解决了 Navier–Stokes 存在性与光滑性问题，这是七个千禧年大奖难题之一。但争议在于：他们是在听说另一个团队（Anthropic 员工 + NYU 教授）用 AI 做了近一年工作后才启动的，而且只用了 88 小时就“抢先”解出来了。Simon Willison 写了一篇长文分析，Terence Tao 也发帖说“开放数学问题正在被 AI 不可再生地开采”。这不是普通的模型发布——这是 AI 能力的一次跃迁，也是学术伦理的一次地震。
📍 背景 · Navier–Stokes 方程是描述流体运动的基本方程，其解的存在性与光滑性被 Clay 数学研究所列为七个千禧年大奖难题之一，悬赏 100 万美元。过去几十年无数数学家尝试未果。2026 年 8 月，Anthropic 员工 Levent Alpöge 和 NYU 教授 Tristan Buckmaster 用 Claude + Codex（GPT-5.6 Sol）合作了近一年，取得了突破。9 月 1 日，OpenAI 听说“两个千禧年问题被解决”的传闻后，启动内部模型（GPT‑6 Astra）评估所有千禧年问题，9 月 5 日就解出了 Navier–Stokes，用时 88 小时，消耗约 1300 亿输出 token（按公开 API 价格约 1500 万美元）。OpenAI 声称没有访问 Buckmaster 团队的数据，但无法完全排除“去标识化数据”的影响。Buckmaster 指控 OpenAI 抢跑。Simon Willison 将此事比作“安全漏洞的传闻足以触发 agent 去挖漏洞”——现在数学也一样。

为什么这事必看

  • AI 能力跃迁的里程碑：AI 首次独立解决了一个千禧年大奖难题。这比之前任何数学辅助都更进一步——agent 自主提出证明思路、形式化验证（Lean），只用了 88 小时。这意味着 AI 已经可以处理人类顶尖数学家需要数年甚至数十年的问题。
  • 对 vibe coding 的间接影响：虽然你不需要解偏微分方程，但这证明了 agent 在长链条推理、形式化验证上的能力。未来 coding agent 可能也能自动验证代码正确性（类似 Lean 验证数学证明）。
  • 学术伦理的警示：传闻触发 agent 抢跑——如果你用 AI 做任何创新工作，你的数据可能被“去标识化”后帮助竞争对手。Simon 说“我的新假设问题变成了：如果我用 ChatGPT 帮我部分解决一个千禧年问题，我的工作会不会影响训练，让后来的模型帮别人先解出来？”
  • HN 双首页 + Simon + Tao 都在讨论：两个帖子分别 1720 和 1269 分，评论超 1700 条。Simon 今天发了长文，Terence Tao 也发帖讨论“开放数学问题被 AI 不可再生开采”。这是本周最热的话题。

🔬 深扒——技术细节、争议点、对 vibe coding 的启示

技术细节：OpenAI 使用的模型是内部版本（推测为 GPT‑6 Astra 的变体），agent 架构类似 Codex + 形式化验证工具 Lean。整个流程：agent 自主提出数学构造 → 用 Lean 形式化 → 验证 → 迭代。共发送 270 万条消息，消耗约 1300 亿输出 token。Lean 验证花了额外 17 小时。

与 Buckmaster 团队的区别：Buckmaster 团队用了近一年，人类主导 + AI 辅助（Claude + Codex）。OpenAI 是纯 agent 驱动，速度极快但成本极高（按公开 API 价格约 1500 万美元）。两个证明在细节上不同（forced vs unforced Euler case）。

争议核心：

  • OpenAI 承认“听到传闻后启动”，但声称没有访问 Buckmaster 的私有数据。
  • Buckmaster 指控 OpenAI 可能通过去标识化训练数据间接利用了他们的工作。
  • OpenAI 提出联合发布，但拒绝将 Levent Alpöge（Anthropic 员工）列为共同作者。
  • Simon 指出：这就像安全漏洞的传闻足以触发 agent 去挖漏洞——现在数学也一样。

对 vibe coding 的启示：

  • Agent 的长链条推理能力已经达到可以解决数学难题的水平。未来 coding agent 可能也能自动验证代码正确性（类似 Lean 验证）。
  • 成本问题：1500 万美元一次，但趋势是快速下降。1-2 年内类似能力可能以更低成本可用。
  • 数据隐私：如果你用 AI 做创新工作，你的数据可能被用于训练，从而帮助竞争对手。建议使用本地模型或明确 opt-out。

诚实警告：这个事件对日常 vibe coding 没有直接影响。但它是一个信号——AI 的能力边界正在快速扩展。值得关注的是 agent 在长链条推理和形式化验证上的进步。

Meta Muse — 个人 AI agent
clawii，Meta 今天发布了 Muse，一个“个人 AI agent”。HN 上 531 分、573 条评论。Muse 定位为你的私人助手，可以跨应用执行任务、管理日程、写邮件、做研究。它基于 Meta 的 Llama 系列模型，但具体版本未公开。关键是——它直接与 ChatGPT、Claude 竞争，而且 Meta 强调“隐私优先”，数据本地处理。这对你这种重度 AI 用户来说，可能是一个值得关注的新选项。
📍 背景 · 个人 AI agent 市场正在快速膨胀：OpenAI 有 ChatGPT + Astra，Anthropic 有 Claude，Google 有 Gemini。Meta 之前主要做开源模型（Llama），现在推出面向消费者的 agent 产品。Muse 的卖点是“隐私优先”——数据处理在设备端完成，不上传云端。这与 ChatGPT 的云端处理形成对比。HN 讨论集中在：Muse 是否真的能本地运行？性能如何？与现有 agent 相比有什么优势？

为什么这事值得看

  • 新的竞争者入场：Meta 有庞大的用户基础（Facebook、Instagram、WhatsApp），如果 Muse 集成到这些平台，可能快速获得用户。对开发者来说，可能意味着新的 API 和生态。
  • 隐私优先的差异化：如果你对数据隐私敏感（比如不想让 OpenAI 看到你的工作内容），Muse 的本地处理模式可能是一个替代方案。
  • HN 531 分，讨论活跃：573 条评论，社区在讨论 Muse 的实际能力、隐私承诺的可信度、以及与现有工具的对比。

🎯 今天就能做的事

  1. 读 Meta 官方公告：meta.com/muse
  2. 看 HN 讨论：HN 主帖
  3. 如果可用，尝试 Muse 的早期访问（可能需要 Meta 账号）。
🔬 深扒——与 ChatGPT/Claude 的对比、技术细节、上手难度

vs ChatGPT / Claude：

  • ChatGPT 和 Claude 是云端处理，Muse 强调本地处理（至少部分任务）。
  • Muse 可能集成 Meta 生态（Instagram、WhatsApp），而 ChatGPT 有插件生态。
  • 模型能力：Muse 基于 Llama 系列，但具体版本未公开。Llama 4 系列在编码任务上不如 GPT-5.6 Sol 或 Claude Fable 5，但日常任务可能足够。
  • 价格：Meta 尚未公布定价，可能免费或低价（通过广告支持）。

技术细节：Muse 使用 Meta 的 Llama 模型，但针对 agent 任务进行了微调。支持工具调用（日历、邮件、浏览器等）。隐私方面：敏感数据在设备端处理，非敏感任务可能使用云端。

上手难度：需要 Meta 账号，可能通过独立应用或集成到现有 Meta 应用中使用。对非开发者友好。

诚实警告：Meta 的隐私承诺需要验证——历史上 Meta 在数据隐私方面有争议。Muse 的本地处理能力可能有限，复杂任务仍需云端。

🔭 盯紧什么 · 看 Muse 是否开放 API 或插件系统。看实际评测与 ChatGPT/Claude 的对比。看 Meta 是否开源底层模型。

OpenAI ChatGPT Images 2.5 — 图像生成升级
clawii，OpenAI 昨天发布了 ChatGPT Images 2.5，改进了指令跟随、多轮编辑和速度。Simon Willison 今天也写了介绍。但图像生成对你的 vibe coding 工作流影响有限，所以只是知道就行。

为什么这事重要（但不用立即行动）

  • 图像生成能力提升：新模型 gpt-image-2.5-sunburst 和 gpt-image-2.5-flare，Sunburst 侧重编辑精度，Flare 侧重速度。支持参考图像。
  • Simon 写了 CLI 工具：可以用 uv run 命令行生成图像，对开发者友好。
  • 对非开发者：如果你需要为工作生成图表、示意图，这个升级可能有用。
