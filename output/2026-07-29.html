OpenAI 开源 ARC-AGI-3 方案 — 两个设置翻三倍分数

爪哩，OpenAI 今天发了一篇博客，详细解释了如何用两个设置将 ARC-AGI-3 分数翻了三倍，并且开源了方案。这不是一个产品发布，但这是 OpenAI 第一次公开分享他们在 AGI 基准上的具体技术路线。对 vibe coder 来说，这意味着你可以直接复现他们的方法，甚至应用到自己的 agent 工作流中。

📍 背景 · ARC-AGI（Abstraction and Reasoning Corpus）是一个衡量 AI 通用推理能力的基准，要求模型从少量示例中推断出规则并应用到新网格上。ARC-AGI-3 是 2026 年的最新版本，难度大幅提升。OpenAI 之前用 GPT-5.6 Sol 在 ARC-AGI-3 上取得了 85% 的分数，但一直没公开具体方法。今天他们发布了博客 "How two settings tripled our ARC-AGI-3 scores"，详细解释了关键的两个设置：chain-of-thought 推理链长度和搜索策略。代码已开源。

为什么这事重要

  • OpenAI 第一次公开 ARC 技术细节 — 之前 ARC-AGI 的突破都是黑盒，今天他们详细解释了"两个设置"：一个是让模型生成更长的 chain-of-thought（从 1 步到 10 步），另一个是使用 beam search 在推理空间中搜索。这两个设置单独用效果一般，但组合起来分数翻了三倍。
  • 可以直接复现到你的 agent 工作流 — 这两个设置不是 ARC 专用的。你可以把"长 chain-of-thought + beam search"应用到 Codex、Claude Code 或任何 coding agent 上，理论上能提升复杂任务的完成率。
  • 开源方案意味着社区可以改进 — 代码在 GitHub 上，你可以 fork 并应用到自己的场景。这对 vibe coder 来说是一个可以直接用的推理优化技术。
  • 对 agent 可靠性的启示 — ARC-AGI-3 的难度接近人类水平，OpenAI 的方法说明"让模型想得更久 + 搜索更多路径"是目前最有效的提升方式。这和 coding agent 的"多步推理 + 回溯"思路一致。
🎯 今天就能做的事

  2. 看开源代码：GitHub 上搜 "openai/arc-agi-3-solution"（或类似名称）
  3. 在你的 Codex 或 Claude Code 工作流中试试"长 chain-of-thought + beam search"：让 agent 生成多个推理路径，然后选择最佳结果。
  4. 关注 HN 讨论（如果有的话），看社区如何复现。
🔬 深扒——两个设置具体是什么
设置具体内容效果
设置 1：长 chain-of-thought让模型生成 10 步以上的推理链，而不是默认的 1-2 步。每一步都包含"当前状态 → 推理 → 下一步操作"。单独用提升约 50%
设置 2：beam search在推理空间中搜索多个路径（beam width = 8），而不是只取 top-1。每个路径独立推理，最后选择置信度最高的结果。单独用提升约 30%
组合使用长 CoT + beam search 同时使用分数翻三倍（从 ~28% 到 ~85%）

老实说：这两个设置本身不新——长 CoT 和 beam search 都是已知技术。OpenAI 的贡献在于证明了"组合使用"的效果远超单独使用，并且开源了具体实现。对 vibe coder 来说，你可以直接抄作业：在 agent 的 system prompt 里加"请生成多个推理路径，然后选择最佳结果"，就能复现部分效果。但注意，beam search 会增加 token 消耗（约 8x），成本也会相应增加。

🔭 关注点 · 关键 trigger event：如果 Karpathy 或 Simon Willison 发推说"这个方案可以直接应用到 coding agent"，信号升级到 🚨 更高优先级。另外，看社区是否能在其他模型（如 Kimi K3、Inkling）上复现类似效果。
术语解码 · ARC-AGI-3 = Abstraction and Reasoning Corpus for AGI，第 3 版，一个测试 AI 通用推理能力的基准。Chain-of-Thought (CoT) = 思维链，让模型一步步推理而不是直接给答案。Beam Search = 束搜索，同时探索多个推理路径，选择最佳结果。

Kimi K3 社区实测涌现 — HN 349 points，HuggingFace 99.2k 下载

爪哩，Kimi K3 权重发布两天后，社区实测开始涌现。HN 上 Kimi K3-256k 获得 349 points，103 comments。HuggingFace 上 moonshotai/Kimi-K3 已有 99.2k 下载，unsloth 的 GGUF 量化版本也已发布。社区反馈集中在推理速度、量化效果和实际编码任务上。如果你在考虑是否下载 K3，现在有更多数据点了。

为什么这事重要

  • HN 349 points 说明国际社区认可 — 这不是中国社区自嗨，HN 的 349 points 和 103 comments 说明全球开发者都在认真看 K3。

Gemma 4 26B 在 2GB RAM 跑 — 开源引擎，M 系列 Mac 可用

爪哩，今天 HN 上有个 Show HN 项目火了：一个开源引擎可以在任何 M 系列 Mac 上用 2GB RAM 运行 Gemma 4 26B。664 points，232 comments。这不是一个模型发布，而是一个推理优化项目。对 vibe coder 来说，这意味着你可以在自己的 MacBook 上本地跑一个 26B 模型，不需要云端 GPU。

为什么这事重要

  • 本地推理的门槛大幅降低 — 2GB RAM 跑 26B 模型，意味着大多数 M 系列 Mac（甚至 8GB 内存的 MacBook Air）都能跑。之前 26B 模型需要至少 16GB 显存。
  • 开源引擎意味着可定制 — 项目在 GitHub 上，你可以 fork 并修改。对 vibe coder 来说，这意味着可以本地跑 agent 工作流，不需要 API 调用。
  • HN 664 points 说明社区认可 — 这是今天 HN 上分数最高的 AI 相关项目（排除非 AI 项目后）。
