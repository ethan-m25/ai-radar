MCP 2.0 协议升级——Stateless MCP，连接更简单，生态系统升级

爪哩，MCP 协议迎来了一次重大升级——MCP 2.0（2026-07-28 规范），也叫 Stateless MCP。Simon Willison 在 7/31 和 8/2 连续发文，说这是 "MCP 发布以来最重要的变化"，还自己做了 mcp-explorer 和 datasette-mcp 两个工具。对于你日常用 Claude Code 时那些 MCP 连接，这次升级意味着什么？

📍 背景 · MCP（Model Context Protocol）是 Anthropic 推出的协议，让 AI 模型（比如 Claude Code）能安全地连接外部工具和数据源。之前每个 MCP 服务器需要维护会话状态（stateful），连接建立和断开都挺重。MCP 2.0 引入了 Stateless MCP：服务器变得无状态，每次请求独立，不需要记住历史会话。这大大降低了搭建 MCP 服务器的门槛，也让连接更可靠、更易扩展。Simon Willison 在 7/31 写了一篇详细分析，今天（8/2）又发帖说 "Stateless MCP 重新点燃了我的兴趣"，并发布了 mcp-explorer（一个 MCP 服务器浏览器）和 datasette-mcp（让 Datasette 数据库通过 MCP 被 AI 调用）。

为什么这事重要

  • 生态级升级 — MCP 是 Claude Code、Cursor 等工具连接外部数据的基础设施。Stateless 让 MCP 服务器更容易写、更稳定，意味着更多数据源能通过 MCP 接入 AI 工具。
  • Simon Willison 连续信号 — 他 7/31 写了一篇长文，8/2 又发帖说 "重新点燃兴趣"，并发布了配套工具。这是典型的 "KOL 持续关注" 信号。
  • 对你的意义 — 如果你在用 Claude Code 或 Codex 做 vibe coding，MCP 是你连接公司数据库、文件系统、API 的桥梁。Stateless MCP 让这些连接更容易搭建，未来可能会有更多 "即插即用" 的 MCP 服务器出现。
  • 协议变化影响所有 MCP 用户 — 现有的 MCP 客户端和服务端可能需要更新以支持 stateless 模式，但这是向好的方向进化。

🔬 深扒——MCP 2.0 和旧版 MCP 到底有什么不同
方面MCP 1.0（Stateful）MCP 2.0（Stateless）
连接方式需要建立持久会话，带状态管理无状态，每次请求独立
服务器复杂度需要维护 session 状态、连接池无状态，实现更简单，部署更轻
扩展性依赖会话，水平扩展需额外工作天然无状态，容易水平扩展
容错性连接断开后需要重建会话连接断开后直接重试，无状态丢失
工具发现通过 capabilities 方式通过工具列表（tools/list）无状态查询
对开发者门槛中等（需要理解 session 管理）低（类似 REST API 思维）

老实说：MCP 2.0 不是颠覆性的新技术，而是一个重要的进化。它让 MCP 服务器变得更像 "AI 可调用的 REST API"，降低了开发门槛。对于非开发者来说，这意味着未来会有更多现成的 MCP 服务器可以用。Simon Willison 的 datasette-mcp 就是一个好例子——一个 SQLite 数据库通过 MCP 暴露给 AI，只需要一行命令。

🔭 关注点 · 关键 trigger event：如果 Anthropic 正式宣布 Claude Code 默认使用 MCP 2.0，或者 major MCP 客户端（如 Cursor、VS Code 扩展）宣布支持 Stateless 模式，信号将升级。另外看是否有企业级 MCP 目录/市场出现——那将是生态成熟的标志。
术语解码 · Stateless = 无状态，每次请求独立，不依赖之前会话的信息。有点像 HTTP 请求 vs 一个需要保持登录状态的聊天窗口。MCP 服务器 = 一个提供数据和工具的 "接口"，AI 可以通过 MCP 协议调用它。比如一个 MCP 服务器可以连接你的公司数据库，让 AI 直接查询。

Kimi K3 在 MI355X 上性价比超 B300——HN 135 分，新部署成本数据

爪哩，Kimi K3 又有了新消息——这次不是关于 29GB 跑 0.5 tok/s，而是正经的部署成本对比：在 AMD MI355X 上，K3 的性价比（每美元产出 token 数）超过了 NVIDIA B300。HN 135 points，45 comments，讨论热烈。对于正在考虑用 K3 做企业级部署的人来说，这是个重要数据点。

📍 背景 · Kimi K3（2.8T 参数 MoE，104B 活跃）发布两周来，一直是讨论焦点。之前社区关注的是 "能不能跑"（29GB 内存实验），现在开始关注 "跑得值不值"。这次 HN 帖子来自 wafer.ai，对比了 K3 在 AMD MI355X（AMD 最新 AI 加速器）vs NVIDIA B300（Blackwell 系列）上的推理性能与成本。结论是：MI355X 在每美元产出的 token 数上超过 B300，意味着用 AMD 芯片跑 K3 更划算。这对企业采购决策有直接影响。

为什么这事重要

  • 成本数据，不是空谈 — 这不是 "K3 很厉害" 的抽象废话，而是具体的每美元 token 产出对比。MI355X 上性价比 > B300，意味着如果你们公司在考虑部署 K3，AMD 方案可能更划算。
  • HN 135 points + 45 comments — 讨论活跃，说明社区对这个数据点认真对待。
  • 对你的意义 — 虽然你不是搞部署的，但如果你公司未来可能用 K3（比如做内部 AI 工具），这个数据点能帮你在成本讨论中站住脚。"MI355X 上跑 K3 性价比比 B300 高" 是个可以拍桌子的论点。
  • 延续 K3 的故事线 — 从 "能不能跑" 到 "跑得值不值"，K3 正在从技术演示走向企业级应用。
