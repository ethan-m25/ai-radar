Tencent Hy4-preview：770B 参数开源 MoE，1M 上下文，HN 312 分
clawii，腾讯开源了 Hy4-preview，770B 总参 / 49B 激活，1M 上下文，Apache 2.0 协议。HN 冲到 312 分，192 条评论。虽然中文圈已经聊了一周，但 HN 的讨论质量很高，值得周末翻翻。
📍 背景 · Hy 系列是腾讯的开源 MoE 模型。Hy3（295B/21B 激活）7 月发布，Hy4-preview 是大幅升级版。770B 总参数 / 49B 激活，1M 上下文，1.56TB 权重文件。目前只支持文本输入（无视觉），有两个 reasoning effort 级别："high"（默认）和 "no_think"。Simon Willison 已经用他的经典 prompt（"骑自行车的鹈鹕 SVG"）测试过，生成了不错的结果。
Hy4-preview 770B 总 / 49B 激活
Hy3 295B 总 / 21B 激活
GLM-5.3 753B 总 / 40B 激活
DeepSeek V4-Flash 304B 总 / 37B 激活

为什么这事重要

  • 49B 激活 = 本地可跑：虽然 770B 总参吓人，但 MoE 架构下每次推理只激活 49B，4-bit 量化后大约 30GB 显存，RTX 4090 勉强能跑。
  • 1M 上下文：和 GLM-5.3 一样，可以处理整本书或整个代码库。适合 agent 和长文档分析。
  • Apache 2.0 协议：商用友好，和 MIT 一样宽松。
  • Simon Willison 亲自评测：他用 OpenRouter 跑了，说 reasoning trace 用了截断式英语（"Let's maybe add a helmet?"），很有意思。
  • HN 312 分不是闹着玩的：社区讨论集中在"和 GLM-5.3 比怎么样"、"为什么只有两个 reasoning 级别"。

vs GLM-5.3：Hy4-preview 总参更大（770B vs 753B），激活参数也更多（49B vs 40B），但 GLM-5.3 支持多模态（视觉+文本），Hy4 目前只有文本。两者都是 MoE、1M 上下文、开源。GLM-5.3 用 MIT 协议，Hy4 用 Apache 2.0，都很宽松。

上手难度：如果你用 OpenRouter，5 分钟就能试。本地跑需要至少 32GB 显存（4-bit 量化），建议用 vLLM 或 llama.cpp。Ollama 可能已经支持。

诚实警告：Simon 提到 reasoning trace 用了截断式英语，说明模型在推理时可能做了 token 效率优化。另外，只有两个 reasoning 级别（high / no_think），没有中间档。中文社区已经覆盖了一周，但 HN 的讨论质量很高，值得看。

🔭 盯紧什么 · Karpathy 是否试用。如果他也发推，那 Hy4-preview 就是中国开源模型的又一里程碑。另外看 Ollama 列表何时加入官方支持。
术语解码 · MoE = 混合专家 · 激活参数 = 每次推理实际使用的参数数量 · reasoning effort = 推理努力程度，控制模型在回答前花多少 token 进行思考 · reasoning trace = 推理过程的中间输出，可以看到模型"在想什么"。
