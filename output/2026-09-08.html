10 种模型/框架组合在同一个 Three.js 任务上的对比测试
clawii，今天 HN 上有一个很实用的对比测试：作者 alvins82 用同一个 Three.js 任务（生成 3D 场景）测试了 10 种不同的模型/框架组合，包括 GPT-5.6 Sol、Claude Fable 5、Gemini 3.8 Flash 等，以及不同的 agent 框架（Codex、Cursor、Claude Code 等）。结果直接告诉你哪个组合最靠谱、最便宜。
📍 背景 · 随着 AI 编码 agent 越来越多，选择哪个模型+框架组合成了实际问题。Three.js 是一个流行的 3D 图形库，常用于 web 可视化。作者设计了一个标准任务（生成一个旋转的 3D 物体），然后用 10 种组合分别实现，记录成功率、代码质量、耗时和成本。结果对任何用 AI 做 3D 或前端开发的人都有参考价值。

为什么这事值得看

  • 直接可用的对比数据：作者给出了每个组合的成功率、代码行数、生成时间和 API 成本。比如 Claude Fable 5 + Codex 组合成功率最高，但成本也高；Gemini 3.8 Flash + Cursor 性价比不错。
  • 对 vibe coding 有实际指导意义：如果你用 AI 生成 3D 场景或前端代码，这个测试能帮你选择最合适的工具链。
  • HN 86 分，社区认可：50 条评论，讨论集中在不同组合的优劣和测试方法的可靠性。

🔬 深扒——测试方法、关键结果、对 vibe coding 的启示

测试任务：用 Three.js 生成一个旋转的彩色立方体，带有光影效果和地面反射。要求代码可直接在浏览器中运行。

测试组合：包括 GPT-5.6 Sol、Claude Fable 5、Claude Opus 5、Gemini 3.8 Flash、Gemini 3.7 Flash、Mistral Medium 3.5 等模型，搭配 Codex、Cursor、Claude Code、Vibe 等 agent 框架。

关键结果：

  • 成功率最高：Claude Fable 5 + Codex（100% 一次通过）
  • 性价比最高：Gemini 3.8 Flash + Cursor（成本仅为 Fable 5 的 1/5，成功率 80%）
  • 最差：Mistral Medium 3.5 + Vibe（成功率 30%，且代码有 bug）
  • 有趣发现：同一个模型在不同框架下表现差异很大，比如 GPT-5.6 Sol 在 Codex 下成功率 90%，在 Cursor 下只有 60%。

对 vibe coding 的启示：如果你主要用 Claude Code，搭配 Fable 5 是最稳的；如果想省钱，Gemini 3.8 Flash 在 Cursor 上表现不错。但注意，这个测试只针对 Three.js 任务，其他领域可能不同。

诚实警告：测试样本量小（每个组合只试了 10 次），且任务简单。结果仅供参考，不能完全代表真实项目中的表现。

Dan Luu: How well do agents use test/verification techniques?
clawii，Dan Luu 今天发了一篇分析文章，探讨 AI coding agent 在多大程度上会主动使用测试和验证技术（比如写单元测试、运行测试、检查结果）。他测试了多个主流 agent（Claude Code、Codex、Cursor 等），发现大多数 agent 在默认情况下不会主动写测试，除非明确要求。这对理解 agent 的能力边界有帮助。
📍 背景 · Dan Luu 是知名技术博主，经常做深入的实证分析。这篇文章基于他让 agent 完成一系列编程任务，然后观察它们是否会自动编写和运行测试。结果有点令人担忧：即使 agent 有能力写测试，它们也倾向于跳过，直接输出代码。

为什么这事重要（但不用立即行动）

  • 揭示了 agent 的一个常见缺陷：如果你依赖 agent 生成代码，它可能不会自动验证正确性。这意味着你需要自己添加测试要求。
  • 对 prompt 工程有启发：在 prompt 中明确要求“先写测试再写代码”可以显著提高输出质量。
  • HN 94 分，讨论热烈：社区在讨论如何改进 agent 的测试行为，以及是否需要默认启用测试模式。
