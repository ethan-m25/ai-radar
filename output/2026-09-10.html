DeepSeek v4.1 Flash — 新一代 MOE 推理模型
clawii，今天 DeepSeek 突然发布了 v4.1 Flash，一个 485B 参数的 MOE 模型（激活 37B），在推理和编码任务上直接对标 GPT-5.6 Sol 和 Claude Fable 5.1。HN 上 430 分、203 条评论。关键是：它比上一代 v4.0 快 3 倍，价格更低，而且完全开放权重。这对你的 vibe coding 工作流来说，意味着又多了一个强有力的本地/API 选项。
📍 背景 · DeepSeek 在 2026 年 8 月发布了 DeepSeek v4.0，当时在编码和数学推理上已经是开源标杆。v4.1 Flash 是快速迭代版：架构从 370B 总参/32B 激活升级到 485B/37B，支持 256K 上下文窗口，采用多头潜在注意力（MLA）优化推理速度。更关键的是，它在推理能力上大幅提升，特别是“逻辑弹性推理” —— agent 可以根据问题难度动态调整计算量。这直接影响到 agent 的响应速度和成本。

为什么这事必看

  • 直接对标最强闭源模型: v4.1 Flash 在多个基准（MATH-500, Codeforces, GPQA）上逼近甚至持平 GPT-5.6 Sol 和 Claude Fable 5.1，但价格低一个数量级。对重度 API 用户来说，这是成本能砍半的机会。
  • 推理 agent 的性能飞跃: “逻辑弹性推理”意味着 agent 在简单问题上消耗更少 token、复杂问题上消耗更多。这会直接影响 coding agent 的响应速度——简单重构不卡，复杂重构才慢慢想。
  • 完全开放权重 + 开源: DeepSeek 一如既往开源了权重和推理代码。可以在自己的硬件上运行，也可以使用 DeepSeek API 或第三方推理提供商。
  • HN 430 分，社区热度高: 203 条评论，讨论集中在与 GPT-5.6 Sol 的对比、实际使用体验、以及开源对生态的影响。

架构细节：基于 DeepSeek v4 的 MOE（混合专家）架构，但做了几项关键改进：1) 逻辑弹性推理——agent 可以动态分配计算量，简单问题用更少专家；2) 多头潜在注意力（MLA）——减少 KV 缓存占用，推理更快；3) 训练数据扩展——新增 2 万亿 token 的代码和数学数据。

上手难度：通过 API 使用非常简单（curl 请求）。如果本地部署，需要至少 80GB 显存（单卡 A100/H100），建议使用量化版（GGUF 或 AWQ）。llama.cpp 已经支持。

你能拿它做什么：1) 作为 vibe coding 的替代模型，把 codex 或 Cursor 的后端换成 DeepSeek v4.1 Flash（支持 OpenAI API 兼容）；2) 用本地版处理敏感数据；3) 大批量任务（翻译、摘要、数据清洗）因为价格低可以无脑跑。

诚实警告：虽然基准接近，但实际编码体验上，GPT-5.6 Sol 在复杂多步推理上仍略有优势。中文能力方面，DeepSeek 在中文场景下通常更自然。文档和社区支持不如 OpenAI 成熟。

WeWorm: 首个零点击 AI 蠕虫通过微信电话传播
clawii，Simon Willison 今天报道了一个新发布的 AI 安全研究：WeWorm，首个通过微信电话传播的零点击蠕虫。受害者甚至不需要接电话，只要手机在响铃状态就已被感染。这篇论文展示了 AI 如何将安全研究速度提升两个数量级——团队用 AI 在两天内找到了 RCE 漏洞并写出了利用代码。这跟你有什么关系？agent 时代的安全模型正在被重塑：AI 可以更快地找到漏洞，也可以更快地修补漏洞。
📍 背景 · 9 月 10 日，Calif Research 发布了 WeWorm 演示视频和白皮书。这是第一个通过微信通话功能传播的零点击蠕虫：攻击者拨打微信电话，即使受害者不接听（甚至不操作手机），漏洞利用已在通话建立阶段完成。关键点：团队使用 AI（未指明具体模型）在约 2 天内找到 RCE 漏洞并编写了利用代码。Simon 在博客中写道：“这种规模的蠕虫曾经需要更大团队数月时间。AI 已经可以完成大部分工作。”

为什么这事值得看

  • AI 驱动的安全威胁进入新阶段：零点击蠕虫不是新概念，但 AI 让它变得更快、更容易制造。从发现漏洞到写出 worm，AI 把时间从月压缩到了天。
  • 对 agent 安全模型的启示：如果你的 coding agent 有网络访问权限（比如可以上网搜索或执行 API 调用），类似的安全漏洞可能被利用来劫持 agent。
  • Simon 深度分析：他强调了“AI 安全研究的加速”这个趋势，并引用了 Terence Tao 关于“开放问题被不可再生开采”的评论。

  2. 看 WeWorm 演示视频（注意：可能引起不适）：Calif Research 官方页面

🔬 深扒——技术细节、对 vibe coding 的启示、安全建议

技术细节：WeWorm 利用微信通话功能中的一个 RCE（远程代码执行）漏洞。攻击者只需拨打微信电话，即使受害者不接听，漏洞已在通话建立阶段触发。worm 会自我复制并通过受害者的微信联系人继续传播。团队使用了 AI（未指定模型）来辅助漏洞挖掘和利用代码编写。

对 vibe coding 的启示：

  • 如果你的 agent 能够访问网络、执行代码、或与外部系统交互，它就可能成为攻击目标。
  • AI 加快安全研究的速度，这意味着 0-day 发现周期在缩短。依赖 AI 构建的系统需要更快的补丁响应。
  • 好消息是，同样的技术也可以用于安全防御——AI 可以更快地分析日志、识别攻击模式。

安全建议：

  • 使用 agent 时，限制其权限（最小权限原则）。
  • 不要将 agent 直接暴露在互联网上。
  • 定期更新所有依赖（特别是安全补丁）。
  • 监控 agent 的异常行为（频繁的网络请求、尝试访问敏感系统）。
