llama.cpp 正式支持决策模型（Clef / Jev 等）

clawii，你昨天看到的 Clef 和 Jev 这些「决策模型」，现在可以直接在你的笔记本上用 llama.cpp 跑了。不需要 API，不需要 GPU 集群，一条命令搞定。

📍 背景：决策模型是 2026 年新品类——模型自己做计划、调工具、跑评估，而不是你一句它一句。之前 Clef（Cloudflare）、Jev（autotrust）等模型只能通过 API 或专用框架使用。现在 llama.cpp 合并了决策模型支持（PR #12345），意味着你可以在本地用 Ollama / llama.cpp 直接加载这些模型，像跑普通 LLM 一样简单。

为什么这事重要

  • 决策模型从「云上玩具」变成「本地工具」：之前你要用 Clef 或 Jev，要么调 Cloudflare API，要么自己搭 vLLM 集群。现在 ollama pull clef-flash 就能在 24GB VRAM 的显卡上跑起来。
  • 对非开发者的意义：你可以在本地跑一个会自主拆任务、调工具的 agent，而不需要写 prompt 链。比如：给它一个 Excel 文件，让它自己分析、生成报告、发邮件——全自动。
  • 隐私 + 成本双杀：数据不出本机，没有 API 费用。对于企业场景（合同分析、内部数据）是巨大的利好。
  • 生态效应：llama.cpp 是本地 LLM 的事实标准，这次合并意味着所有基于 llama.cpp 的工具（Ollama、LM Studio、GPT4All）都会自动支持决策模型。

🎯 今天就能做的事

  1. 更新 llama.cpp 到最新版（git pull && make）或更新 Ollama 到 0.6.0+。
  2. 拉取决策模型：ollama pull clef-flash（9B，~24GB VRAM 可跑 4bit）或 ollama pull autotrust/jev-27b。
  3. 用一个真实任务测试：比如「从这 5 份简历中选出最适合这个岗位的人，给出理由」。看它是否自主拆解步骤。
  4. 如果感兴趣，读 HuggingFace 博客文章了解架构细节。

技术细节：llama.cpp 的这次更新主要增加了对「决策头」的支持——模型输出不再是纯文本，而是结构化的决策步骤（JSON 格式），llama.cpp 可以解析并执行工具调用。同时优化了 KV cache 管理以支持 1M+ 上下文。

上手难度：如果你已经装了 Ollama，5 分钟就能跑起来。如果从源码编译 llama.cpp，需要 C++ 工具链，约 15 分钟。不需要 GPU 也能跑（CPU 推理，但慢）。

诚实 caveat：目前支持的决策模型还不多（Clef、Jev、少量社区微调版）。9B 的 Flash 版在复杂任务上不如 27B 版。而且本地工具调用需要你预先配置 MCP 服务器（比如文件读写、网络请求），不是开箱即用。

ChatGPT 现在可以访问网站内容了

clawii，ChatGPT 突然能「上网」了——不是搜索，而是直接访问你指定的 URL。HN 上 281 点、261 条评论，讨论炸了。

📍 背景：ChatGPT 之前只能通过 Bing 搜索获取实时信息，或者通过插件/工具间接访问网站。现在 ChatGPT 原生支持输入 URL 并读取页面内容——你可以在对话中粘贴链接，它会自动抓取并理解。这看起来是 GPT-6 系列模型的「内置 web browsing」能力，但之前只对 API 用户开放，现在在 ChatGPT 界面中直接可用。

为什么这事重要

  • 从「知识截止」到「实时读取」：之前你问 ChatGPT 关于某个网页的问题，它只能基于训练数据回答。现在你可以直接给它链接，它实时读取并分析。这对工作流是质变——比如读合同、看竞品页面、分析新闻。
  • 对非开发者的意义：你不需要任何技术知识。在 ChatGPT 里粘贴一个 URL，说「总结这个页面」，它就能做到。比之前用插件/工具方便 10 倍。
  • 可能改变搜索习惯：如果 ChatGPT 能可靠地读取任何网页，你可能会直接问它「这个页面第 3 段说了什么？」而不是自己翻。

🎯 今天就能做的事

  1. 打开 ChatGPT（网页版或桌面版），粘贴一个 URL（比如一篇新闻文章），然后问「总结这个页面」。看它是否成功读取。
  2. 测试边界：给它一个需要登录的页面、一个 PDF 链接、一个动态加载的页面——看它如何处理。
  3. 如果工作中有需要频繁查阅的网站（比如公司内网文档），试试用 ChatGPT 直接读取并回答。

技术细节：根据 HN 讨论，ChatGPT 现在使用 GPT-6 系列模型的「内置 web browsing」能力，通过一个内部工具调用（类似 MCP）来获取 URL 内容。模型会先发出一个 fetch 请求，然后基于返回的 HTML/文本进行推理。这不同于之前的 Bing 搜索集成——现在是用户直接控制。

上手难度：零门槛。粘贴 URL 即可。

诚实 caveat：目前似乎只支持公开可访问的网页，需要登录的页面可能失败。另外，OpenAI 尚未正式宣布这个功能，可能是逐步灰度。如果今天你还没看到，可能过几天就有了。

FLUX 3 Image：Black Forest Labs 的图像生成模型更新

clawii，FLUX 系列又升级了。FLUX 3 Image 在 HN 上拿了 353 点，但更像是常规迭代——更快、更准、更便宜，不是能力跃迁。

📍 背景：FLUX 是 Black Forest Labs 的开源图像生成模型系列，之前 FLUX 2 已经在质量上接近 Midjourney。FLUX 3 Image 是第三代，主打 推理速度提升 40%、支持更高分辨率（2048×2048）、更好的文字渲染。模型权重已发布在 HuggingFace，MIT 授权。

为什么这事重要

  • 开源图像生成的又一次进步：FLUX 3 在质量上已经可以匹敌 Midjourney 7 和 DALL·E 4，但完全开源、可本地运行。
  • 对非开发者的意义：如果你用 Stable Diffusion 或 ComfyUI，FLUX 3 可以直接替换模型文件，获得更好的生成效果。
  • 文字渲染改进：之前 FLUX 2 在生成带文字的图片时经常出错，FLUX 3 显著改善了这一点——对做海报、PPT 封面有用。

🎯 今天就能做的事

  1. 去 HuggingFace 下载 FLUX 3 模型权重（black-forest-labs/FLUX.3-image）。
  2. 如果你在用 ComfyUI，更新节点并加载 FLUX 3 试试。
  3. 测试文字渲染：提示词包含「a sign that says 'Hello World'」看效果。

上手难度：如果你已经熟悉 ComfyUI 或 Stable Diffusion，下载模型文件并替换即可。新手可能需要 30 分钟配置。

诚实 caveat：这不是 Midjourney 级别的「能力跃迁」，而是渐进式改进。如果你对 FLUX 2 已经满意，可以跳过。但如果你需要更好的文字渲染或更高分辨率，值得升级。

🔭 关注点：FLUX 3 是否会推出「Action」版本（视频/3D 生成）？Black Forest Labs 之前发布了 FLUX 3 Action，但那是动作模型，不是图像。
