llama.cpp natively supports "decision models" — the watershed moment for this new category going local

Hey clawii — the "decision models" that've been flooding your feed all week (Clef, DeepSeek V4.1 Flash — models that plan tasks, call tools, and evaluate on their own) just stepped off the cloud. llama.cpp — the engine under Ollama — just announced native support. You can run one on your laptop tonight.

📍 Context: This week had a clear主线: decision models went from a buzzword to a real category. Cloudflare open-sourced Clef (27B/9B with RL fine-tuning platform), DeepSeek dropped V4.1 Flash (causal encoder-decoder architecture optimized for agent scenarios), and GLM-5.3 Flash got red-teamed for cyber capabilities. But all of these required cloud APIs or custom frameworks. Yesterday, ggml-org (the llama.cpp maintainers) published "New in llama.cpp: Decision Models" on the HuggingFace blog — the world's most popular local inference engine now natively supports this paradigm. That means "decision models" officially enter the personal developer / productivity-worker toolkit, no longer exclusive to big-company APIs.

Why this matters

  • Decision models go from "cloud-only" to "one command, local": Before, to use a Clef or DeepSeek decision model you needed API keys, SDKs, and quota management. Now Ollama's底层 supports it — ollama pull a decision model, give it a goal, and it plans, calls tools, and iterates on its own.
  • This is the key step in taking "delivery models" off the server: For someone like you who vibe-codes with Claude Code and codex, this means you can run a "self-directed worker" model locally — handling sensitive tasks (contracts, comp data, org structure) that you don't want to upload to any cloud. No data leaves your machine.
  • The closed ecosystem is chasing the same lane: The HF community simultaneously published "What Is OpenAI Decisions API? A Practical Guide" — OpenAI is pushing something called "Decisions API" too. Both ecosystems formalizing "decision" as a product category at the same time is not a coincidence.
  • This is not another chat model: The usage pattern is different from ChatGPT/Claude — you're not having a conversation. You give it a goal. It decomposes the task, runs evaluations, and outputs a decision. That's a workflow-level shift.

🎯 What you can do today

  1. Make sure your Ollama is up to date (ollama update), then ollama pull a model tagged "decision" (like Clef-Flash 9B or JEV-27B) and see if it's recognized.
  2. Read the official llama.cpp blog post "New in llama.cpp: Decision Models" — it lists which models are supported and how to invoke them.
  3. Try a real goal: "Read these 5 resumes and rank the best fit for a comp manager role, with reasoning." Watch whether it does Q&A or actually decomposes steps, calls tools, and produces a report.
  4. If your company has strict data policies, bookmark this — local decision models are a legitimate answer to "AI that never leaves the intranet."

What it runs on: llama.cpp is a C++ local inference engine — it's what powers Ollama. Models are packaged in GGUF format (a 27B model can be quantized down to 12–15GB). Supports Apple Silicon Metal, NVIDIA GPU, even pure CPU.

How hard to set up: 5 minutes, eyes closed. Install Ollama → pull a model → run. 16–32GB RAM/VRAM handles quantized 9B–27B models. No code required.

Honest caveat: Local decision models are "small" (9–27B). Their ceiling on complex decisions is lower than cloud big models (Clef's large model has higher accuracy; OpenAI's is stronger). GGUF quantization loses a tiny bit of precision. For "rank 5 resumes" it's plenty. For "redesign the entire company comp structure," use a cloud big model + human review. Don't overhype it, but don't underestimate "no-egress + free + self-directed" as a combo.
