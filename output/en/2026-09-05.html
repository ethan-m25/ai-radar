GPT-6 Astra Day 2 Follow-up — OpenRouter Live, Simon's Deep Review, ARC-AGI 99.9% Catch Gets Worse
clawii, yesterday's Astra launch got louder: OpenRouter already has the model (236 HN points), Simon Willison published his first full review using pelican SVGs across 5 reasoning levels, and the community dug deeper into that ARC-AGI 3 99.9% — the Provider Adapter caveat is worse than day-1 reporting suggested. The official blog is still throwing 500 errors.
📍 Context · GPT-6 Astra is OpenAI's flagship model announced yesterday, priced identically to Claude Fable 5.1 ($10/$50 per million tokens). Yesterday's coverage focused on the security score blowout and the ARC-AGI caveat. Three new signals emerged today: OpenRouter listing, Simon's pelican-based review comparing low-through-max reasoning, and a community deep-dive showing the ARC 99.9% may not be comparable to any other model's score at all. Simon's review already says "I found details I didn't cover yesterday."

Why this is worth following up

  • OpenRouter has Astra live right now: You can call the API immediately without waiting for the ChatGPT rollout. 236 HN points from devs already testing it.
  • Simon Willison's full review is out: He generated pelican SVGs at five reasoning levels (low, medium, high, xhigh, max). Key finding: quality jumps markedly from low to high, but max mode burns through tokens. Directly useful for deciding which reasoning tier to use.
  • The ARC-AGI 3 caveat is deeper than reported: HN commenters dug into OpenAI's technical report. The 99.9% was achieved with a custom "Provider Adapter harness" that preserves reasoning state across requests — essentially a multi-shot benchmark. On the standard ARC-AGI 3 harness, Astra scored 62.7% — which is below GPT-5.6 Sol's historical ~65%. The gap is real and matters.
  • OpenAI's blog is still serving 500 errors: The official announcement is only accessible via mirrors on day 2. Community speculation about a rough launch is growing.

Anthropic Formalizes Fermat's Last Theorem in Lean 4 — Scientific Capability Showcase, No Direct Impact on Vibe Coding
clawii, Anthropic open-sourced a Lean 4 formal proof of Fermat's Last Theorem today — 625 HN points, 390 comments. It's a demonstration of Fable 5.1's ability to reason through one of mathematics' most famous problems and produce machine-verifiable code. Impressive science, but not a tool you'll use this week.
📍 Context · Fermat's Last Theorem was conjectured in 1637 and proven by Andrew Wiles in 1994. Anthropic had Fable 5.1 generate the full proof in Lean 4 — a formal theorem prover that checks every logical step automatically. This is significant for formal mathematics and verification communities: the proof can be automatically validated as bug-free.

Why this matters (but no rush)

  • Milestone for formal mathematical proof: This isn't something Codex or Claude Code does — it requires understanding deep mathematical reasoning and writing verifiable Lean 4 code. A real validation of abstract reasoning capability.
  • Long-term implications for software verification: If an AI can formally verify a math proof, it could eventually verify software safety properties (no buffer overflows, no deadlocks). This is a facet of Fable 5.1's security capability.
  • No immediate action needed: Lean 4 isn't a vibe-coding tool. This is not a usable API or end-to-end product. Pure "good to know" tier — unless you're building safety-critical systems.
📖 Jargon decoder · Lean 4 = an interactive theorem prover, a functional-language-based system for writing and verifying formal mathematical proofs · Formal proof = a proof written in mathematical logic that can be automatically checked by a computer.
