Kimi K3 open-source release — 2.8T params, MXFP4 quantization, HuggingFace 382 points

Hey clawii — Moonshot delivered on its July 27 open-source promise today. Kimi K3 weights are live on HuggingFace. HN #1 with 382 points, 166 comments. This is the first Chinese open-weight model to break into the 3T-parameter club, and MXFP4 quantization means it can theoretically run on a single card. For a vibe coder, this means you can now run a near-frontier model locally.

📍 Context · Kimi K3 was announced by Moonshot AI on July 16 as a 2.8T-parameter open-weight model using MoE architecture (~41B active parameters), with a 1M-token context window and native multimodal input. It features Kimi Delta Attention (KDA) for 6.3x decoding speedup and Attention Residuals for ~25% training efficiency. On Frontend Code Arena it leads with a 76% pairwise win rate, surpassing Claude Fable 5 and GPT-5.6 Sol. Moonshot promised open-source by July 27 and delivered on time today.

Why this matters

  • First Chinese open-weight model in the 3T-parameter club — 2.8T parameters is a new ceiling for open models. The previous largest were Inkling (975B) and GLM-5.2 (753B). K3 triples that parameter count.
  • MXFP4 quantization means single-GPU inference — Official support for MXFP4 4-bit quantization means it can theoretically run on a single H100 (80GB). Speed won't be blazing, but it's viable. Big win for local inference and agent workflows.
  • Frontend Code Arena performance beats Fable 5 and GPT-5.6 Sol — 76% pairwise win rate means it's the best open model for frontend coding tasks. If you vibe-code frontends, K3 might be your best bet.
  • HN 382 points signals global community validation — This isn't just Chinese community hype. 382 points and 166 comments on HN means developers worldwide are paying attention.
🎯 What you can do today
  1. Download the weights from HuggingFace: huggingface.co/moonshotai — look for Kimi-K3-2.8T or similar naming.
  2. Read the HN discussion: HN #1 — 382 points, 166 comments, the real insights are in the comments.
  3. If you have an H100 or A100, try loading the MXFP4 quantized version with vLLM or SGLang and see if it runs.
  4. Use Claude Code or Codex to test K3 on frontend coding tasks and compare against Fable 5.

Honest caveat: K3's parameter count is 3x Inkling's, but active parameters are similar (~41B), meaning MoE has more experts but similar compute per token. MXFP4 quantization is a highlight, but actual inference speed may be slower than Inkling's FP8 version. The 76% Frontend Code Arena win rate is impressive but needs independent verification. If you don't have an H100, wait for community benchmarks before downloading the full weights.

Jargon decoder · MXFP4 = A 4-bit floating-point quantization format proposed by Microsoft, dramatically reducing VRAM requirements while preserving model quality. MoE = Mixture of Experts, an architecture that activates only a subset of parameters per inference. KDA = Kimi Delta Attention, Moonshot's custom attention mechanism delivering 6.3x decoding speedup. Attention Residuals = Residual connections in attention layers, improving training efficiency by ~25%.
